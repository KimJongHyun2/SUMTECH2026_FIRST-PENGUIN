# E2E 입력 자료

실제 흐름에서 쓰는 자료를 이 폴더에 포함한다. 주최 측 실행은 저장소만으로 재현되어야 한다. 파일 하나는 10MB 이하이며 빈 파일·가짜 결과를 넣지 않는다. 영상은 촬영 동의를 받고 불필요한 개인정보를 포함하지 않는다.

## 현재 평가 설계의 자료

원격 병합으로 `front-good.webm`·`front-turtle.webm`·`front-away.webm`과 S1·S7 spec이 추가됐다. 이 spec은 `e2e/helpers.ts`에서 getUserMedia를 교체해 WebM을 재생하며 평가 빌드·URL 설계와 다르다. 아래 MP4·구간 명세는 아직 없다. 처리 규칙은 [PRD 7절](../../docs/prd.md#7-평가-재현-설계), 준비 상태는 [진행 기록](../../progress.md)을 따른다. 공식 키트가 특정 영상 파일명이나 시험 우회를 허용했다는 뜻은 아니다.

| 파일 | 필요한 내용 |
|---|---|
| `test-pose.mp4` | 같은 사람·배치의 실제 영상이다. 안정 등록·기준 범위·이탈·복귀·자리 비움의 명세된 재생 구간을 제공한다. |
| `test-pose.manifest.json` | SHA-256·해상도·프레임률·구간 시작/끝·사람의 라벨·모델/판정 설정·실제 추론 검증 결과이다. 촬영·검증 전 가상 값으로 채우지 않는다. |

영상 시각을 앱의 연속 측정 시각에 매핑하고 시크·루프 이동을 유효 시간에 더하지 않는다. 영상 라벨과 추론 결과가 일치하는지 먼저 확인한다. E2E 오차는 처리 주기·평활화·추론 지연을 실측해 정한다. 현재 영상 한 프레임 이내 정확도를 보장하지 않는다.

## 촬영 도구

저장소 루트에서 실행한다.

```sh
python3 -m http.server 8123 --bind 127.0.0.1 -d e2e/tools
```

브라우저에서 http://localhost:8123/record.html 을 연다. 도구는 640×480 WebM을 저장한다. 기존 촬영 안내의 기준 자세 30초·이탈 20초·자리 비움 15초는 촬영 길이이며 제품의 시간 임계값이 아니다. WebM만 찍으면 위 MP4·구간 명세가 준비되는 것은 아니며 변환·구간 구성·추론 확인이 필요하다.

파일 업로드를 사용하는 spec은 `__dirname` 기준으로 fixtures 경로를 만든다. e2e는 독립 패키지이며 package.json에 type: module을 넣지 않는다. 제출 전 `node tools/check-planning.mjs --submission`으로 존재를 확인하고 실제 내용·실행은 별도 검증한다.
