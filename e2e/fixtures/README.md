# E2E 입력 자료

실제 흐름에서 쓰는 자료를 이 폴더에 포함한다. 주최 측 실행은 저장소만으로 재현되어야 한다. 파일 하나는 10MB 이하이며 빈 파일·가짜 결과를 넣지 않는다. 영상은 촬영 동의를 받고 불필요한 개인정보를 포함하지 않는다.

## 현재 평가 설계의 자료

`front-good.webm`·`front-turtle.webm`·`front-away.webm`은 S1·S7 spec이 `e2e/helpers.ts`에서 getUserMedia를 교체해 재생하는 원본 촬영 영상이다. 평가 빌드(`/?mode=eval`)는 아래 `test-pose.webm`을 쓴다. 처리 규칙은 [PRD 7절](../../docs/prd.md#7-평가-재현-설계), 준비 상태는 [진행 기록](../../progress.md)을 따른다. 공식 키트가 특정 영상 파일명이나 시험 우회를 허용했다는 뜻은 아니다.

| 파일 | 내용 |
|---|---|
| `test-pose.webm` | 같은 사람·배치의 실제 영상 3개를 이어 붙인 54.5초 VP8 영상이다. good 0–16초·turtle 16–36초·away 36–51초·brief_touch 51–54.5초(참고용 짧은 가림)이다. 손으로 얼굴을 만지는 장면은 good에서 뺐다. Playwright 기본 Chromium이 H.264를 재생하지 못할 수 있어 MP4 대신 WebM을 쓴다. |
| `test-pose.manifest.json` | SHA-256·크기·해상도·프레임률·구간 시작/끝·사람의 라벨·모델·실제 추론 결과와 구간별 verified이다. 앱은 해시와 필수 구간(good·turtle·away)의 verified를 확인한 뒤에만 영상을 쓴다. |

구간 명세는 손으로 쓰지 않고 `e2e/tools/verify-test-pose.mjs`로 만든다. `posture-web`에서 `EVAL_ENABLED=true npm run dev`를 띄운 뒤 `e2e`에서 `node tools/verify-test-pose.mjs`를 실행하면, 개발 서버의 확인 페이지가 앱과 같은 모델·판정 코드로 각 구간을 추론하고 기준을 넘은 구간만 verified로 남긴다. 영상을 바꾸면 이 명령을 다시 실행한다.

영상 시각을 앱의 연속 측정 시각에 매핑하고 시크·루프 이동을 유효 시간에 더하지 않는다. 영상 라벨과 추론 결과가 일치하는지 먼저 확인한다. E2E 오차는 처리 주기·평활화·추론 지연을 실측해 정한다. 현재 영상 한 프레임 이내 정확도를 보장하지 않는다.

## 평가용 입력과 시간

Docker 빌드는 `docker-compose.yml`의 `EVAL_ENABLED`(기본 true)를 빌드 인자로 받는다. 평가 빌드는 영상과 구간 명세를 `/eval/`에 넣고, 하나라도 없으면 실패한다. 배포 사이트는 이 값 없이 빌드하므로 `/eval/`이 없다.

평가 전용 빌드 설정 `EVAL_ENABLED=true`와 첫 URL `/?mode=eval`을 함께 요구한다. 화면 이동·새로고침 중 같은 context의 평가 상태를 유지하고 종료 시 폐기한다. 일반 빌드에서는 URL·로컬 저장만으로 켤 수 없고 테스트 UI·입력 핸들러를 제공하지 않는다.

평가 빌드·녹화 입력·측면 모의 입력·시간 가속의 주최 측 허용 여부는 각각 확인한다. 일반 사용자 권한 거부를 시험 입력으로 자동 우회하지 않는다. 아래 도구는 팀의 시험 계약이며 실제 구현·실행 상태는 진행 기록을 따른다.

| 도구 | 대체할 입력·시간과 검증 범위 |
|---|---|
| 평가 모드 ‘카메라 켜기’ | `e2e/fixtures/test-pose.webm`의 녹화 프레임을 공통 추론·등록·판정·집계·저장 경로로 공급한다. 실제 권한은 요청하지 않는다. 파일 누락·디코딩 실패·필수 구간 미검증은 ‘평가 입력을 불러올 수 없어요’로 차단한다. |
| ‘[테스트용] 정면 이탈·복귀 재생’ | S2의 이탈 10초 → 복귀 3초를 연속 재생한다. |
| ‘[테스트용] 자리 비움·재이탈 재생’ | S4의 이탈 6초 → 자리 비움 5초 → 새 이탈 10초 → 복귀 3초를 연속 재생한다. |
| ‘[테스트용] 리포트 3초 가속’ | S3 첫 자동 주기만 유효 3초로 바꾼다. 첫 생성 후 경계부터 1800초로 복원한다. 등록·경고·복귀·재경고는 바꾸지 않는다. |
| ‘[테스트용] 측면 데이터 주입’ | S5·S6의 연결 요청·정면 영상 시각에 맞춘 측면 특징·품질·시각·모의 종료 응답을 공급한다. PC 승인·양쪽 등록은 UI로 수행한다. |
| ‘[테스트용] 양쪽 이탈·복귀 재생’·‘[테스트용] 측면 연결 끊기’ | 양쪽 이탈·복귀 입력 또는 측면 입력 중단·끊김·종료 무응답을 공급한다. 기본 전환은 사용자 선택으로 수행한다. |

입력·연결·리포트 주기만 대체하고 기준·세션·PC 승인 성공·최종 리포트를 미리 만들지 않는다. 테스트 기록·적용 주기를 표시한다. S3의 V=3초·D=0초를 1800초 관찰로 환산하지 않는다. 종료·새 context에서 도구를 초기화한다. 일반 사용자 권한 거부를 녹화 입력으로 우회하지 않는다.

## 촬영 도구

저장소 루트에서 실행한다.

```sh
python3 -m http.server 8123 --bind 127.0.0.1 -d e2e/tools
```

브라우저에서 http://localhost:8123/record.html 을 연다. 도구는 640×480 WebM을 저장한다. 기존 촬영 안내의 기준 자세 30초·이탈 20초·자리 비움 15초는 촬영 길이이며 제품의 시간 임계값이 아니다. 새로 찍은 WebM으로 평가 영상을 바꾸려면 구간을 이어 붙인 뒤 위 확인 도구로 구간 명세를 다시 만들어야 한다.

파일 업로드를 사용하는 spec은 `__dirname` 기준으로 fixtures 경로를 만든다. e2e는 독립 패키지이며 package.json에 type: module을 넣지 않는다. 제출 전 `node tools/check-planning.mjs --submission`으로 존재를 확인하고 실제 내용·실행은 별도 검증한다.

## 입력 자료 검증

`test-pose.manifest.json`은 영상 파일명·SHA-256·바이트 수·해상도·프레임률·구간·사람 라벨과 실제 추론 확인 결과를 포함한다. 현재 어댑터는 필수 구간 `good`·`turtle`·`away`의 `verified` 값을 확인한다. 구간 경계와 메타데이터는 실제 영상과 대조하고 검증 결과를 임의로 채우지 않는다.

평가 개발 서버를 `EVAL_ENABLED=true npm run dev --prefix posture-web`로 띄운 뒤, e2e 디렉터리에서 `node tools/verify-test-pose.mjs <개발 서버 HTTPS 주소>`로 현재 검증 도구를 실행한다. 이 도구에 작성된 구간·메타데이터·판정 기준도 해당 입력의 실측값·라벨과 맞는지 확인해야 한다. 도구가 명세를 출력했다는 사실만으로 영상 E2E·감지 정확도 검증을 완료로 처리하지 않는다.

파일 존재 검사, 구간 라벨과 추론 결과의 일치, 실제 UI E2E는 별도로 확인한다. 3초 가속은 운영 1800초 경계 시험을, 측면 모의 응답은 실제 QR·휴대폰 연결·카메라 종료 시험을 대신하지 않는다. 흐름당 실행 시간은 로컬에서 측정하고 주최 측 실행은 따로 확인한다.
