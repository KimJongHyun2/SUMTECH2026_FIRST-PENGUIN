# PRD — 패스트거북이

2026-10-30 기획 정합성 정리본이다. 현재 사용자 지정 정책과 기존 기획을 정리했으며 앱 구현·실행 완료를 뜻하지 않는다. 기획 점수는 사용자 전달 기준 14.6점이고 목표는 20점대 이상이다. 문서 검사를 실제 재채점이나 목표 달성으로 해석하지 않는다.

## 2. 문제·대상·근거

**노트북으로 과제·공부하는 대학생은 몰입 중 자세 변화를 제때 알아차리기 어렵고, 고쳐 앉아도 다시 작업에 집중하면 같은 자세로 돌아오는 어려움을 겪는다.**

초기 대상은 자세를 관리하려 하지만 노트북 작업 중 확인을 놓치는 대학생이다. 직접 자기보고가 기록된 대상은 P1이며 전체 대학생으로 일반화하지 않는다. 관리 도구 사용·추가 서비스 사용 의향은 미확인이다.

| 근거 | 확인된 범위 | 확대 해석하지 않는 범위 |
|---|---|---|
| E1 | 학교 프로젝트 중 사용자가 친구의 굽은 자세를 보고 알려준 관찰이다. | 친구의 당시 발화·감정·조정·효과·정확한 날짜는 미확인이다. |
| E2 | 기존 문서에 보존된 2026-10-30 자기보고이다. 최근 일주일에 고개가 앞으로 나오는 일이 자주 있었고, 지적 후 고쳐도 다시 집중하면 돌아왔으며 오래 앉으면 목·어깨가 뻐근한 경우가 있었다. | 횟수·시간·작업 효율 손실·인과는 미측정이다. 이번 작업의 새 인터뷰나 관찰 결과가 아니다. |
| R1 | 디지털기기 사용과 불편의 집단 관련성을 참고한다. | P1의 손실이나 자동 경고 필요성을 직접 입증하지 않는다. |
| R2~R4 | 자세 피드백의 도움·작업 부담·불확실성을 참고한다. | 본 서비스의 효과나 자동 경고 단독 효과가 아니다. |
| R5 | 개인 기준·웹캠 알림의 유사 접근이다. | 기능 자체의 독창성·우월성·기존 서비스 결함을 입증하지 않는다. |
| R6~R9 | 환경 안내와 정면 특징 계산의 참고이다. | 임상 정상선·제품 정확도·개인 기준의 의학적 타당성 검증이 아니다. |

E1과 E2를 동일 사건이나 독립된 두 사용자 표본으로 합치지 않는다. 외부 출처의 URL·주장·기존 확인 범위는 problem.yaml에 보존한다. 이번 작업에서 논문 원문을 새로 검증하지 않았다. 감정·손실 수치·사용 의향·원인이 없는 부분은 미확인으로 남긴다.

잠정 근본 문제는 작업 수행 중 자세 변화를 확인하고 조정을 지속하기 어렵다는 점이다. 주의 부담·환경·글씨 크기·유지 불편 중 주원인은 미확인이다. 따라서 알림이 충분한 해결책이라는 결론도 검증 대상이다.

## 3. 해법·대안·범위

기본 경로는 자세·환경 안내 → 개인 기준 등록 → 지속 기준 이탈 경고 → 정상 복귀·중단 기록 → 자동/종료 리포트 → 사용자 확인·조정이다. 자세 관리 습관과 예방을 돕는 목적이며 진단·치료·장기 예방 효과를 보장하지 않는다.

| 대안 | 현재 근거·한계 | 이번 경로로 검증할 가치 |
|---|---|---|
| 생각날 때 또는 주변 지적으로 고쳐 앉기 | E2에서 사용했으나 다시 집중하면 돌아왔다. 원인은 미확인이다. | 주변 사람이 없어도 지속 변화 시 확인 계기를 제공하는지 확인한다. |
| 시간 기반 알림 | 팀원의 사용 여부는 미확인이다. 변화와 알림 시점이 어긋날 수 있다는 가설이다. | 같은 작업에서 불필요한 경고·조정·작업 방해를 비교한다. |
| 받침대·외부 입력장치 | 사용 경험과 환경 개선 후 남는 어려움은 미확인이다. | 환경 개선으로 충분한 경우를 구분하고 남는 확인 부담만 보완한다. |
| 유사 웹캠 알림 서비스 | R5가 존재하나 직접 비교 결과는 없다. | 학습 중 오경고·작업 방해·기록과 리포트의 유용성을 비교한다. |

현재 핵심 범위는 기준 등록·경고·세션 제어·로컬 기록·자동/종료 리포트이다. 선택형 딥 모드도 기존 chosen 경로로 유지한다. 휴대폰 승인 연결 → 측면 배치·기준 등록 → 정면·측면 통합 → 결과 확인을 제공하는 설계이며 정확도 향상·동기화·공식 재현은 검증 전이다. 범위를 임의로 보류나 완료로 바꾸지 않는다.

로그인·계정·클라우드 동기화·랭킹은 후속 범위이다. 고정 시간 알림은 비교 실험 조건이며 현재 제품 기능에 추가하지 않는다. 더미 순위·가짜 감지·가짜 리포트는 만들지 않는다.

## 4. 공통 정책과 용어

| 항목 | 현재 기본값 | 시작·완료 기준 |
|---|---|---|
| 기준 등록 | 5초 | 필수 입력이 연속 안정 5초일 때 등록한다. 중단 시 0부터 다시 센다. |
| 최초 경고 | 10초 | 개인 기준 이탈이 연속 유효 10초일 때 확정 이탈과 최초 경고를 기록한다. |
| 정상 복귀 | 3초 | 기준 범위의 연속 유효 입력 3초일 때 확정 이탈을 닫고 경고를 해제한다. |
| 재경고 | 60초 간격 | 같은 확정 이탈의 최초 경고 뒤 연속 유효 60초마다 추가한다. 이탈 ID는 유지한다. |
| 자동 리포트 | 유효 30분(1800초) | 누적 유효 시간 기준이다. 생성 후 세션은 계속한다. |
| 종료 리포트 | 남은 유효 구간 | 마지막 자동 경계 이후 잔여 구간이 있을 때만 생성한다. |

위 값은 이번 사용자 요청으로 현재 기획의 기준값을 정한 것이다. 의학적 정상선·검증된 최적값·실제 성능값이라는 의미는 아니다.

기존 설정 기능은 유지한다. 경고 시간 정수 1~300초·재경고 간격 정수 10~600초는 기존 입력 검증 설계안이다. 사용자가 유효한 값을 입력해 **적용**한 경우에만 이후 구간에 새 설정 버전으로 사용하고 기본값과 구분해 표시한다. 소수·0·범위 밖 값은 저장하지 않는다. 기준 등록 5초·복귀 3초·자동 리포트 유효 30분은 이 화면에서 변경하지 않는다. S8의 0초는 오류 입력이며 대체 정책값이 아니다. 제출 흐름은 모두 기본 경고 10초·재경고 60초에서 독립 시작한다.

QR 120초·1회용, 연결 신호 2초·6초 미수신 시 장애, 휴대폰 자체 중단 10초, 보관 상한 30일은 기존 보조 설계안으로 유지한다. 이번 요청에서 별도 승인·기기 검증된 값으로 기록하지 않는다. 민감도·판정 경계·측면 촬영 범위·동기화 허용 오차는 실측 대상이다.

용어의 정의는 planning-policy.yaml의 glossary를 따른다. **기준 자세**는 개인 비교 기준, **이탈 후보**는 연속 조건 미충족, **확정 이탈**은 지속 조건을 충족한 한 에피소드, **정상 복귀**는 유효 3초 확인, **자리 비움**은 촬영 범위 밖으로 인한 입력 부재, **판정 보류**는 정상·이탈·복귀를 결정하지 않는 처리이다. 사용자 일시 정지와 자리 비움을 혼용하지 않는다.

공통 경고는 **기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.** 이다. 유형이 검증된 경우에만 구체 안내를 쓴다. 어깨 기울기를 둥근어깨로 확정하거나 얼굴 크기만으로 목 전진을 진단하지 않는다. 유형이 불명확해도 신뢰 가능한 변화라면 공통 경고, 입력 자체가 무효라면 판정 보류이다.

## 5. 상태와 자리 비움 처리

세션(준비/진행/사용자 정지/복구 대기/종료), 인식(유효/자리 비움/인식 불가), 모드(기본/딥), 연결(대기/연결/끊김/해제), 저장(저장 중/완료/실패)을 별도 상태로 관리한다.

| 상황 | 판정·연속 시간 | 기록·복귀·재개 |
|---|---|---|
| 진행 중 유효 입력 | 이탈·복귀 조건과 유효 시간을 센다. | 같은 조건의 유효 구간을 누적한다. |
| 자리 비움 | '자리 비움 · 판정 보류'를 표시하고 경고·유효 시간 누적을 멈춘다. 이탈·복귀·재경고 연속 타이머를 초기화한다. | 후보는 폐기하고 확정 이탈은 자리 비움 사유로 닫는다. 확정 여부와 별개로 보류 구간·사유를 기록하며 정상 복귀 수는 늘리지 않는다. |
| 인식 불가·영상 갱신 중단 | 입력을 정상으로 간주하지 않으며 연속 타이머를 초기화한다. | 인식 중단 사유로 닫고 전후 이벤트를 이어 붙이지 않는다. |
| 같은 배치로 입력 복원 | 유효 기준·입력 확인 뒤 새 연속 구간을 시작한다. | 이전 누적 유효 시간·저장 기록은 유지한다. 새 이탈은 새 10초 조건을 충족해야 한다. |
| 사용자 일시 정지 | 촬영·추론·경고·유효 시간 누적을 중단하고 연속 타이머를 초기화한다. | 사용자 정지로 닫고 '재개' 뒤 장치·기준·배치를 확인한다. 입력만 돌아왔다고 재개하지 않는다. |
| 기준 재등록 | 준비 중 판정을 보류하고 연속 시간을 초기화한다. | 새 기준 ID를 저장하고 '탐지 재개'를 기다린다. |
| 유효 설정 적용 | 기존 이탈을 설정 변경으로 닫고 새 연속 구간을 시작한다. | 새 버전·적용 시각을 남긴다. 무효 입력 거부 시에는 기존 상태를 유지한다. |
| 딥 입력 무효·연결 장애 | 한쪽 입력만 무효여도 전체 판정·유효 시간 누적을 보류하고 연속 타이머를 초기화한다. | 장애 사유를 남긴다. 기본 전환은 정면 기준·입력이 유효할 때만 허용한다. |
| 세션 종료 | 판정·촬영을 중단한다. | 미복귀 이탈은 세션 종료 사유로 닫고 카메라 상태와 저장 결과를 따로 표시한다. |

자리 비움에서는 카메라가 촬영 중일 수 있으며, 사용자 일시 정지는 촬영 자체를 중단한다. 보류 중에는 정상 시간·정상 복귀·미발생 경고를 만들어 넣지 않는다. 경고 중 자리 비움이 발생하면 경고 표시를 중단하고 이탈을 중단으로 닫는다. 복귀 2초 뒤 입력이 끊겨도 정상 복귀 1회로 세지 않는다. 이탈 후보가 10초 전에 기준 범위로 돌아오면 후보를 폐기한다. 확정 이탈에서 3초 미만 복귀 후 다시 이탈하면 같은 이벤트를 유지하되 복귀 연속 시간을 다시 센다.

연속성 예시는 **이탈 6초 → 자리 비움 5초 → 이탈 4초 = 경고 0회**이다. 돌아온 뒤 연속 이탈이 새로 10초에 도달하면 최초 경고 1회가 발생한다. 세션 누적 유효 시간은 유지하되 자리 비움 5초는 제외한다. 재경고 시점은 새 이벤트가 물려받지 않는다.

## 6. 로그인 없는 저장과 딥 모드 데이터

기록·리포트·기준·설정은 **로그인 없이 같은 PC의 같은 사이트·브라우저 프로필**에 저장한다. IndexedDB는 기존 구현 설계안이다. 첫 화면은 '로그인 없이 이 PC 브라우저에 기록을 저장해요'를 안내하며, 계정 생성·로그인·클라우드 복원·다른 기기 기록을 선행 조건으로 요구하지 않는다.

공유 PC의 다른 이용자 접근 보호와 브라우저 간 동기화는 제공하지 않는다. 사이트 데이터 삭제·브라우저 정리로 기록이 일찍 사라질 수 있다. 저장 실패를 저장 완료로 표시하지 않는다. 진행 중 주기 저장을 설계하되 주기는 미정이며 새로고침 후에는 마지막 저장된 구간만 중단 세션으로 복원하고 카메라를 자동 시작하지 않는다.

보관 상한 30일은 정상 종료 시각 또는 비정상 중단 세션의 마지막 저장 유효 시각을 기준으로 한다. 접속·조회 시 만료 기록을 정리하며 브라우저가 닫힌 동안 정확한 만료 시각에 삭제된다고 보장하지 않는다. 개별 삭제는 종료 세션의 원장·리포트·파생 집계에 함께 반영한다. 다른 세션이 참조하는 기준과 현재 등록 기준은 보존한다. 전체 삭제는 기준·설정 포함 여부를 확인 화면에서 구분한다.

원본 영상은 각 기기에서 처리하고 원본 영상·연속 원시 좌표는 저장·전송하지 않는 구조가 목표이다. 딥 모드에서는 휴대폰의 최소 특징·품질·측정 시각을 승인된 보안 연결로 PC에 전달하므로 '어떤 데이터도 기기를 떠나지 않는다'고 쓰지 않는다. 개인 기록은 PC에만 남기고 휴대폰·중계 서버를 이력 저장소로 쓰지 않는다. 중계는 특징을 전달 후 폐기하고 영구 로그에 남기지 않는 설계이며 실제 네트워크·저장 검증이 필요하다.

## 7. 화면·버튼 계약

아래 경로와 문구는 목표 기획이다. 기존 앱과의 구현 차이는 [implementation-status.md](implementation-status.md)의 과거 대조 기록을 참고하며, 이 작업에서 UI를 수정하거나 동작을 확인하지 않았다.

| 화면 | 메뉴·버튼·표시 |
|---|---|
| 첫 화면 `/` | 패스트거북이, 서비스 목적·로컬 저장 안내, 자세 등록하고 시작, 딥 모드 사용하기, 내 기록, QR이다. QR 생성만으로 촬영하지 않는다. |
| 카메라 설정 `/setup` | 카메라 켜기, 권한·장치·배치 안내, 기준 자세 등록, 기준 자세가 등록됐어요, 탐지 시작이다. |
| 감지 `/watch` | 진행 상태·유효 시간·후보·경고·자리 비움/판정 보류, 일시 정지, 재개, 세션 종료, 설정, 기준 다시 등록, 탐지 재개, 리포트 보기이다. |
| 감지의 설정 화면 | 민감도·경고 시간·재경고 간격·소리·적용이다. 무효 입력은 오류를 표시하고 열어 둔다. 유효 적용은 저장 후 감지 화면으로 돌아온다. |
| 딥 연결 `/connect`·휴대폰 보조 화면 | 휴대폰 연결 요청, PC 연결 승인, 양쪽 카메라 켜기, 측면 배치·기준 안내, PC 기준 자세 등록, 딥 모드 탐지 시작이다. |
| 종료 화면 | 종료된 세션 요약, 기기별 촬영 종료 요청/확인, 저장 결과, 리포트 보기, 내 기록이다. |
| 리포트 `/report` | 구간·이탈·경고·정상 복귀·중단 요약, 잠정/개정 상태, 닫기, 내 기록이다. 진행 중 닫기는 같은 세션 감지 화면으로 돌아간다. |
| 내 기록 `/history`·세션 상세 | 세션 선택, 이전 기록과 비교, 기록 삭제, 삭제 확인, 빈 기록 안내이다. |

카메라 권한은 '카메라 켜기' 이후 요청하며 거부 시 등록·시작을 막고 재시도 방법을 안내한다. 권한을 사전 허용하지 않은 시험 환경에서는 그 버튼 직후 브라우저 권한창을 처리한다. 없는 주소는 404와 첫 화면 안내를 표시한다. 화면 이름이 바뀌면 YAML과 이후 E2E도 함께 맞춘다.

| S2 | 기준 등록 → 10초 최초 경고·3초 정상 복귀 → 종료 리포트 | F1·F2·F3·F6·F12 |

모든 흐름은 빈 저장소의 별도 브라우저 context에서 첫 화면부터 시작한다. 이는 테스트 환경의 격리 조건이며 실제 사용자에게 기존 기록 삭제를 요구하는 정책이 아니다. 이전 흐름의 기준·QR·세션 ID·기록·계정을 재사용하지 않는다. 로그인 없는 서비스이므로 account는 모두 생략한다. 화면 간 이동은 메뉴·버튼 순서로 수행하며 주소 직접 열기·API 호출로 생략하지 않는다.

브라우저 카메라 권한·실제 입력·촬영 배치는 실행 환경에서 준비해야 한다. 기준 등록 클릭 뒤 연속 안정 5초는 처리 완료 대기 조건이다. 자세 유지·자리 비움·QR 스캔·통신 중단은 실제 입력 동작이며 가짜 화면 조작으로 대체하지 않는다. 주최측 자동화에서 이 입력을 제공하는 방식은 아직 확인되지 않았다.

YAML 형식은 8개 흐름·각 1~12단계·기대 결과 1~500자를 따른다. 다만 **S3의 실제 30분 시험과 흐름당 로컬 1분 이내 요건은 아직 양립하지 않는다.** 시간을 몰래 줄이거나 종료 리포트를 자동 리포트 성공으로 표시하지 않는다. 이 제약과 딥 모드 다중 기기 재현은 validation-plan.md에서 미해결로 관리한다.

## 9. 집계·비교 규칙

유효 구간은 진행 중 실제 유효 입력이 있었던 반열린 구간의 합집합이다. 등록·자리 비움·인식 불가·사용자 정지·복구 대기 시간은 제외한다. 확정 이탈의 시간은 onset부터 정상 복귀 확인 또는 중단 시각까지이며 복귀 확인 3초도 포함한다. 지속 조건 미충족 후보는 확정 이탈 시간·횟수로 세지 않는다.

한 에피소드에 유형이 겹쳐도 전체 이탈 시간은 합집합이다. 이탈 ID는 재경고·유형 변경·자동 리포트 경계에서 새로 만들지 않는다. 다만 자리 비움 등으로 연속성이 끊기면 이전 이벤트를 닫고 새 조건으로 시작한다. 신규 횟수는 onset이 속한 구간, 실제 경고 수는 경고가 표시된 구간에 귀속한다.

자동 리포트는 누적 유효 1800초마다 생성한다. 늦게 확정된 후보는 같은 리포트 ID의 개정값으로 반영한다. 정확히 1800초에 종료하면 자동 리포트 1개만 있고 빈 종료 리포트는 없다. 유효 시간 0은 0% 대신 '분석 가능한 기록이 없습니다'로 표시한다.

모드·지표·기준·설정·배치 유효성이 같을 때만 정량 비교한다. 조건이 다르면 '조건이 달라 비교할 수 없어요', 자료가 부족하면 '비교할 기록이 부족해요'를 표시한다. 비교를 위해 필요한 재등록을 생략하도록 유도하지 않는다. 결과는 '측정된 기준 이탈 비율의 변화'이며 질환 개선 효과로 표현하지 않는다.

## 10. 검증·제출 상태

이번 작업의 검증 범위는 YAML 파싱·주최측 키/개수/길이 규격·기능/흐름 연결·정책 및 상태 규칙 대조·기존 가상 산술 재계산이다. 문서 검사 통과는 건강 효과·감지 성능·앱·E2E 통과·기획 점수 상승의 증거가 아니다.

후속 문제 검증에서는 실제 대안 사용·반복 빈도·불편·사용 의향을 확인한다. 감지 검증에서는 사람·세션을 나눠 독립 참조와 이벤트 정밀도·놓침·시간당 오경고를 비교한다. 가치 검증에서는 같은 작업에서 무알림/시간 기반/변화 기반의 순서를 바꿔 조정·무시·작업 방해·재사용 의향을 본다. 합격 목표 수치는 실험 전 팀이 정하며 이번 문서에서 성과를 지어내지 않는다.

기획 문서는 로컬 수정·검사, 기본 브랜치 반영, 대시보드 재채점을 구분해 보고한다. 대시보드는 등록 저장소의 기본 브랜치 파일을 읽으며 로컬 수정만으로 점수가 갱신되지는 않는다. 현재 사용자 전달 점수 14.6점과 과거 13.5점 기록을 구분한다. 앱·Docker·E2E·배포 작업은 이번 범위에 포함하지 않는다.
