# PRD — 패스트거북이

2026-10-30 파일 격리·기획 정합성 최종 정리본이다. 기획 평가는 **30점 만점에 현재 14.6점**, 목표는 **20점대 이상**이다. 현재값은 사용자 확인값이며 이 문서의 재채점·목표 달성은 미확인이다.

## 1. 핵심 기획 요약

| 항목 | 현재 계약 |
|---|---|
| 사용자·상황 | 자세를 관리하려 하지만 노트북 과제·공부 중 변화 확인을 놓치는 대학생이다. |
| 문제 | 고쳐 앉아도 다시 작업에 집중하면 같은 자세로 돌아오는 어려움이다. |
| 기본 경로 | 안내 → 개인 기준 등록 → 지속 기준 이탈 경고 → 정상 복귀/중단 기록 → 자동·종료 리포트 → 사용자 확인·조정이다. |
| 시간 | 안정된 유효 입력 등록 5초·최초 연속 유효 이탈 10초·연속 유효 복귀 3초·재경고 60초·누적 유효 감지 30분이다. |
| 입력 중단 | 자리 비움·인식 불가는 판정 보류·경고/유효 시간 중단·연속 타이머 초기화이다. 정상 복귀로 세지 않는다. |
| 저장 | 로그인 없이 같은 PC 사이트·브라우저 프로필에 로컬 저장한다. IndexedDB/localStorage는 구현 수단이다. |
| 선택 경로 | 휴대폰 QR 승인·측면 기준을 추가하는 딥 모드이다. 정확도 향상·다중 기기 재현은 미검증이다. |
| 후속 범위 | 로그인·클라우드 동기화·랭킹이다. 현재 기능에 더미 순위를 넣지 않는다. |

## 2. 문서 역할·현재 자료 범위

[planning-policy.yaml](planning-policy.yaml)이 서비스명·용어·시간·중단·저장의 단일 기준이다. [problem.yaml](problem.yaml)은 주최측 양식의 문제·근거·선택 해법·기능별 입력/결과/완료 조건이고, [scenarios.yaml](scenarios.yaml)은 독립 사용자 흐름과 기대 결과이다. [report-contract.md](report-contract.md)는 집계·경계·삭제 규칙, [validation-plan.md](validation-plan.md)는 형식 검사·실제 실행·미해결 조건을 구분한다.

현재 제출 문서는 docs/에서 관리한다. 과거 초안·검토·제안값은 [archive/planning-history/](../archive/planning-history/README.md), 초기 실험 화면·코드·분석은 [archive/posture-experiments/](../archive/posture-experiments/README.md)에 격리한다. 이 보관소의 옛 서비스명·시간값·지시·기능 번호를 현재 계약으로 적용하지 않는다. docs/references/에는 기존 검사에 필요한 가상 집계 JSON만 유지한다.

변경 시 공통 정책을 먼저 고치고 기능 완료 조건·시나리오·PRD·집계 계약을 함께 맞춘다. 현재 기능은 F1~F10·F12이며 F11은 랭킹 후속 번호이다. 현재 흐름은 S1~S8이다.

## 3. 문제·대상·근거

**노트북으로 과제·공부하는 대학생은 몰입 중 자세 변화를 제때 알아차리기 어렵고, 고쳐 앉아도 다시 작업에 집중하면 같은 자세로 돌아오는 어려움을 겪는다.**

직접 자기보고가 기록된 대상은 P1이다. 전체 대학생을 대표하는 표본은 아니며 관리 도구 사용·추가 서비스 사용 의향은 미확인이다. 잠정 근본 문제는 작업 중 변화 인지와 조정을 지속하기 어렵다는 점이다. 주의 부담·환경·글씨 크기·유지 불편 중 주원인은 미확인이다. 알림만으로 충분히 해결된다고 확정하지 않는다.

| 근거 | 확인된 범위 | 한계 |
|---|---|---|
| E1 | 학교 프로젝트 중 사용자가 친구의 굽은 자세를 보고 알려준 관찰이다. | 정확한 날짜·당시 발화·친구의 감정·조정·효과는 미확인이다. |
| E2 | 기존 문서에 보존된 2026-10-30 자기보고이다. 최근 일주일에 고개가 앞으로 나오는 일이 자주 있었고 지적 후 고쳐도 다시 집중하면 돌아왔다. 오래 앉으면 목·어깨가 뻐근한 경우가 있었다. | 횟수·지속 시간·효율 손실·인과는 미측정이다. 이번 작업의 새 인터뷰가 아니다. |
| R1 | 디지털기기 사용과 불편의 집단 관련성이다. | P1의 손실·자동 경고 필요성을 직접 입증하지 않는다. |
| R2~R4 | 자세 피드백의 도움·부담·불확실성을 참고한다. | 본 서비스나 자동 경고 단독 효과가 아니다. |
| R5 | 개인 기준·웹캠 알림의 유사 접근이다. | 독창성·우월성·기존 서비스 결함을 입증하지 않는다. |
| R6~R9 | 환경 안내와 영상 특징 계산의 참고이다. | 임상 정상선·제품 정확도·개인 기준의 정상 인증이 아니다. |

E1과 E2를 같은 사건이나 독립된 두 사용자 표본으로 합치지 않는다. 외부 자료의 URL·주장·기존 확인 범위는 problem.yaml에 보존한다. 이번 작업에서 원문을 새로 검증하거나 경험·감정·손실 수치·효과를 만들어 넣지 않았다.

## 4. 대안·선택 이유·범위

| 대안 | 근거·한계 | 선택 경로에서 확인할 가치 |
|---|---|---|
| 생각날 때나 주변 지적으로 고쳐 앉기 | E2에서 사용했으나 다시 집중하면 돌아왔다. 원인은 미확인이다. | 주변 사람이 없는 동안에도 지속 변화 시 확인 계기를 주는지 본다. |
| 시간 기반 알림 | 실제 사용 경험은 미확인이다. 변화와 알림 시점 불일치는 가설이다. | 같은 작업에서 불필요한 경고·조정·작업 방해를 비교한다. |
| 받침대·외부 입력장치 | 사용 경험·환경 개선 후 남는 어려움은 미확인이다. | 환경 개선으로 충분한 경우를 구분하고 남는 확인 부담만 보완한다. |
| 유사 웹캠 알림 | R5가 존재하지만 직접 비교 결과는 없다. | 학습 중 오경고·작업 방해·기록과 리포트의 유용성을 비교한다. |

기본 경로와 선택형 딥 모드는 기존 chosen 상태를 유지한다. 딥 모드는 휴대폰 승인 연결 → 측면 배치·기준 → 유효 정면·측면 통합 → 경고·복귀·종료 결과의 경로이다. 정확도 향상은 검증 대상이다. 고정 시간 알림은 비교 실험 조건이며 현재 제품 기능은 아니다. 로그인·클라우드 동기화·랭킹은 후속이다.

목적은 자세 관리 습관과 예방을 돕는 것이다. 개인 기준을 의학적 정상으로 인증하거나 진단·치료·장기 예방 효과를 보장하지 않는다. 실제 확인·조정에 주는 도움과 작업 방해를 함께 검증한다.

## 5. 시간·설정·용어 계약

| 항목 | 값 | 판정 기준 |
|---|---|---|
| 기준 등록 | 5초 | 필수 입력이 연속 안정 5초여야 등록한다. 중단 시 0부터 다시 센다. |
| 최초 경고 | 10초 | 개인 기준 이탈이 연속 유효 10초이면 확정 이탈·최초 경고를 남긴다. |
| 복귀 확인 | 3초 | 기준 범위의 연속 유효 복귀 3초에 경고를 해제하고 정상 복귀를 남긴다. |
| 재경고 | 60초 간격 | 같은 확정 이탈의 최초 경고 뒤 연속 유효 60초마다 추가한다. |
| 자동 리포트 | 유효 30분(1800초) | 유효 시간 누적 기준으로 생성하며 세션은 계속한다. |
| 종료 리포트 | 남은 유효 구간 | 마지막 자동 경계 이후 잔여 유효 구간이 있을 때만 만든다. |

다섯 기본값은 최신 사용자 지정 정책이며 의학적 기준·검증된 최적값은 아니다. 경고 시간·재경고 간격의 사용자 적용값은 기본값과 구분하고 새 설정 버전 이후에만 사용한다. 0·소수·음수는 '양의 정수를 입력해 주세요'로 거부하고 기존 값·버전·측정 구간을 유지한다. 유효 적용은 기존 이탈을 설정 변경으로 닫고 새 연속 구간을 시작한다. 기준 등록 5초·복귀 3초·자동 리포트 유효 30분은 이 설정으로 바꾸지 않는다. 모든 제출 흐름은 기본 경고 10초·재경고 60초에서 시작한다.

보관 기간·QR 만료 시간·연결 감시/장애 판정/휴대폰 자체 중단 시간·시간 입력 상한은 미확정이다. 이전 제안 숫자는 아카이브에 보존하며 확정 완료 조건에서 제외한다. 판정 경계·민감도·촬영 범위·동기화 오차도 실측 대상이다.

서비스명은 **패스트거북이**이다. **기준 자세**는 개인 비교 기준, **이탈 후보**는 지속 조건 미충족 상태, **확정 이탈**은 지속 조건을 충족한 한 에피소드, **정상 복귀**는 유효 3초 확인이다. **인식 불가**는 가림·품질 저하·영상 갱신 중단 등으로 필수 입력을 신뢰할 수 없는 상태이며 '인식 실패'는 그 원인 설명으로만 사용한다. 자리 비움·인식 불가의 처리는 **판정 보류**이다.

공통 경고는 **기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.** 이다. 검증된 유형에만 구체 안내를 쓴다. 신뢰 가능한 변화인데 유형이 불명확하면 공통 경고, 입력 자체가 무효이면 판정 보류이다.

## 6. 상태 전이·시간 연속성

세션(준비/진행/사용자 정지/복구 대기/종료), 인식(유효/자리 비움/인식 불가), 모드(기본/딥), 연결(대기/연결/끊김/해제), 저장(저장 중/완료/실패)을 분리한다.

| 조건 | 판정·시간 | 기록·다음 상태 |
|---|---|---|
| 유효 입력·진행 | 연속 판정과 세션 유효 시간을 센다. | 같은 조건의 유효 구간을 누적한다. |
| 자리 비움 | '자리 비움 · 판정 보류'를 표시하고 경고·유효 시간 누적을 멈춘다. | 후보 폐기·확정 이탈 중단, 이탈/복귀/재경고 타이머 초기화, 보류 구간·사유 기록이다. 정상 복귀 수는 늘리지 않는다. |
| 인식 불가·영상 갱신 중단 | 정상·이탈로 임의 판정하지 않고 같은 보류·초기화 원칙을 적용한다. | 인식 중단으로 닫고 전후 이벤트를 이어 붙이지 않는다. |
| 같은 배치로 입력 복원 | 기준·배치가 유효하면 새 연속 구간을 시작한다. | 누적 유효 시간·기존 기록은 유지한다. 새 이탈은 새 10초 조건을 요구한다. |
| 사용자 일시 정지 | 촬영·추론·경고·유효 시간 누적을 멈추고 연속 타이머를 초기화한다. | '재개' 뒤 장치·기준·배치를 확인한다. 입력만 돌아와도 자동 재개하지 않는다. |
| 기준 재등록 | 준비 중 판정을 보류하고 연속 시간을 초기화한다. | 새 기준 ID를 저장하고 '탐지 재개'를 기다린다. |
| 유효 설정 적용 | 기존 이탈을 닫고 새 설정 구간을 시작한다. | 적용 시각·불변 버전을 남긴다. 무효 입력 거부는 기존 상태를 유지한다. |
| 딥 입력 무효·연결 장애 | 한쪽 입력만 무효여도 전체 판정을 보류한다. | 장애 사유를 남기고 유효한 정면 기준·입력에서만 기본 전환을 허용한다. |
| 종료 | 촬영·판정을 중단한다. | 미복귀 이탈은 종료 사유로 닫고 카메라 상태와 저장 결과를 따로 표시한다. |

자리 비움에서는 촬영 중일 수 있고 사용자 일시 정지는 촬영 자체를 멈춘다. 이탈 **6초 → 자리 비움 5초 → 이탈 4초의 경고는 0회**이다. 돌아온 뒤 새 연속 이탈 10초에 최초 경고 1회가 발생한다. 보류 중 경고를 나중에 몰아서 만들지 않는다.

경고 중 자리 비움은 정상 복귀가 아니다. 복귀 2초 → 인식 불가 → 복귀 1초도 정상 복귀로 합산하지 않는다. 10초 미만 후보가 기준 범위로 돌아오면 폐기한다. 확정 이탈에서 3초 미만 복귀 뒤 다시 이탈하면 같은 이벤트를 유지하되 복귀 연속 시간은 다시 센다.

## 7. 로컬 저장·삭제·기기별 처리

기록·리포트·기준·설정은 로그인 없이 같은 PC 사이트·브라우저 프로필에 로컬 저장한다. IndexedDB 또는 localStorage는 구현 수단이며 같은 저장 범위·삭제·실패 계약을 따른다. 첫 화면은 '로그인 없이 이 PC 브라우저에 기록을 저장해요'를 안내한다. 계정 생성·클라우드 복원·다른 브라우저의 기록을 선행 조건으로 요구하지 않는다.

공유 PC 타인 접근 보호·기기/브라우저 간 동기화는 제공하지 않는다. 브라우저 정리·사이트 데이터 삭제에 따른 소실과 저장 실패를 안내한다. 저장 실패를 완료로 표시하지 않으며 새로고침 후 마지막 저장 구간만 중단 세션으로 복원하고 카메라를 자동 시작하지 않는다. 보관 기간·만료 정리 시점은 미확정이며 자동 만료·영구 보관을 약속하지 않는다.

종료 세션을 삭제하면 원장·리포트·파생 집계를 함께 제거한다. 현재 등록 기준·다른 세션의 참조 기준은 보존한다. 전체 삭제는 기준·설정 포함 여부를 확인 화면에서 구분한다.

원본 영상·연속 원시 좌표는 저장·전송하지 않는 구조가 목표이다. 딥 모드는 휴대폰에서 산출한 최소 특징·품질·시각을 승인된 보안 연결로 PC에 전달하므로 모든 데이터가 기기를 떠나지 않는다고 표현하지 않는다. 개인 기록은 PC에만 두며 휴대폰·중계 서버에 이력을 보관하지 않는다. 실제 네트워크·저장·카메라 종료 검증은 미완료이다.

## 8. 화면·버튼과 독립 흐름

아래 문구는 목표 기획이다. 현재 앱의 과거 이름·감지·저장 구현을 이번에 맞춰 구현했다는 의미는 아니다. 이번 코드 관련 변경은 실험 파일 격리와 그에 필요한 빌드 진입점·전용 개발 중계·실험 링크 정리에 한정한다.

| 화면 | 메뉴·버튼·결과 |
|---|---|
| 첫 화면 `/` | 패스트거북이·목적·로컬 저장 안내, 자세 등록하고 시작, 딥 모드 사용하기, 내 기록, QR이다. QR 생성만으로 촬영하지 않는다. |
| 카메라 설정 `/setup` | 카메라 켜기, 권한·배치 안내, 기준 자세 등록, 기준 자세가 등록됐어요, 탐지 시작이다. |
| 감지 `/watch` | 상태·유효 시간·경고·판정 보류, 일시 정지, 재개, 세션 종료, 설정, 기준 다시 등록, 탐지 재개, 리포트 보기이다. |
| 감지의 설정 화면 | 민감도·경고 시간·재경고 간격·소리·적용이다. 무효 입력은 오류를 표시하고 열어 두며 유효 적용은 감지 화면으로 돌아간다. |
| 딥 연결 `/connect`·휴대폰 | 연결 요청, PC 연결 승인, 양쪽 카메라 켜기, 측면 가이드, PC 기준 자세 등록, 딥 모드 탐지 시작이다. |
| 종료·리포트 `/report` | 종료/저장 상태, 기기별 종료 요청/확인, 리포트 보기, 구간·경고·복귀·중단 요약, 닫기, 내 기록이다. 진행 중 닫기는 같은 세션의 감지 화면으로 돌아간다. |
| 내 기록 `/history`·상세 | 세션 선택, 이전 기록과 비교, 기록 삭제, 삭제 확인, 빈 기록 안내이다. |

카메라 켜기 이후 브라우저 권한을 요청한다. 거부 시 등록·시작을 막고 재시도를 안내한다. 없는 주소는 404와 첫 화면 안내를 표시한다. 버튼 이름 변경 시 YAML·이후 E2E도 함께 맞춘다.

| 흐름 | 자체 준비 → 완료 결과 | 기능 |
|---|---|---|
| S1 | 기준 등록 → 새로고침 → 기준 1개·준비·촬영 꺼짐 | F1·F3·F4·F12 |
| S2 | 기준 등록 → 경고·복귀 → 종료 리포트 | F1·F2·F3·F6·F12 |
| S3 | 기준 등록 → 유효 30분 자동 리포트 1개 → 같은 세션 계속 | F1·F3·F6 |
| S4 | 자체 기준 → 자리 비움 전후 시간 분리 → 정지·재개·종료 | F1·F2·F3·F4·F6 |
| S5 | 자체 QR 승인·양쪽 기준 → 딥 경고·복귀·종료 리포트 | F1·F2·F3·F6·F8·F9·F10·F12 |
| S6 | 자체 QR 승인·양쪽 기준 → 장애 → 기본 전환·종료 | F3·F4·F6·F8·F9·F10 |
| S7 | 자체 세션·리포트 생성/조회 → 삭제 후 각각 0개 | F1·F3·F6·F7·F12 |
| S8 | 자체 기준 → 0초 거부·10초 적용 → 새 기준 등록·명시적 재개 | F1·F3·F5 |

각 흐름은 빈 기록의 별도 브라우저 context에서 첫 화면부터 시작한다. 앞 시나리오의 QR·기준·세션·리포트·storageState에 의존하지 않는다. 이는 시험 환경 격리이며 실제 사용자 기록 삭제 정책이 아니다. 로그인 없는 서비스이므로 account를 생략한다. 첫 화면 이후에는 버튼·메뉴로 이동하고 주소·API로 건너뛰지 않는다.

실제 카메라 입력·촬영 배치·권한은 실행 환경에서 준비한다. 사전 허용이 없으면 카메라 켜기 직후 브라우저 권한창을 처리한다. 등록 클릭 뒤 연속 안정 5초는 처리 완료 대기 조건이다. 물리 입력을 가짜 상태 생성·시간 조작으로 대신하지 않는다.

## 9. 리포트 집계·비교

유효 시간은 진행 중 실제 입력이 유효했던 구간의 합이다. 준비·등록·자리 비움·인식 불가·정지·복구 대기는 제외한다. 확정 이탈 시간은 onset부터 복귀 확인 또는 중단 시각까지이며 복귀 확인 3초를 포함한다. 미확정 후보는 이탈 시간·횟수에 넣지 않는다.

유형이 겹쳐도 전체 이탈 시간은 합집합이다. 유형 변경·재경고·자동 경계로 같은 이탈 ID를 늘리지 않는다. 중단 시에는 기존 이벤트를 닫고 새 조건으로 시작한다. 신규 이탈 횟수는 onset 구간, 경고 수는 실제 표시 구간에 귀속한다. 늦은 확정은 같은 리포트 ID를 개정한다.

정확한 유효 1800초에 종료하면 자동 리포트 1개만 유지하고 빈 종료 리포트를 만들지 않는다. 유효 시간 0은 0% 대신 '분석 가능한 기록이 없습니다'로 표시한다. 같은 모드·지표·기준·설정·배치 유효성에서만 비교하며 다르면 '조건이 달라 비교할 수 없어요', 자료 부족은 '비교할 기록이 부족해요'를 표시한다. 결과는 측정된 기준 이탈 비율의 변화이며 질환 개선 효과가 아니다.

## 10. 검증·남은 조건

주최측 양식은 시나리오 3~8개·단계 1~12개·제목 1~120자·expected 1~500자이다. 현재 8개 흐름의 키·길이·독립 준비·기능 연결을 검사한다. P0/P1은 공식 배점이 아닌 내부 위험 우선순위이며 출처는 validation-plan.md에 명시한다.

S3의 실제 유효 30분과 스타터의 흐름당 로컬 1분 이내 실행 요구는 아직 양립하지 않는다. S5·S6의 카메라·다중 기기·HTTPS·QR 자동 재현도 미확인이다. 문서 형식 검사 통과와 주최측 실제 실행 충족을 구분하며 종료 리포트로 자동 리포트 검증을 대신하지 않는다.

문제 검증에서는 실제 대안 사용·반복 빈도·손실·사용 의향을, 감지 검증에서는 사람·세션 분리와 독립 참조의 정밀도·놓침·오경고를, 가치 검증에서는 같은 작업의 무알림/시간 기반/변화 기반 조건에서 조정·작업 방해·재사용 의향을 확인한다. 목표 허용치는 실험 전에 팀이 정하고 결과를 만들지 않는다.

이번 검증은 파일 보존·경로·YAML 구조·정책 대조·기존 가상 산술에 한정한다. 앱·카메라·E2E·Docker·배포·건강 효과는 검증하지 않는다. 기본 브랜치 문서 반영과 대시보드의 실제 30점 기준 재채점을 구분해 보고한다.
