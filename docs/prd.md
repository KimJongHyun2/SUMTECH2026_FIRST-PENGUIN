# 패스트거북이 — MVP 구현 설계

패스트거북이는 노트북 공부·작업 중 지속적인 자세 변화를 알려 사용자가 알아차리고 스스로 조정하도록 돕는 서비스이다. 개인 기준과의 차이를 안내하며 진단·통증 치료·예방 효과를 보장하지 않는다.

## 1. 범위와 문서 역할

[problem.yaml](problem.yaml)이 문제·경험·근거·선택한 해법·기능 완료 조건을, [scenarios.yaml](scenarios.yaml)이 사용자 흐름을 담당한다. 이 문서는 세부 구현 규칙을 담당한다. 실제 실행 결과와 미완료 사항은 [진행 기록](../progress.md)에 둔다.

- 기본 경로는 개인 기준 등록 → 탐지 → 지속 이탈 경고 → 자기 조정 → 리포트·기록 확인이다.
- 선택형 딥 모드도 현재 채택 범위이다. 휴대폰 연결 승인 → 양쪽 기준 등록 → 통합 탐지 → 종료까지 구현·검증해야 한다.
- 로그인 없이 같은 PC 사이트·브라우저 프로필에 저장한다. 로그인·클라우드 동기화·랭킹은 보류 범위이다.
- 딥 모드·30분 자동 리포트·기록 비교는 유지한다. 추가 입력과 리포트의 필요성·반복 사용 가치는 검증할 가정이다.

## 2. 화면과 판정 입력

| 화면 | 주요 행동과 결과 |
|---|---|
| 첫 화면 `/` | 서비스 이름·목적·로컬 저장 안내, 자세 등록하고 시작·딥 모드 사용하기·내 기록을 제공한다. |
| 등록 `/setup` | 카메라 켜기 → 배치 안내 → 기준 자세 등록 → 탐지 시작이다. |
| 감지 `/watch` | 상태·유효 시간·경고·판정 보류를 표시하고 일시 정지·재개·종료·설정·재등록·리포트 보기를 제공한다. |
| 딥 연결 `/connect`·휴대폰 `/phone` | 연결 요청 → PC 연결 승인 → 측면 배치 → 양쪽 기준 등록 → 딥 모드 탐지 시작이다. |
| 리포트 `/report` | 유효 시간·확정 이탈 시간·비율·경고·복귀·중단·저장 결과를 표시한다. 진행 중 닫기는 같은 세션으로 돌아간다. |
| 기록 `/history` | 저장된 세션 선택·리포트 조회·조건부 비교·삭제 확인을 제공한다. |

첫 화면은 ‘로그인 없이 이 PC 브라우저에 기록을 저장해요’를 안내한다. 카메라 권한 거부·장치 없음은 ‘카메라를 쓸 수 없어요’와 재시도 안내를 표시하고 등록·시작을 막는다. 없는 주소는 404와 첫 화면 안내를 제공한다.

‘머리가 기준보다 앞으로 나왔어요’는 해당 유형을 판별할 수 있을 때 쓰는 상태 문구이다. 공통 경고는 ‘기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.’이다. 입력이 무효이면 자세를 추정하지 않고 판정 보류를 표시한다.

현재 기본 판정은 MediaPipe Pose·Face의 머리–어깨 관계·목 길이·고개 각도 특징을 개인 기준과 비교한다. [판정 코드](../posture-web/src/core/detector.js)의 경계값은 파일럿 값이며 보편 정상선이 아니다. 안정 등록도 올바른 자세를 의학적으로 인증하지 않는다.

R7의 턱선–어깨 관계, R8의 얼굴 면적·어깨 변위·개인 보정, R9의 코–목 거리 비율은 기술 참고이다. 정확한 출처·주장은 problem.yaml을 따른다. 현재 구현이 연구의 방법·성능을 재현했다는 뜻은 아니다. 얼굴 크기만으로 목 전진을, 어깨 기울기만으로 둥근어깨를 확정하지 않는다. C7을 측정하지 않은 대체 지표를 임상 CVA로 표시하지 않는다.

사람·촬영 세션을 나누고 독립 참조와 비교해 오경고·놓침·유효 시간·보류 사유를 확인한다. 민감도 경계·측면 촬영 범위·동기화 오차는 실측 후 확정한다.

## 3. 시간과 상태 전이

아래 값은 기존 제품 기본값이며 의학적 최적값이 아니다. 운영 코드는 [policy.js](../posture-web/src/core/policy.js)에 두고 표와 함께 맞춘다.

| 정책 키 | 기본값 | 완료 조건 |
|---|---:|---|
| `baselineStableSeconds` | 5초 | 필수 입력이 연속 안정·유효하면 기준을 저장한다. 중단·불안정이면 처음부터 모은다. |
| `deviationSeconds` | 10초 | 기준 이탈이 연속 유효 10초이면 확정 이탈·최초 경고를 만든다. |
| `recoverySeconds` | 3초 | 확정 이탈 후 기준 범위가 연속 유효 3초이면 경고를 해제하고 정상 복귀 1회를 남긴다. |
| `rewarningSeconds` | 60초 | 같은 확정 이탈의 최초 경고 뒤 연속 유효 60초마다 재경고한다. |
| `reportValidSeconds` | 1800초 | 누적 유효 30분마다 자동 리포트를 만들고 세션을 계속한다. |
| `qrExpirySeconds` | 120초 | 발급 후 경과 120초 미만만 QR 요청·승인할 수 있다. |

세션 상태·입력 유효성·연결·저장 결과는 구분한다. 입력 중단은 세션 기록 삭제나 정상 복귀가 아니다.

| 조건 | 처리 |
|---|---|
| 진행·유효 입력 | 연속 타이머와 세션 유효 시간을 누적한다. |
| 자리 비움·인식 불가·영상 갱신 중단 | 후보를 폐기하고 확정 이탈은 중단 사유로 닫는다. 경고·유효 시간 누적을 멈추고 이탈·복귀·재경고 타이머를 초기화한다. 보류 구간·사유를 별도로 남긴다. |
| 입력 복원 | 기준·배치가 유효하고 세션이 진행 중일 때 새 연속 구간을 시작한다. 사용자 정지·복구 대기는 입력만 돌아왔다고 재개하지 않는다. |
| 사용자 일시 정지 | 촬영·추론·경고·유효 시간 누적을 중단한다. 명시적 재개와 장치·기준·배치 확인 후 같은 세션을 이어간다. |
| 기준 재등록·유효 설정 변경 | 기존 이탈을 변경 사유로 닫고 새 기준·설정 구간을 남긴다. 재등록 뒤 ‘탐지 재개’를 요구한다. |
| 종료 | 촬영·판정을 중단하고 미복귀 이벤트를 종료 사유로 닫는다. 카메라 종료와 저장 완료·실패를 따로 표시한다. |

자리 비움은 촬영 중 판정 보류이고 일시 정지는 촬영 자체의 중단이다. 이탈 6초 → 자리 비움 5초 → 새 이탈 4초에서는 경고가 없다. 새 이탈이 연속 10초가 될 때만 경고한다. 복귀 2초 → 인식 불가 → 복귀 1초도 정상 복귀가 아니다. 누락된 경고를 재개 뒤 몰아서 표시하지 않는다.

## 4. 리포트와 저장

| 항목 | 정의 |
|---|---|
| V | 진행 중 필수 입력이 유효했던 구간의 합집합 시간이다. 준비·등록·자리 비움·인식 불가·정지·복구 대기·재등록 준비는 제외한다. |
| D | 확정 이탈 시작부터 복귀 확인 또는 중단까지를 유효 구간과 교집합한 합집합 시간이다. 확정 전 시작 구간과 복귀 확인 3초를 포함한다. 미확정 후보는 제외한다. |
| R | `D / V × 100(%)`이다. 각 리포트는 해당 구간 D/V, 전체 세션은 합산 D/합산 V로 계산한다. |
| 분석 없음 | V=0이면 비율은 null이고 ‘분석 가능한 기록이 없습니다’를 표시한다. 0%로 채우지 않는다. |

R은 지속 조건을 충족한 개인 기준 이탈 에피소드의 비율이다. 복귀 확인 시간도 포함하므로 실제 기준 밖에 있던 모든 시간과 같지 않다. 리포트에 이 의미를 설명한다. 이탈 10초 → 복귀 3초의 명목 D는 13초이고 V에는 UI 조작 중 유효 시간도 포함한다. 항상 0≤D≤V이며 비율을 단순 평균하거나 원장 값을 미리 반올림하지 않는다. 화면 표시 자릿수는 구현 시 확정한다.

### 구간 경계와 이벤트

- 유효 1800초마다 자동 리포트를 만든다. 종료 시 마지막 경계 뒤 남은 유효 구간만 종료 리포트로 만든다. 정확한 경계 종료에는 빈 종료 리포트를 추가하지 않는다.
- 유형 중첩·재경고·리포트 경계로 같은 이탈 ID를 늘리지 않는다. 신규 횟수는 시작 구간에, 경고는 실제 표시 구간에 귀속한다.
- 경계에 미확정 후보가 있으면 리포트를 잠정 표시한다. 나중에 확정되면 시작 시각부터 시간을 나눠 같은 리포트 ID의 개정값과 세션 비율을 갱신한다. 후보가 끝나면 잠정 표시를 해제한다.
- onset=1795초, confirmed=1805초이면 첫 구간 D에 5초를 소급 반영하고 경고는 다음 구간에 남긴다. 이미 확인한 리포트의 개정 여부와 갱신 시점을 표시한다. 세션·구간·개정 식별자로 중복 저장을 방지한다.
- V=0 종료는 빈 분석 안내로 처리한다. 현재 엔진의 empty 종류 기록은 자동·종료 리포트와 구분한다.

가상 산술 C01~C06은 [검사 입력](../tools/fixtures/report-calculation.json)과 [엔진 테스트](../posture-web/src/core/engine.test.js)에 연결한다. 사람의 측정 데이터나 E2E 실행 증거가 아니다.

### 저장·비교·삭제

| 항목 | 규칙 |
|---|---|
| 저장 범위 | 기록·리포트·기준·설정은 같은 PC 사이트·브라우저 프로필의 로컬 저장이다. 다른 브라우저 복원·계정 동기화·공유 PC 타인 접근 보호를 보장하지 않는다. |
| 기준·설정 | 기준 ID·특징·장치·촬영 조건·모델 버전과 설정 버전을 남긴다. 기존 기록을 새 기준으로 덮어쓰지 않는다. |
| 새로고침 | 마지막 저장 구간까지 중단 세션으로 복원하고 카메라·탐지를 자동 시작하지 않는다. |
| 저장 실패 | ‘저장 실패’를 표시한다. 촬영 종료를 저장 성공으로 표시하지 않는다. |
| 비교 | 모드·지표·기준·설정·배치가 같은 기록만 정량 비교한다. 조건 차이는 ‘조건이 달라 비교할 수 없어요’, 자료 부족은 ‘비교할 기록이 부족해요’를 표시한다. |
| 삭제 | 종료된 세션 원장·리포트·파생 집계를 함께 제거한다. 현재 기준과 다른 세션의 참조 기준을 보존한다. 전체 삭제 확인에서 기준·설정 포함 여부를 구분한다. |

보관 기간·자동 만료는 미정이다. 브라우저 데이터 정리로 소실될 수 있다. 원본 영상·연속 원시 좌표는 저장·전송하지 않는 구조를 목표로 한다. 딥 모드의 최소 특징·품질·시각은 승인된 보안 연결로 PC에 전달하므로 모든 데이터가 기기를 떠나지 않는다고 표현하지 않는다. 휴대폰·중계에 개인 기록 이력을 보관하지 않는다.

## 5. 설정과 기준 변경

민감도·경고 시간·재경고 간격·소리가 기획 범위이다(F5). 시간은 양의 정수만 받고 0·소수·음수는 ‘양의 정수를 입력해 주세요’로 거부한다. 실패하면 저장값·버전·측정 구간을 유지한다.

유효 값이 실제로 바뀔 때만 새 버전·적용 시각을 남기고 기존 이탈을 닫는다. 같은 값 재적용은 오류 해제·화면 닫기만 수행한다. 변경 전 기록에 새 값을 소급 적용하지 않는다. 등록 5초·복귀 3초·자동 리포트 30분은 설정 화면에서 바꾸지 않는다. 입력 상한·민감도 경계는 미정이다.

재등록은 판정 보류와 새 기준 ID 생성이다(F1). 연속 안정 5초가 끝나도 ‘탐지 재개’ 전에는 자동 시작하지 않는다. 현재 구현과의 차이는 진행 기록에 둔다.

## 6. 딥 모드 연결과 복구

F8~F10은 다음 계약을 따른다.

1. QR 생성만으로 촬영하지 않는다. 휴대폰 연결 요청 뒤 PC 승인으로 연결한다.
2. 요청 수신·승인 시점 모두 만료를 검사한다. 120초 도달·사용·재발급으로 무효인 요청은 거부하고 새 휴대폰으로 자동 교체하지 않는다. QR 만료만으로 승인된 기존 연결을 끊지는 않는다.
3. 정면·측면 필수 입력이 함께 연속 안정 5초여야 등록한다. 유효하고 동기화된 두 입력만 결합하며 한쪽 무효이면 전체 판정·V 누적을 즉시 보류한다.
4. 연결 끊김 확인 시 연결 권한을 무효화하고 복구 대기로 전환한다. 유효 정면 기준·입력과 사용자의 ‘기본 모드로 계속’ 선택 뒤 같은 세션에 새 기본 구간을 만든다. 정면 무효이면 전환을 비활성화한다.
5. 전환 뒤 새 이탈은 새 10초를 요구한다. 장애·전환을 정상 복귀로 세지 않는다. 모드별 D·V·R을 나누고 전체 합산 비율을 모드 간 개선 효과로 쓰지 않는다.
6. 휴대폰 종료 요청과 실제 종료 확인을 구분한다. 무응답이면 ‘종료 요청·확인 안 됨’으로 남긴다.

연결 감시·장애 판정·휴대폰 자체 중단 시간은 실기기로 확정한다. 코드의 heartbeat 2초·disconnect 6초·phoneStop 10초는 파일럿 값이고 확정 정책이 아니다. QR 120초는 확정 기본값이다.

## 7. 평가 재현 설계

공식 실행 요건은 [README](../README.md#루프톤-제출-요건)를 따른다. 아래는 팀의 기존 시험 설계이며 주최 측 허용이 확인된 절차가 아니다. 구현·영상·E2E 준비 상태는 진행 기록을 따른다.

### 평가용 입력과 시간

평가 전용 빌드 설정 `EVAL_ENABLED=true`와 첫 URL `/?mode=eval`을 함께 요구한다. 화면 이동·새로고침 중 같은 context의 평가 상태를 유지하고 종료 시 폐기한다. 일반 빌드에서는 URL·로컬 저장만으로 켤 수 없고 테스트 UI·입력 핸들러를 제공하지 않는다.

| 도구 | 대체할 입력·시간과 검증 범위 |
|---|---|
| 평가 모드 ‘카메라 켜기’ | `e2e/fixtures/test-pose.mp4`의 녹화 프레임을 공통 추론·등록·판정·집계·저장 경로로 공급한다. 실제 권한은 요청하지 않는다. 파일 누락·디코딩 실패·필수 구간 미검증은 ‘평가 입력을 불러올 수 없어요’로 차단한다. |
| ‘[테스트용] 정면 이탈·복귀 재생’ | S2의 이탈 10초 → 복귀 3초를 연속 재생한다. |
| ‘[테스트용] 자리 비움·재이탈 재생’ | S4의 이탈 6초 → 자리 비움 5초 → 새 이탈 10초 → 복귀 3초를 연속 재생한다. |
| ‘[테스트용] 리포트 3초 가속’ | S3 첫 자동 주기만 유효 3초로 바꾼다. 첫 생성 후 경계부터 1800초로 복원한다. 등록·경고·복귀·재경고는 바꾸지 않는다. |
| ‘[테스트용] 측면 데이터 주입’ | S5·S6의 연결 요청·정면 영상 시각에 맞춘 측면 특징·품질·시각·모의 종료 응답을 공급한다. PC 승인·양쪽 등록은 UI로 수행한다. |
| ‘[테스트용] 양쪽 이탈·복귀 재생’·‘[테스트용] 측면 연결 끊기’ | 양쪽 이탈·복귀 입력 또는 측면 입력 중단·끊김·종료 무응답을 공급한다. 기본 전환은 사용자 선택으로 수행한다. |

입력·연결·리포트 주기만 대체하고 기준·세션·PC 승인 성공·최종 리포트를 미리 만들지 않는다. 테스트 기록·적용 주기를 표시한다. S3의 V=3초·D=0초를 1800초 관찰로 환산하지 않는다. 종료·새 context에서 도구를 초기화한다. 일반 사용자 권한 거부를 녹화 입력으로 우회하지 않는다.

### 시간 경계와 독립 실행

정확한 임계값은 결정적 입력을 쓰는 엔진 단위 시험에서 검증한다. 등록 4/5초, 이탈 9/10초, 복귀 2/3초, 재경고 70/130초, 운영 리포트 1799/1800초, QR 120초가 대상이다.

영상 E2E는 샘플링·평활화·추론 지연을 포함한다. 현재 처리 주기는 400ms이고 최근 3개 샘플을 평균하므로 영상 한 프레임 이내 오차를 보장하지 않는다. 영상 라벨·추론 결과·앱 시각을 측정해 수용 오차를 정한 뒤 제출한다. S2·S4·S5의 명목 D=13초는 결정적 입력의 기준이며 영상 실측값을 강제로 맞추지 않는다. 임계값보다 이른 경고를 허용하거나 시크·루프 이동을 유효 시간에 더하지 않는다.

각 흐름은 저장 기록·기준·설정이 없는 context의 첫 화면에서 시작하고 필요한 데이터를 스스로 만든다. 앞 흐름의 storageState·세션·QR을 재사용하지 않는다. 로그인 없는 서비스이므로 account는 생략한다. 첫 화면 이후 버튼·메뉴로 이동하고 최종 결과를 화면에서 확인한다. 실제 사용자 기록을 지우라는 제품 정책이 아니다.

입력 자료는 [e2e/fixtures 안내](../e2e/fixtures/README.md)에, 흐름별 테스트는 `e2e/scenarios/<id>.spec.ts`에 둔다. 정면 녹화·측면 모의 입력·시간 가속의 허용 여부는 각각 확인한다. 자료 존재 검사와 실제 독립·순차 실행은 별도이다.

| 기능 | 흐름 | 핵심 완료 조건 |
|---|---|---|
| F1 개인 기준·재등록 | S1·S8 | 기준 저장·새로고침 유지, 새 기준과 명시적 재개이다. |

| F3 세션 제어·F4 입력 장애 | S1~S8 | 시작·정지·재개·종료와 판정 보류·카메라 상태이다. |

가치 검증에서는 같은 사용자·작업·모드·기준·설정·배치에서 무알림·고정 시간·변화 기반 알림의 R과 인지 지연을 비교한다. 감소폭은 %p로 기록하고 유효 시간·보류 비중·오경고·놓침·작업 중단을 함께 본다. 인지 보고가 없으면 알림·복귀 시각으로 대신하지 않는다. 표본 수·최소 관찰 시간·목표 감소폭·작업 방해 허용치는 실험 전에 정한다.

R2의 복합 개입과 R3의 게임 실험은 작업 부담을, R4는 임상 효과의 한계를 보여준다. 경고 증가·R 감소만으로 인지 향상·건강 개선을 확정하지 않는다.

실제 작업은 다른 탭·IDE·인강 화면에서 일어나므로 감지 화면의 경고 표시만으로 전달 성공을 판정하지 않는다. 작업 중 경고 전달·인지를 확인해야 하며 전달 방식과 허용 지연은 미확정이다. 이를 해결한 것으로 간주해 새 알림 기능을 추가하지 않는다.
