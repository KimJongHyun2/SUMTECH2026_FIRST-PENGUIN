# PRD — 패스트거북이

**패스트거북이는 공부·작업 중 놓치는 지속적인 자세 변화를 감지하고 경고와 리포트로 자기 조정을 돕는 거북목 예방 지원 서비스이다.**

## 1. 핵심 기획 요약

| 항목 | 기획 결정 |
|---|---|
| 초기 고객 | 캡스톤 디자인·코딩·과제·인강에 몰입하는 대학생이다. |
| 핵심 문제 | 작업 몰입 중 자세 인지 불능(Unawareness)으로 조정 시점을 놓친다. |
| 핵심 경로 | 개인 기준 등록 → 탐지 → 지속 이탈 경고 → 자기 조정 → 리포트 확인이다. |
| 선택 경로 | 승인된 휴대폰 측면 입력을 결합하는 딥 모드이다. |
| 성공 지표 | 자세 이탈 비율 R=D/V×100(%)와 인지까지 걸린 시간이다. 감지 품질·작업 방해를 함께 평가한다. |
| 기본 정책 | 등록 5초·최초 경고 10초·복귀 3초·재경고 60초·자동 리포트 누적 유효 30분이다. |
| 저장 | 로그인 없이 같은 PC 사이트·브라우저 프로필에 로컬 저장한다. |
| 평가 목표 | 사용자 전달 기획 점수 14.6/30에서 20점대 상위권을 목표로 한다. 점수는 대시보드 재평가로 확인한다. |

## 2. 문제·사용자 경험·근거

### 2.1 문제 정의

**노트북으로 과제·공부하는 대학생은 작업에 몰입하면 자세 변화를 제때 알아차리지 못해 스스로 조정할 시점을 놓치고, 고쳐 앉아도 같은 자세를 반복하는 어려움을 겪는다.**

팀은 작업 중 자세 확인이 끊기는 문제에 집중한다. ‘자세 인지 불능’은 작업 중 몸 상태를 알아차리지 못하는 사용자 경험을 설명하는 기획 용어이다. ‘즉각적 피드백’은 연속 유효 이탈 10초를 충족하면 경고를 제공한다는 뜻이다.

### 2.2 실제 사용자 인터뷰

다음은 팀이 제공한 세 경험의 원문이다. 경험 번호는 기록 단위이며 서로 다른 세 명의 표본 수를 뜻하지 않는다. 상대 날짜는 인터뷰 원문 표현을 유지한다.

#### E1

> 어제 새벽 2시에 캡스톤 회의실에서 코딩하는데, 옆에 있던 팀장이 모니터에 빨려 들어갈 것처럼 목을 빼고 있더라고요. '야, 너 목 빠지겠다' 하고 쳤는데, 본인은 전혀 몰랐다며 엄청 놀랐습니다. 어깨가 아픈데도 화면에 집중하느라 몰랐대요.

- 언제·어디서: 어제 새벽 2시, 캡스톤 회의실에서 코딩하던 중이다.
- 행동·대응: 옆에 있던 동료가 '야, 너 목 빠지겠다'라고 말하고 쳐서 알려줬다.
- 감정: 팀장은 본인이 전혀 몰랐다는 사실에 크게 놀랐다.

#### E2

> 며칠 전 기숙사에서 밤새 알고리즘 과제를 하고 일어났는데, 뒷목부터 허리까지 너무 뻐근해서 고개를 돌리기 힘들었습니다. 집중할 때는 전혀 아픈 줄 몰랐습니다. 내 자세가 망가지는 걸 그때그때 누가 쳐다보고 알려주면 좋겠다는 생각이 절실했습니다.

- 언제·어디서: 며칠 전, 기숙사에서 밤새 알고리즘 과제를 하고 일어난 때이다. 회상 기록 제공일은 2026-10-30이다.
- 행동·대응: 작업을 마치고 일어난 뒤 몸의 불편을 알아차렸다.
- 감정: 자세가 무너지는 순간 누군가 보고 알려주면 좋겠다는 생각이 절실했다.

#### E3

> 도서관에서 3시간 내내 인강을 보다가 화장실 가려고 일어났는데 눈앞이 핑 돌고 어깨에 담이 왔습니다. 내가 3시간 동안 한 번도 안 움직이고 거북이처럼 이러고 있었다는 걸 깨닫고 진짜 충격받았습니다.

- 언제·어디서: 도서관에서 3시간 내내 인강을 본 뒤 화장실에 가려고 일어난 때이다.
- 행동·대응: 화장실에 가려고 자리에서 일어나면서 몸 상태와 장시간 움직이지 않은 사실을 알아차렸다.
- 감정: 장시간 같은 자세로 있었다는 사실에 충격을 받았다.

### 2.3 근본 원인 분석 — five_whys

아래는 팀이 제시한 원인 분석이다. 과몰입과 주의 배분을 설명하는 문장은 팀의 문제 해석으로 사용하며 신경학적 측정 결과로 제시하지 않는다.

1. 왜 거북목 자세로 장시간 작업하는가? → 화면의 코드에 집중하다 보니 고개가 앞으로 빠져서.
2. 왜 자세가 빠진 것을 스스로 고치지 않는가? → 코딩에 과몰입(Hyper-focus)해 있어서 몸의 통증을 뇌가 무시하기 때문에.
3. 왜 통증이 오기 전에는 모르는가? → 시각적 피드백(모니터)에 주의력이 쏠려 신체 상태를 모니터링할 여력이 없어서.
4. 왜 기존의 시간 알람은 효과가 없는가? → 현재 자세가 나쁘다는 걸 알려주는 게 아니라 기계적으로 울리기 때문에 무시함.
5. 결론: 작업 몰입 시 발생하는 '자세 인지 불능(Unawareness) 상태'를 즉각적으로 깨워줄 맞춤형 외부 개입이 부재하기 때문.

## 3. 팀의 강점·대안·선택 범위

### 3.1 왜 우리 팀인가 — why_ours

> 우리는 매일 밤 캡스톤 디자인과 해커톤 프로젝트를 위해 노트북 앞에서 뼈를 깎는 IT융합학과 4학년 당사자들입니다. 거북목과 허리 통증은 남의 이야기가 아니라 현재 우리가 겪는 가장 큰 고통이며, 대학생들의 작업 환경을 누구보다 잘 이해하고 있어 가장 실용적인 해결책을 만들 수 있습니다.

### 3.2 대안과 선택 이유

| 대안 | 해결하는 부분과 남는 공백 | 패스트거북이의 선택 이유 |
|---|---|---|
| 주변 지적·작업 후 몸 상태 확인 | E1은 동료의 지적, E2·E3는 작업 중단 뒤에야 몸 상태를 알아차렸다. | 지속 이탈 시점에 맞춰 자세 확인 계기를 제공한다. |
| 고정 시간 알림 | 정해진 시간에 울리며 실제 자세 상태와 알림 시점이 분리된다. | 개인 기준에서 벗어난 상태의 지속을 기준으로 경고한다. |
| 받침대·외부 입력장치 | 화면과 입력 환경을 조정한다. 작업 중 자세 변화의 감지는 별도의 과제이다. | 환경 조정과 함께 사용하며 탐지·경고·기록을 보완한다. |
| 유사 웹캠 알림 R5 | 개인 기준과 웹캠 알림 기능이 존재한다. | 대학생의 학습 세션 안에서 탐지→경고→복귀 기록→리포트를 연결한다. |

기본 경로와 선택형 딥 모드를 채택한다. 기본 경로를 시연 우선순위로 두며 딥 모드는 QR 승인·양쪽 기준 등록·통합 탐지·리포트를 포함한다. 로그인·클라우드 동기화·랭킹 F11은 후속 범위이다. 고정 시간 알림은 비교 실험 조건으로 사용한다.

## 4. 성공 지표와 판단 계약

### 4.1 주 지표

| 항목 | 정의 |
|---|---|
| V: 유효 시간 | 세션 진행 중 필수 입력이 유효했던 시간의 합집합이다. 준비·등록·자리 비움·인식 불가·사용자 정지·복구 대기·재등록 준비는 제외한다. |
| D: 확정 이탈 시간 | 확정 이탈의 시작부터 복귀 확인 또는 중단까지를 유효 구간과 교집합한 합집합 시간이다. 확정 전의 시작 구간과 복귀 확인 3초를 포함한다. |
| R: 자세 이탈 비율 | `D / V × 100(%)`이다. 10초 미만 지속 조건을 충족하기 전의 이탈 후보는 D에서 제외하되 유효 입력 시간은 V에 포함한다. |
| V=0 | 비율은 null이며 ‘분석 가능한 기록이 없습니다’를 표시한다. 0%로 채우지 않는다. |
| 구간 합산 | 전체 세션은 `합산 D / 합산 V × 100`이다. 리포트별 비율을 단순 평균하지 않는다. |
| 비교 | 동일 사용자·작업 조건·모드·지표·기준·설정·배치에서 `ΔR = 알림 조건 R - 비교 조건 R`을 %p로 기록한다. 감소 방향은 ΔR<0이다. |
| 성공 판단 | 사전 합의한 실험 조건에서 R 감소와 인지 지연 감소, 감지 품질·작업 방해 허용 조건을 함께 확인한다. 목표 감소폭·표본 수·허용치는 실험 전 확정할 항목이다. |

R은 지속 조건을 충족한 개인 기준 이탈의 비율이다. 모든 부적절 자세의 시간·발병 위험·인지 속도·임상 개선을 직접 나타내지 않는다. 예를 들어 이탈 10초 뒤 복귀 확인 3초이면 D는 13초이다. UI 조작 중 기준 범위의 유효 입력 시간도 V에 포함하므로 전체 세션 V를 임의로 13초라고 고정하지 않는다.

### 4.2 보조 검증과 지표 왜곡 방지

별도 동의받은 관찰 실험에서 이탈 시작·알림 표시·사용자 인지 보고·복귀 확인 시각을 구분한다. 인지까지 걸린 시간은 인지 보고 시각에서 이탈 시작 시각을 뺀 값이다. 보고가 없으면 해당 관측값을 비워 두고 분석에서 구분한다.

같은 작업의 무알림·고정 시간 알림·변화 기반 알림 조건을 비교하고 순서·작업 난이도 차이를 기록한다. 감지 정밀도·놓침·시간당 오경고·유효 시간·보류 시간·알림으로 인한 작업 중단을 함께 확인한다. 유효 시간이 부족하거나 보류 비중이 달라 직접 비교할 수 없는 결과는 판단을 유보한다. 감지 경계·기준·설정을 바꿔 비율만 낮추지 않는다. 세부 실험 조건은 [검증 계획](validation-plan.md#8-인지와-이탈-비율의-검증-설계)을 따른다.

## 5. 시간·용어·화면 문구

| 항목 | 단일 기본값·완료 조건 |
|---|---|
| 기준 등록 | 연속 안정 유효 입력 5초이다. 중단 시 0초부터 다시 등록한다. |
| 최초 경고 | 연속 유효 이탈 10초이다. 9초에는 경고가 없다. |
| 복귀 확인 | 기준 범위의 연속 유효 입력 3초이다. 2초에는 해제하지 않는다. |
| 재경고 | 같은 확정 이탈의 최초 경고 뒤 연속 유효 60초마다이다. 이탈 시작 기준 10·70·130초에 최초·재경고가 발생한다. |
| 자동 리포트 | 누적 유효 30분(1800초)마다이다. 생성 후 같은 세션을 계속한다. |
| 종료 리포트 | 마지막 자동 경계 이후 남은 유효 구간만 생성한다. 정확한 경계 종료에는 빈 종료 리포트를 만들지 않는다. |

기본값은 사용자 지정 기획값이며 의학적 기준·검증된 최적값이 아니다. 경고 시간·재경고 간격의 유효 변경은 새 설정 버전 이후에만 적용하고 기존 이탈을 설정 변경으로 닫는다. 0·소수·음수는 ‘양의 정수를 입력해 주세요’로 거부하며 기존 값·버전·측정 구간을 유지한다. 기준 등록 5초·복귀 3초·자동 리포트 유효 30분은 이 설정 화면에서 바꾸지 않는다. S1~S8은 기본값으로 시작하며 S3만 아래 테스트 도구로 첫 자동 주기를 가속한다.

### 5.1 테스트 환경에서의 시간 가속(Mocking)

실제 서비스의 자동 리포트 주기는 누적 유효 30분(1800초)이다. **E2E 평가 환경에서는 `NODE_ENV=test`와 명시적 테스트 도구 활성화를 함께 요구하고, 리포트 스케줄러에 테스트용 시계·주기를 주입하여 S3의 첫 자동 주기를 유효 3초로 가속한다.** 화면의 ‘테스트 도구’를 펼쳐 ‘[테스트용] 리포트 3초 가속’을 누른 뒤 ‘탐지 시작’을 누르면 해당 세션에서 가속을 시작한다. 유효 3초 직전에는 리포트가 없고, 가속된 3초 후 리포트가 정상 팝업됨을 확인한다. 팝업의 ‘리포트 보기’로 상세를 열고 ‘닫기’로 같은 세션을 계속한다.

전역 시계는 바꾸지 않고 리포트 주기만 1800초에서 3초로 대체한다. 기준 등록 5초·경고 10초·복귀 3초·재경고 60초는 그대로이다. 보류·정지 시간은 가속 조건에서도 누적하지 않는다. 첫 구간의 실제 V=3초·D=0초·비율 0%를 저장하며 1800초를 관찰한 것으로 환산하지 않는다. 첫 자동 생성 직후 가속을 해제하고 마지막 경계부터 다음 주기를 1800초로 복원해 상세 조회 중 중복 팝업을 방지한다. 종료·새 context에서도 테스트 설정을 초기화한다. S1·S2·S4~S8의 자동 주기는 1800초이다.

테스트 표시와 적용 주기를 기록에 남기고 운영 기록·효과 검증과 분리한다. 테스트가 꺼진 운영 환경에서는 테스트 버튼·입력 핸들러를 제공하지 않으며 주소 파라미터나 로컬 저장 값만으로 켤 수 없다. 운영의 29:59/30:00 경계·유효 1800초 집계는 별도 단위/실기기 시험으로 유지한다. 이 절은 테스트 도구의 구현·수용 계약이다.

‘기준 자세’는 개인 비교 기준, ‘이탈 후보’는 지속 조건 미충족 상태, ‘확정 이탈’은 지속 조건을 충족한 한 에피소드이다. ‘정상 복귀’는 기준 범위로 유효 3초 복귀했다는 이벤트명이며 의학적 정상 판정이 아니다. ‘인식 불가’는 가림·품질 저하·영상 갱신 중단으로 입력을 신뢰할 수 없는 상태이고, 이때의 처리는 ‘판정 보류’이다.

**화면 상태 문구는 ‘거북목이에요’이다.** 이 문구는 개인 기준 대비 머리가 앞으로 나온 상태의 사용자용 안내이다. 공통 경고는 ‘기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.’이다. 유형이 불명확하면 공통 경고, 입력이 무효이면 판정 보류를 사용한다. 등록 성공·상태 문구를 진단으로 설명하지 않는다.

## 6. 상태 전이와 예외 계약

세션(준비/진행/사용자 정지/복구 대기/종료), 인식(유효/자리 비움/인식 불가), 모드(기본/딥), 연결(대기/연결/끊김/해제), 저장(저장 중/완료/실패)을 분리한다.

| 조건 | 판정·시간·이벤트 | 사용자에게 남는 결과 |
|---|---|---|
| 유효 입력·진행 | 연속 시간과 V를 누적한다. 확정 이탈만 D에 넣는다. | 상태·유효 시간·경고이다. |
| 자리 비움 | 후보 폐기·확정 이탈 중단, 이탈/복귀/재경고 타이머 초기화, V·D 누적 중단이다. | ‘자리 비움 · 판정 보류’와 보류 구간·사유이다. 정상 복귀는 증가하지 않는다. |
| 인식 불가·영상 갱신 중단 | 정상·이탈을 추정하지 않고 같은 보류·초기화를 적용한다. | 인식 중단 사유이며 과거 이벤트와 이어 붙이지 않는다. |
| 같은 배치로 입력 복원 | 기준·배치가 유효하고 사용자가 정지하지 않았으면 새 연속 구간을 시작한다. | 이전 V·기록은 유지하고 새 이탈은 새 10초를 요구한다. |
| 사용자 일시 정지 | 촬영·추론·경고·V 누적을 중단하고 연속 타이머를 초기화한다. | 명시적인 ‘재개’와 장치·기준·배치 확인을 요구한다. |
| 기준 재등록 | 판정 보류·기존 이탈 중단·새 기준 ID 저장이다. | 연속 안정 5초 완료 후에도 ‘탐지 재개’ 전 자동 시작하지 않는다. |
| 설정 적용 | 유효 변경만 새 버전과 구간을 만든다. | 무효 입력은 오류만 표시하고 기존 상태를 유지한다. |
| 딥 한쪽 입력 무효 | 전체 판정·V 누적을 즉시 보류하고 연속 타이머를 초기화한다. | 정면만으로 딥 판정을 계속하지 않는다. |
| 딥 연결 끊김 확인 | 연결 권한 무효화·복구 대기이다. | 유효 정면 기준·입력에서만 ‘기본 모드로 계속’을 허용한다. 무효이면 비활성화·복구 안내이다. |
| 기본 모드 전환 | 사용자 선택 후 같은 세션의 새 기본 구간을 시작한다. 새 이탈은 새 10초를 요구한다. | 딥·기본 구간과 전환 사유를 분리하며 장애·전환을 정상 복귀로 세지 않는다. |
| 종료·저장 실패 | 촬영·판정 중단, 미복귀 이벤트를 종료 사유로 닫는다. | 카메라 종료와 저장 완료/실패를 별도로 표시한다. |

**S4의 핵심은 6초 이탈 → 자리 비움 5초 → 복귀 후 이탈 4초에서도 경고 0회라는 점**이다. 돌아온 뒤 새 연속 10초에만 최초 경고 1회가 발생한다. 첫 후보 6초는 D에서 제외하고 V에는 포함한다. 자리 비움·정지 시간은 V에서 제외한다. 자리 비움은 촬영 중 판정 보류이며 사용자 일시 정지는 촬영 자체의 중단이다.

**S6의 핵심은 장애 중 판정을 보류하고 사용자의 선택과 유효 정면 입력을 확인한 뒤 기본 모드로 전환한다는 점**이다. 장애 판정 전이라도 측면 입력이 무효이면 딥 판정을 보류한다. 휴대폰 종료 요청과 실제 종료 확인은 구분하며 무응답을 종료 완료로 표시하지 않는다. 모드별 D·V·비율은 분리하고 혼합 세션의 전체 비율은 합산 D/V로만 기술한다. 다른 모드 사이의 개선 비교는 하지 않는다.

경고 후 복귀 2초 → 인식 불가 → 복귀 1초도 정상 복귀 1회가 아니다. 과거 재경고 시계를 물려받거나 보류 중 경고를 나중에 몰아서 만들지 않는다.

## 7. 로컬 저장·비교·삭제

기록·리포트·기준·설정은 **로그인 없이 같은 PC 사이트·브라우저 프로필**에 로컬 저장한다. IndexedDB/localStorage는 구현 수단이다. 첫 화면은 ‘로그인 없이 이 PC 브라우저에 기록을 저장해요’를 안내한다. 계정·클라우드 복원·다른 브라우저 동기화·공유 PC 타인 접근 보호를 제공한다고 쓰지 않는다.

새로고침 후 마지막 저장 구간을 중단 세션으로 복원하고 카메라는 자동 시작하지 않는다. 저장 실패를 완료로 표시하지 않는다. 브라우저 정리·사이트 데이터 삭제로 기록이 소실될 수 있다. 보관 기간과 자동 만료는 구현 전 확정하며 영구 보관을 약속하지 않는다.

정량 비교는 같은 모드·지표·기준·설정·배치 유효성에서만 제공한다. 조건 차이는 ‘조건이 달라 비교할 수 없어요’, 자료 부족은 ‘비교할 기록이 부족해요’를 표시한다. 세션 삭제는 종료 후 원장·리포트·파생 집계까지 제거하고 현재 기준과 다른 세션 참조 기준은 보존한다. 전체 삭제는 기준·설정 포함 여부를 확인 화면에서 구분한다.

원본 영상·연속 원시 좌표는 저장·전송하지 않는 구조가 목표이다. 딥 모드 최소 특징·품질·시각은 승인된 보안 연결로 PC에 전달하므로 모든 데이터가 기기를 떠나지 않는다고 표현하지 않는다. 개인 기록은 PC에만 두고 휴대폰·중계 서버에 이력을 보관하지 않는다. 실제 저장·네트워크·카메라 종료 검증은 별도이다.

## 8. 화면·기능·독립 시나리오

아래는 구현과 수용 시험의 기준이다.

| 카메라 설정 `/setup` | 카메라 켜기, 권한·배치 안내, 기준 자세 등록, 기준 자세가 등록됐어요, 탐지 시작이다. |

| 종료·리포트 `/report` | 종료·저장 상태, 기기별 종료 요청/확인, 리포트 보기, V·D·이탈 비율·경고·복귀·중단 요약, 닫기, 내 기록이다. 진행 중 닫기는 같은 감지 화면으로 돌아간다. |

카메라 켜기 이후 권한을 요청한다. 거부 시 등록·시작을 막고 재시도를 안내한다. 없는 주소는 404와 첫 화면 안내를 표시한다. 버튼 이름이 바뀌면 YAML·PRD·후속 E2E를 함께 맞춘다.

| 흐름 | 자체 준비 → 관찰 결과 | 기능·검증 논리 |
|---|---|---|
| S1 | 개인 기준 등록 → 새로고침 → 기준 1개·준비·촬영 꺼짐·분석 없음 | F1·F3·F4·F12이다. 로그인 없이 기준을 유지한다. |
| S2 | 기준 등록 → 이탈 10초·복귀 3초 → 종료 리포트 | F1·F2·F3·F6·F12이다. 이탈·최초 경고·복귀 각 1회, D=13초·R=13/V×100이다. |
| S3 | 자체 기준 → 테스트 도구·3초 가속 → 자동 리포트 팝업 → 같은 세션 계속 | F1·F3·F6이다. 테스트 첫 구간 V=3초·D=0초·R=0%이며 운영은 1800초이다. |
| S4 | 자체 기준 → 자리 비움 전후 연속성 분리 → 정지·재개·종료 | F1·F2·F3·F4·F6이다. 6초+4초 합산 금지, 새 10초 경고, 보류·정지 제외이다. |
| S5 | 테스트 측면 주입·PC 승인·양쪽 기준 → 딥 경고·복귀·종료 | F1·F2·F3·F6·F8·F9·F10·F12이다. 단일 PC에서 중복 이탈 없이 D=13초·모의 종료 응답을 확인한다. |
| S6 | 테스트 측면 주입·자체 딥 시작 → 연결 끊기·판정 보류 → 사용자 선택으로 기본 전환·종료 | F3·F4·F6·F8·F9·F10이다. 같은 세션·별도 모드 구간·복귀 0회·측면 종료 응답 없음 처리이다. |
| S7 | 자체 세션·리포트 조회 → 삭제 → 각각 0개 | F1·F3·F6·F7·F12이다. 원장·집계 연쇄 삭제와 현재 기준 보존이다. |
| S8 | 자체 기준 → 0초 거부·10초 적용 → 재등록·명시적 재개 | F1·F3·F5이다. 무효 설정 불변·새 기준 구간·비교 제한이다. |

각 흐름은 **기록·기준·설정이 없는 별도 브라우저 context의 첫 화면**에서 시작하고 필요한 데이터를 자체 생성한다. 앞 S번호의 세션·QR·기준·storageState를 재사용하지 않는다. 같은 DB에서 순서대로 실행되는 주최측 조건에서도 로컬 저장을 각 흐름 안에서 격리한다. 실제 사용자 기록을 지우는 제품 정책은 아니다. 로그인 없는 서비스이므로 `account`는 생략한다. 첫 화면 이후에는 버튼·메뉴로 이동하며 테스트도 아래 명시된 입력 주입 버튼만 사용한다. 주소·API로 최종 상태를 직접 만들지 않는다.

운영·실기기 시험은 단계에 적힌 카메라 권한·실제 영상·배치·자세 유지·QR·통신 중단을 준비한다. 사전 허용이 없으면 ‘카메라 켜기’ 직후 브라우저 권한창을 처리한다. E2E 테스트에서는 ‘카메라 켜기’ 이후 결정적 정면 입력을 공급한다. 기준 등록 클릭 뒤 안정 5초는 해당 작업의 완료 대기 조건이다. UI 조작 중에는 기준 범위 입력을 유지하고 조작 시간을 고정 유효 시간으로 가정하지 않는다. 시나리오 산술은 유효 입력 시각을 기준으로 하며 실제 입력 재현 허용 오차는 별도 검증 대상이다.

### 8.1 단일 PC의 다중 기기 시뮬레이션(Bypass)

실제 사용자는 휴대폰으로 QR을 스캔하지만, 테스트 환경의 S5·S6에서는 이 물리 동작을 생략한다. 운영에서 숨기는 ‘테스트 도구’를 테스트 환경에서는 연결 화면에서 펼칠 수 있고, 펼친 버튼은 클릭·접근성 탐색이 가능해야 한다. 연결 뒤에도 감지 화면에서 같은 도구를 제공한다. `NODE_ENV=test`와 명시적 테스트 도구 활성화가 모두 필요하며 새 context마다 시뮬레이션을 초기화한다. S4는 자리 비움 흐름으로 유지하고 실제 딥 모드 흐름인 S5·S6에 적용한다.

| 테스트 버튼 | 주입하는 입력·검증 경로 |
|---|---|
| [테스트용] 측면 데이터 주입 | 해당 흐름 전용 테스트 휴대폰 1대의 연결 요청과 정면 입력에 동기화된 측면 특징·품질·시각을 공급한다. PC ‘연결 승인’을 누른 뒤에만 연결됨으로 처리한다. 기준이나 세션을 미리 만들지 않는다. |
| [테스트용] 양쪽 이탈·복귀 재생 | 정면·측면 이탈 입력을 연속 유효 10초 공급하고 정확한 입력 시각의 경계에서 기준 범위 입력 3초로 이어 재생한 뒤 기준 범위를 유지한다. 최초 경고·복귀를 공통 엔진이 생성한다. 두 입력 사이에 추가 클릭을 요구하지 않아 조작 지연이 D=13초를 늘리지 않게 한다. 경고·집계를 직접 기록하지 않는다. |
| [테스트용] 측면 연결 끊기 | 측면 입력 갱신 중단·연결 끊김·종료 무응답을 주입한다. 정면 기준 범위 입력은 유지하며 즉시 판정 보류·타이머 초기화, 연결 끊김 확인 후 복구 대기로 진입한다. |

S5는 주입→PC 승인→카메라 켜기→양쪽 기준 등록→딥 시작→이탈·복귀 연속 재생→종료→리포트를 순서대로 클릭하고 각 처리 완료를 기다린다. 정상 연결 상태에서는 종료 요청에 모의 측면 종료 응답을 돌려준다. S6은 독립적으로 같은 준비를 한 뒤 딥 유효 입력 1초 이상을 확인하고 연결 끊기를 누른다. 사용자 선택 전에는 기본으로 자동 전환하지 않고, 유효 정면 기준·입력에서 ‘기본 모드로 계속’을 누른 뒤 기본 유효 입력 1초 이상을 확인하고 종료한다. 무응답 측면은 ‘종료 요청·확인 안 됨’으로 남긴다.

버튼은 연결·센서·장애 입력만 대체하고 승인·안정 등록 5초·경고·복귀·모드 전환·저장·집계는 공통 경로를 실행한다. 최종 리포트·성공 응답을 직접 주입하지 않는다. 테스트 표시를 남기며 실제 QR 카메라·휴대폰 통신·측면 추론 정확도·실제 카메라 종료를 검증한 것으로 세지 않는다. 테스트 UI·입력 어댑터는 이 계약에 따라 구현한다.

### 8.2 기능별 상세 구현 계약

핵심 경로는 **개인 기준 등록·탐지(F1~F5) → 경고·복귀(F2) → 리포트·기록(F6·F7·F12)**이며 F8~F10은 선택형 딥 모드이다. 아래 완료 조건은 4~9절의 지표·상태·저장·테스트 정책을 함께 적용한다.

#### F1. 개인 기준 등록·재등록

- 입력: 카메라 권한, 자세·배치 안내 확인, 안정된 유효 입력, 기준 자세 등록 버튼이다.
- 출력: 기준 ID·특징·장치·촬영 조건·모델 버전과 등록 상태이다.

필수 입력이 연속 안정 5초이면 '기준 자세가 등록됐어요'를 표시하고 탐지 시작을 허용한다.
자리 비움·인식 불가·불안정 입력이면 등록 타이머를 0으로 초기화하고 새 연속 5초를 요구한다.
재등록 진입 시 판정을 보류하고 기존 이탈을 기준 변경으로 닫는다. 새 기준 ID를 저장하며 '탐지 재개' 전에는 자동 재개하지 않는다.
개인 기준을 의학적 정상 인증으로 표시하지 않는다.

#### F2. 지속 기준 이탈 경고·정상 복귀

- 입력: 등록 기준, 유효 영상 특징, 적용 설정 버전이다.
- 출력: 이탈 후보·확정 이탈, 실제 최초 경고·재경고, 정상 복귀·중단 기록이다.

기본 연속 유효 이탈 10초에 '기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.'를 표시한다.
기준 범위의 연속 유효 복귀 3초에 경고를 해제하고 정상 복귀 1회를 남긴다. 10초 전에 기준 범위로 돌아온 후보는 확정 이탈·경고로 집계하지 않는다.
같은 확정 이탈은 최초 경고 뒤 연속 유효 60초마다 재경고하며 유형 중첩·재경고로 이탈 ID를 늘리지 않는다.
자리 비움·인식 불가·정지·기준/설정/모드 변경은 중단으로 닫고 이탈·복귀·재경고 연속 타이머를 초기화한다. 전후 시간을 합치지 않는다.
경고 10초·재경고 60초는 기본값이며 유효 사용자 적용값은 별도 설정 버전으로 구분한다.
사용자 지정 화면 상태 문구 '거북목이에요'는 유지한다. 공통 경고·서비스 안내는 개인 기준 이탈 감지와 예방 지원 목적을 설명하며 진단을 뜻하지 않는다.

#### F3. 세션 시작·일시 정지·재개·종료

- 입력: 탐지 시작, 일시 정지, 재개, 세션 종료 버튼이다.
- 출력: 세션·카메라·저장 상태, 누적 유효 감지 시간이다.

등록 완료와 유효 입력을 확인한 뒤 탐지 시작에서 세션을 시작한다.
일시 정지는 촬영·추론·경고·유효 시간 누적을 멈추고 연속 타이머를 초기화한다. 재개는 장치·기준·배치 확인 후 같은 세션의 새 연속 구간을 시작한다.
세션 누적 유효 시간과 이전 기록은 유지한다. 종료 시 카메라 종료 상태와 '저장 완료'/'저장 실패'를 별도로 표시한다.
새로고침 후에는 마지막 저장 구간만 중단 세션으로 복원하고 카메라·탐지를 자동 시작하지 않는다.

#### F4. 권한·자리 비움·인식 불가 처리

- 입력: 카메라 권한, 연결·영상 갱신, 필수 지점 품질이다.
- 출력: 권한 안내, 유효/자리 비움/인식 불가 상태, 판정 보류 구간·사유이다.

권한 거부 시 '카메라를 쓸 수 없어요'와 재시도 안내를 표시하고 등록·시작을 막는다.
자리 비움은 '자리 비움 · 판정 보류'로 표시하고 경고·유효 시간 누적을 멈춘다. 후보는 폐기하고 확정 이탈은 자리 비움 사유로 닫으며 정상 복귀 수를 늘리지 않는다.
인식 불가·영상 갱신 중단도 같은 중단 원칙으로 처리한다. 이탈·복귀·재경고 타이머를 모두 초기화하고 확정 이탈 유무와 별개로 보류 구간·사유를 남긴다.
기준·배치가 유효한 입력이 돌아오면 새 연속 구간을 시작한다. 이탈 6초→자리 비움→이탈 4초의 경고는 0회이다.
사용자 정지나 복구 대기가 필요한 상태에서는 입력만 돌아왔다고 자동 재개하지 않는다. 자리 비움 자체는 촬영 종료가 아니다.

#### F5. 설정 입력 검증·적용·버전 기록

- 입력: 민감도, 경고 시간·재경고 간격·소리, 적용 버튼이다.
- 출력: 유효 설정·적용 시각·설정 버전, 잘못된 입력 안내이다.

처음에는 기본 경고 10초·재경고 60초를 표시한다. 0·소수·음수는 '양의 정수를 입력해 주세요'로 거부하고 기존 저장값·설정 버전·측정 구간을 유지한다.
유효한 값의 적용은 설정 화면을 닫고 적용 시각·불변 버전을 저장한다. 진행 이탈은 설정 변경으로 닫고 새 연속 구간으로 판정한다.
같은 브라우저에서 재접속하면 적용값이 보인다. 기준 등록 5초·복귀 3초·자동 리포트 유효 30분은 이 화면에서 변경하지 않는다.
시간 입력 상한·민감도별 판정 경계는 실측 후 확정한다.

#### F6. 자동 리포트·종료 리포트

- 입력: 유효 구간, 확정 이탈, 실제 경고, 정상 복귀·중단 원장이다.
- 출력: 유효 시간·합집합 이탈 시간/비율, 이탈·경고·복귀·중단 내역이다.

유효 감지 누적 1800초(30분)마다 '리포트가 준비됐어요'를 표시하고 자동 리포트 1개를 생성한다. 탐지와 세션은 계속한다.
테스트 환경(NODE_ENV=test 및 명시적 테스트 도구 활성화)의 S3에서는 리포트 스케줄러에 테스트용 시계·주기를 주입해 첫 자동 주기를 유효 3초로 대체한다. 가속된 3초 후 리포트가 정상 팝업됨을 확인한다.
등록·경고·복귀·재경고 시간은 가속하지 않는다. 테스트 리포트는 실제 V=3초로 집계하고 1800초 관찰로 표시하지 않는다. 첫 생성 후 가속을 해제해 후속 주기는 1800초로 복원한다.
종료 시 마지막 자동 경계 이후 남은 유효 구간만 종료 리포트로 만든다. 정확한 경계 종료는 빈 리포트를 만들지 않는다.
자세 이탈 비율은 확정 이탈 합집합 시간 D / 전체 세션 유효 시간 V * 100(%)으로 표시한다. 여러 리포트는 D와 V를 각각 합산한 뒤 계산하며 백분율을 단순 평균하지 않는다.
유효 시간 0은 '분석 가능한 기록이 없습니다'로 표시하고 비율을 계산하지 않는다. 지속 조건을 충족하기 전의 이탈 후보는 D에서 제외하지만 해당 유효 입력 시간은 V에 포함한다.
같은 이탈의 유형 중첩은 시간을 합집합하고 경계를 넘으면 ID를 유지한다. 신규 횟수는 onset 구간, 경고는 실제 표시 구간에 귀속하며 늦은 확정은 같은 리포트 ID를 개정한다.
등록·자리 비움·인식 불가·정지·복구 대기·재등록 준비 시간은 유효 시간과 이탈 시간에서 제외한다.

#### F7. 로컬 기록 조회·조건부 비교·삭제

- 입력: 내 기록, 세션 선택, 이전 기록과 비교, 기록 삭제·삭제 확인이다.
- 출력: 같은 PC 브라우저의 저장 기록, 비교 가능 여부·삭제 결과이다.

로그인 없이 같은 PC 사이트·브라우저 프로필에 실제 저장된 기록만 표시한다.
모드·지표·기준·설정·배치 유효성이 같을 때만 정량 비교한다. 조건 차이는 '조건이 달라 비교할 수 없어요', 자료 부족은 '비교할 기록이 부족해요'를 표시한다.
종료 세션 삭제는 원장·리포트·파생 집계에 함께 반영하고 현재 등록 기준과 다른 세션이 참조하는 기준을 보존한다.
전체 삭제의 기준·설정 포함 여부는 확인 화면에서 구분한다. 기록이 없으면 '저장된 기록이 없어요'를 표시한다.
보관 기간·자동 만료 시점은 정책 확정 항목이다. 브라우저 정리·사이트 데이터 삭제로 소실될 수 있으며 영구 보관을 보장하지 않는다.

#### F8. QR 휴대폰 승인 연결

- 입력: PC 딥 모드 사용하기, 휴대폰 연결 요청, PC 연결 승인이다.
- 출력: 해당 PC 세션에 승인된 휴대폰 연결 상태이다.

QR 생성만으로 촬영하지 않는다. 휴대폰 '연결 요청' 뒤 PC '연결 승인'을 거쳐야 연결한다.
단일 PC E2E에서는 테스트 환경에서만 '테스트 도구'를 펼쳐 '[테스트용] 측면 데이터 주입'을 누른다. QR 스캔·휴대폰 연결 요청을 대체하는 동일 형식의 연결 요청·측면 특징·품질·시각을 주입하며 PC의 연결 승인·기준 등록·탐지 시작은 실제 UI 경로를 따른다.
만료·사용·재발급으로 무효가 된 QR 요청은 거부하고 이유를 표시한다. 새 휴대폰으로 자동 교체하지 않는다.
연결 상태·종료 요청·종료 확인을 구분한다. QR 만료 시간과 연결 감시 주기는 연결 시험 후 확정한다.

#### F9. 측면 배치·개인 기준 등록

- 입력: 휴대폰 카메라 권한, 측면 배치 가이드, 기준 자세 등록이다.
- 출력: 정면·측면 기준 ID와 측면 배치 품질이다.

정면·측면 필수 입력이 함께 연속 안정 5초를 충족해야 '기준 자세가 등록됐어요'를 표시한다.
한쪽이라도 자리 비움·인식 불가이면 등록 타이머를 초기화하고 딥 모드 탐지 시작을 막는다.
지원 방향·거리·촬영 범위는 실측 대상이다. C7을 측정하지 않는 지표를 임상 CVA로 표시하지 않는다.

#### F10. 통합 탐지·연결 장애 복구

- 입력: 정면·측면 특징·품질·측정 시각, 연결 상태, 기본 모드로 계속이다.
- 출력: 딥 모드 판정, 복구 대기, 같은 세션의 기본 모드 구간이다.

유효하고 동기화된 두 입력만 결합한다. 한쪽이 무효이면 전체 판정·유효 시간 누적을 보류하고 연속 타이머를 초기화한다.
연결 끊김이 확인되면 연결 권한을 무효화하고 '복구 대기'를 표시한다. 정면 기준·입력이 유효할 때만 '기본 모드로 계속'을 허용한다.
정면 기준·입력이 무효이면 '기본 모드로 계속'을 비활성화하고 복구·재등록을 안내한다. 입력이 돌아와도 사용자 선택 전에는 자동 전환하지 않는다.
같은 세션에서 딥·기본 구간을 분리하고 장애·모드 변경을 정상 복귀로 집계하지 않는다. 전환 뒤 새 연속 이탈 10초를 요구하고 장애 전 타이머를 이어 붙이지 않는다.
모드별 D·V·비율을 분리하며 서로 다른 모드의 비율을 개선 효과로 비교하지 않는다. 전체 세션 비율은 합산 D / 합산 V로 기술 통계만 제공한다.
휴대폰 종료 요청과 실제 확인은 구분한다. 장애 판정 시간·휴대폰 자체 중단 시간은 실제 기기 시험 후 확정한다.

#### F12. 로그인 없는 로컬 저장·처리 범위 안내

- 입력: 시작·카메라·저장·삭제 요청이다.
- 출력: 로컬 저장 범위·개인정보 한계·실패 안내이다.

첫 화면에 '로그인 없이 이 PC 브라우저에 기록을 저장해요'를 표시한다. 기록·리포트·기준·설정은 같은 PC 사이트·브라우저 프로필의 로컬 저장이다.
IndexedDB/localStorage는 구현 수단이며 같은 저장 범위·삭제·실패 계약을 따른다. 계정·클라우드 동기화·다른 브라우저 복원·공유 PC 타인 접근 보호를 제공한다고 쓰지 않는다.
원본 영상·연속 원시 좌표는 저장·전송하지 않는 구조가 목표이다. 딥 모드의 최소 특징·품질·시각은 승인된 보안 연결로 PC에 전달하되 휴대폰·중계에 개인 기록 이력을 보관하지 않는다.
저장 실패를 완료로 표시하지 않는다. 저장·네트워크·카메라 종료는 실기기 시험 항목이다.

## 9. 집계·경계 계약

유형이 겹쳐도 전체 D는 합집합이다. 유형 변경·재경고·자동 경계가 같은 이탈 ID를 늘리지 않는다. 중단 시 기존 이벤트를 닫고 새 조건으로 시작한다. 신규 이탈 횟수는 이탈 시작 구간에, 경고 수는 실제 표시 구간에 귀속한다.

유효 1800초 경계에 지속 조건을 충족하기 전의 이탈 후보가 있으면 리포트를 잠정 표시하고 나중에 확정될 때 같은 리포트 ID를 개정한다. 확정 시작 시각 기준으로 시간을 나눠 이전·이후 D와 R도 다시 계산한다. 정확한 1800초에 종료하면 자동 리포트 1개만 유지한다. 구체 산술·개정·삭제 계약은 [report-contract.md](report-contract.md)를 따른다.

## 10. 리스크 및 검증 계획

### 10.1 피드백의 작업 부담과 효과

| 근거·리스크 | 원문 결과 | 검증·대응 |
|---|---|---|
| [R3: Posture biofeedback increases cognitive load, 2022](https://link.springer.com/article/10.1007/s00426-021-01622-2) | 젊은 성인이 컴퓨터 게임을 하는 조건에서 목 자세 지표는 개선됐지만 게임 수행 점수는 낮아졌다. | 무알림·고정 시간 알림·변화 기반 알림을 같은 작업 조건에서 비교하고, 인지 지연·이탈 비율·작업 중단·오경고를 함께 측정한다. |
| [R4: Can biofeedback training in combination with ergonomic information reduce pain among young adult computer users with neck and upper extremity symptoms?, 2024](https://pubmed.ncbi.nlm.nih.gov/37883913/) | 참가자 39명의 무작위 대조 연구에서 개입군은 대조군 대비 작업 자세·통증·자각적 부담을 유의하게 개선하지 못했다. | 개인 기준 이탈 감지와 자기 조정을 제품 범위로 두고 통증 치료·임상 개선·예방 효과를 제품 성과로 주장하지 않는다. |
| R2의 작업 부담 | 복합 개입과 함께 평균 생산성 11% 감소가 보고됐다. | 자세 지표 개선과 작업 수행 저하를 함께 평가하며 경고 수 증가를 성공으로 삼지 않는다. |

### 10.2 성공 판단과 실패 조건

이탈 시작·알림 표시·사용자 인지 보고·복귀 확인 시각을 구분한다. 인지 보고 없이 알림 시각이나 복귀 시각을 인지 시각으로 대체하지 않는다. 같은 사용자·작업·모드·기준·설정·배치에서 R과 인지 지연의 감소를 확인하고, 감지 정밀도·놓침·시간당 오경고·유효 시간·보류 비중·작업 중단을 함께 기록한다. R이 줄지 않거나 작업 방해가 허용 범위를 넘으면 성공으로 판정하지 않는다. 환경 개선만으로 충분한 사용자는 별도로 구분한다.

목표 감소폭·실험 참여자 수·최소 관찰 시간·오경고·작업 방해 허용치는 실험 전에 확정한다. E1~E3는 정성 인터뷰 근거이며 인지 지연·빈도·효과의 정량 측정은 별도 실험으로 수행한다.

### 10.3 실제 기기·테스트 예외·제출 규격

[최신 Starter Kit 대조](starter-kit-review.md)에 따라 시나리오는 3~8개·단계 1~12개·제목 1~120자·expected 1~500자이다. 각 chosen 경로를 끝까지 수행하며 각 흐름에서 입력과 저장 상태를 자체 준비한다.

S3의 첫 자동 주기는 테스트에서만 유효 3초로 가속하고 생성 직후 1800초로 복원한다. S5·S6은 테스트 UI로 측면 데이터와 장애를 주입한다. 모든 테스트 도구는 NODE_ENV=test와 명시적 활성화를 함께 요구하고 운영에서는 버튼·입력 핸들러를 제공하지 않는다. 테스트 입력은 연결·센서·시계만 대체하며 승인·등록·판정·집계·저장은 공통 경로를 실행한다.

| 검증 범위 | 수용 기준 |
|---|---|
| 운영 리포트 | 유효 29:59에는 자동 생성하지 않고 30:00에 생성한다. 테스트 3초를 운영 30분으로 환산하지 않는다. |
| 테스트 도구 격리 | 운영에서 테스트 UI·주입 핸들러가 없고 URL·로컬 저장만으로 켜지지 않는다. 세션·context마다 초기화한다. |
| 딥 실기기 | 실제 QR·HTTPS·측면 추론·동기화·연결 장애·휴대폰 촬영 종료를 시험한다. |
| 연결·판정 정책 | QR 만료·감시·장애 판정·휴대폰 자체 중단 시간·동기화 오차·촬영 범위·민감도 경계는 실측 후 확정한다. |
| 저장·설정 정책 | 보관 기간·자동 만료·시간 설정 상한은 구현 전 확정한다. 기존 기본값과 양의 정수 검증은 유지한다. |
| 주최측 재현 규칙 | 키트의 가짜 응답·상태 금지와 테스트 시계·입력 주입 허용 범위를 제출 전에 확인한다. |
| 실행 시간 | 시나리오별 로컬 1분 이내 실행 시간을 구현 후 측정한다. |

기획 문서 검사는 앱·카메라·E2E·배포·효과 검증과 별도이다. 구체 실험·경계 검증은 [validation-plan.md](validation-plan.md)를 따른다.

## 11. 문서 역할과 기준

[problem.yaml](problem.yaml)은 문제·사용자 경험·출처·팀 분석·핵심 기능을 담는다. 정책 수치와 기능별 세부 구현 계약은 이 PRD의 4~9절에 둔다. [planning-policy.yaml](planning-policy.yaml)은 같은 정책을 구조화한 참조이며 변경 시 함께 맞춘다. [scenarios.yaml](scenarios.yaml)은 S1~S8의 독립 UI 흐름과 테스트 예외를, [report-contract.md](report-contract.md)는 상세 집계·삭제 산술을 담당한다.

기능 ID는 F1~F10·F12를 유지한다. 기능 수를 줄이는 대신 각 기능의 입력·결과·관찰 가능한 완료 조건을 짧게 표현해 기존 시나리오와 연결한다. 과거 원문은 [archive/](../archive/README.md)에 보존한다.
