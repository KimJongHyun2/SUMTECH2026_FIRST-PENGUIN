## 1. 한 문장

**거북목은 본인은 모르고 남이 봐야 안다. 친구 대신 정면 웹캠이 내 자세를 보고, 내가 등록한 바른 자세에서 벗어난 상태가 이어지면 "거북이가 되었습니다"라고 알려 준다.**

목적(기능 명세서): 개인 기준 자세와의 변화를 감지하고, 이탈이 지속되면 경고해 자세 확인과 조정을 돕는다. **거북목을 진단하거나 치료·예방 효과를 판정하지 않는다.**

## 2. 문제 — 누가, 언제, 어디서, 어떻게

| 항목 | 내용 | 상태 |
|---|---|---|
| 누가 | 노트북으로 공부·작업하며 오래 앉아 있는 대학생(우리 팀), 같은 상황의 개발자·직장인 | 확정 |
| 언제·어디서 | 장소·시간을 가리지 않고, 업무·공부에 **집중할 때면** | 확정 |
| 어떻게 | 허리가 구부정해지고 목이 앞으로 나온다. 집중하고 있어서 **본인은 모른다** | 확정 |
| 어떻게 알게 되나 | 친구가 "너 목이 좀 휘었어. 거북이 같아."라고 말해 줘서 | 확정 |
| 그때 기분 | 기분이 나쁘고 스트레스를 받는다. 건강이 나빠진다 | 확정 |
| 실제 경험 E1 | 친구가 알려 준 장면 — 언제, 무슨 말, 어떻게 넘겼나 | 학생 답 대기 |
| 측정 가능한 영향 | 출처 있는 수치, 또는 팀이 직접 잰 기록 | 학생 답 대기 |

### 왜 아직 아무도 못 고쳤나 (5 Whys)

1. 증상: 거북목이 된다
2. 왜? 구부정한 자세를 오래 유지한다
3. 왜? 업무에 집중하면 자세가 자연스럽게 무너진다
4. 왜? **지금 자기 자세가 어떤지 본인은 모른다 — 다른 사람이 봐야 알 수 있다**
5. 왜 알고 나서도 안 고쳐지나? 스트레칭을 해도 **다시 무너지는 순간은 여전히 아무도 알려 주지 않는다** ← 근본 문제

### 지금 버티는 방법과 남는 문제

| 현재 대안 | 남는 단점 | 우리가 다른 점 |
|---|---|---|
| 자세 교정 의자·베개 | 완치가 안 된다. 의자에 앉아 있어도 집중하면 다시 목이 나온다 | 의자는 자세가 무너져도 알려 주지 않는다. 우리는 무너지는 순간을 잡아낸다 |
| 아플 때 턱 당기기·스트레칭 | 확실한 해결 방법이 없어서 이게 전부인데 완치가 안 된다. 아플 때만 하니 그 사이에 모르는 채로 악화된다 | 스트레칭은 아픈 뒤의 사후 대응. 우리는 아프기 전, 나쁜 자세가 이어지는 바로 그때 알려 준다 |

## 3. 해법과 원칙

**공식 자세 안내(KOSHA) → 개인 기준 자세 등록 → 정면 웹캠으로 기준 대비 변화 측정 → 변화가 지속될 때만 경고 → 세션 리포트**

| 원칙 | 내용 | 상태 |
|---|---|---|
| 친구를 대신한다 | 알려 주던 건 늘 옆 사람. 그 역할을 노트북에 달린 카메라가 한다 | 확정 |
| 내 바른 자세가 기준이다 | 보편적 "정상 각도"는 정면 웹캠에서 확정할 수 없다(개발 상세 §5). 그래서 KOSHA 안내로 잡은 **개인 기준**과의 변화만 본다 | 확정 |
| 처음 보이는 자세를 그대로 기준으로 삼지 않는다 | 안내를 거친 뒤 등록한다(개발 상세 §1) | 확정 |
| 순간 움직임은 봐준다 | 필기·물 마시기 같은 짧은 움직임은 경고하지 않는다. **지속적인 이탈**에만 경고한다(T03) | 확정 |
| 진단·치료하지 않는다 | 거북목 판정·CVA 표시를 하지 않는다. 어깨점을 C7 대신 넣고 CVA라고 부르지 않는다 | 확정 |
| 영상은 내 컴퓨터를 떠나지 않는다 | 브라우저 안에서 분석, 원본 영상 저장·전송 없음(P03·P04) | 확정 |

## 4. 서비스 구성과 범위

| 구분 | 기본 모드 | 딥 모드 |
|---|---|---|
| 장치·방향 | 노트북·PC 카메라, 정면 | PC 카메라 + 휴대폰 카메라(QR 연결), 정면 + 측면 |
| 측정 | 머리–어깨 간격 비율, 얼굴 면적 변화, 어깨 변위 (+ 보조: 머리·어깨 기울기) | 기본 + 머리 앞뒤 위치, 고개 숙임, 상체 기울기 |
| 이번 대회 | **MVP — 만든다** | **보류** — 설계는 기능 명세서 D01~D17에 있음. 정면 기준이 동작한 뒤 |

### 구현 범위 (기능 명세서 ID 기준)

| 단계 | 포함 | 상태 |
|---|---|---|
| **MVP (대회 제출)** | C01~C07 안내·카메라·기준 등록 / T01~T07 탐지·상태 / A01~A06 경고·설정 / S01~S03·S05 세션 / R01·R03·R04 세션 리포트 / P01·P04·P06 개인정보 | 가정 (기능 명세서의 "1차 구현 범위"에서 딥 모드만 뺌) |
| 2차 | S06 비정상 종료 / R05 이력·R08 삭제·R02 / A07 오탐 피드백·A08 휴식 알림 | 가정 |
| 보류 | 딥 모드 D01~D17·S04 / 랭킹 L01~L05 / R06·R07 | 확정(보류) |

딥 모드를 MVP에서 뺀 이유: 휴대폰↔PC 실시간 연결·QR·배치 검증은 서버 세션이 필요해 2일 안에 정면 판정 실험과 함께 끝내기 어렵다. 측면 지원 방향·거리 허용 범위도 "검증 결과에 따라 제시"(D06)로 아직 없다. **팀이 "딥 모드도 넣는다"고 하면 이 표를 바꾼다.**

## 5. 사용자 흐름 (기본 모드)

웹 접속 → 사용 안내·카메라 허용 → 기준 자세 등록 → 세션 시작 → 탐지·경고 → 종료 → 리포트 확인

화면 글자(메뉴·버튼)는 scenarios.yaml과 E2E가 그대로 찾아요. 바꾸면 세 곳을 같은 commit에서 고쳐요.

### S1. 처음 와서 기준 자세를 등록한다 (C01~C05)

1. `/` → 서비스 이름 **패스트거북이**, "친구 대신 웹캠이 내 거북목을 알려 줘요", 안내(목적·카메라 배치·기준 등록·경고 방식·영상 처리 방식 = C01·P01)
2. **시작하기** → `/setup`
3. **카메라 켜기** → 허락 → 미리보기 + 얼굴·어깨 인식 표시(C03). 카메라가 여럿이면 선택(C02)
4. 안내: "화면을 몸 앞에 두고 자연스럽게 고개를 세우세요 · 어깨를 으쓱하지 말고 팔을 내리세요 · 눈과 화면은 40cm 이상 · 화면은 약간 아래를 보게" (KOSHA 기준)
5. 얼굴·어깨가 안정적으로 잡히면 **기준 등록** 활성(C04) → 누르면 3초 측정 → "기준 자세가 등록됐어요" → `/watch`
- 기대 결과: 새로고침해도 기준이 남아 있다

### S2. 세션을 시작하고 거북이가 되면 경고를 받는다 (S01, T01~T03, A01~A03)

1. `/watch` → **세션 시작** (처음이면 **알림 허용**)
2. 바르게 앉음 → 상태 **감지 중 · 바른 자세**, 이탈 시간 `0:00`
3. 목을 내밀거나 숙임 → **주의** 표시, 이탈 시간 증가
4. 이탈이 경고 시간(가정 30초)을 넘김 → 화면 배너 **거북이가 되었습니다** + 브라우저 알림 + 소리(켜져 있으면)
5. 자세를 고치고 복귀 확인 시간(가정 5초) 유지 → 경고 해제, 이탈 시간 `0:00`
- 기대 결과: 다른 창에서 일하고 있어도 4번 알림이 온다

### S3. 세션을 끝내고 리포트를 본다 (S05, R01·R03·R04)

1. `/watch`에서 **세션 종료** → `/report`
2. 전체 세션 시간, 유효 감지 시간, 이탈 횟수·누적 시간·비율·최장 연속, 경고 횟수(최초·재경고)·시점
- 기대 결과: S2에서 받은 경고 1회가 리포트에 보인다

### S4. 자리가 바뀌어 기준을 다시 등록한다 (C06)

1. `/watch`에서 **기준 다시 등록** → 세션 일시 정지 → `/setup` → S1 3~5
- 기대 결과: 새 기준으로 판정된다

### S5. 카메라를 거부했다 (C07)

1. `/setup`에서 **카메라 켜기** → 거부
2. "카메라를 쓸 수 없어요. 주소창의 카메라 아이콘에서 허락한 뒤 **다시 시도**를 눌러 주세요", **기준 등록** 비활성
- 기대 결과: 등록되지 않고 이유와 재시도 방법이 보인다

### S6. 자리를 비우거나 얼굴이 안 보인다 (T05·T06·T07)

1. 세션 중 화면 밖으로 → 상태 **자리 비움**(사람 없음) 또는 **인식 불가**(일부만 보임). 판정·경고 중단, 유효 감지 시간 멈춤. **정상 자세로 처리하지 않는다**
2. 돌아옴 → 2초 안정 확인 뒤 **감지 중** 재개, 이탈 구간은 새로 센다
- 기대 결과: 자리 비운 시간은 유효 감지 시간·이탈 시간에 들어가지 않는다

## 6. 화면 명세

### `/` 첫 화면 — 로그인 없이 누구나
제목 **패스트거북이** / 소개 "친구 대신 웹캠이 내 거북목을 알려 줘요" / 안내 4줄(카메라 배치, 기준 등록, 경고 방식, "영상은 내 컴퓨터 안에서만 처리하고 어디에도 보내지 않아요") / **시작하기**(기준 없으면 `/setup`, 있으면 `/watch`)

### `/setup` 기준 자세 등록
| 요소 | 글자 | 규칙 |
|---|---|---|
| 버튼 | **카메라 켜기** / 카메라 선택 | 허락 전·여러 대일 때 |
| 영상 | 미리보기 + 얼굴·어깨 점 표시, 인식 상태 "인식 중 / 안정" | 거울처럼 좌우 반전 |
| 안내 | KOSHA 4줄 (S1-4) | |
| 버튼 | **기준 등록** | 인식 "안정"일 때만 활성. 3초 평균 저장(가정) |
| 성공 | 기준 자세가 등록됐어요 | → `/watch` |
| 오류 | 카메라를 쓸 수 없어요 … **다시 시도** | 거부·장치 없음·끊김 |
| 오류 | 얼굴과 양쪽 어깨가 보이게 앉아 주세요 | 인식 실패 |

### `/watch` 감지 화면
| 요소 | 글자 | 규칙 |
|---|---|---|
| 상태 | **준비 중 / 감지 중 / 일시 정지 / 자리 비움 / 인식 불가 / 종료** (T04) + 감지 중일 때 **바른 자세 / 주의** | 크게, 색 구분 |
| 시간 | 이탈 시간 `m:ss`, 세션 시간 | |
| 영상 | 작은 미리보기 (**영상 숨기기** 가능, 감지는 계속) | |
| 버튼 | **세션 시작** / **일시 정지** ↔ **재개** / **세션 종료** | S01~S03·S05 |
| 버튼 | **알림 허용** | 권한 없을 때만 |
| 설정 (A06) | 민감도 낮음·보통·높음 / 경고 시간 `30`초 / 재경고 간격 `60`초 / 소리 켬 | 바꾸면 시점·값 기록 |
| 버튼 | **기준 다시 등록** | 일시 정지 후 `/setup` |
| 경고 | **거북이가 되었습니다** — 기준 자세에서 벗어난 상태가 이어지고 있어요. 자세를 확인해 주세요 | 배너 + 브라우저 알림 + 소리. 복귀 확인 뒤 해제 |

### `/report` 세션 리포트
표: 전체 세션 시간 / 유효 감지 시간 / 이탈 횟수 / 이탈 누적 시간 / 이탈 비율 / 최장 연속 이탈 / 경고 횟수(최초·재경고) / 경고 시점 목록. 유효 감지 시간 0이면 비율 "—". **다시 시작하기** → `/watch`

없는 주소는 404("없는 페이지예요" + **첫 화면으로**).

## 7. 판정·경고 규칙

근거와 한계는 [detection-basis.md](detection-basis.md). 여기서는 구현 규칙만.

### 측정 지표 (T01) — 모두 **기준 대비 변화율**로 정규화

| 지표 | 계산 | 뜻 | 역할 |
|---|---|---|---|
| 머리–어깨 간격 | 턱·광대에서 어깨선까지 세로 거리 ÷ 광대 너비 | 머리가 어깨 쪽으로 내려옴 | 주 지표 |
| 화면 접근 | 양눈·코끝 삼각형 면적 ÷ 기준 면적 | 얼굴이 화면에 가까워짐 | 주 지표 |
| 어깨 변위 | 좌우 어깨점의 기준 대비 위치 변화 (어깨 너비로 정규화) | 상체 이동 | 주 지표(보정용) |
| 머리 기울기 | 양눈 연결선 각도 변화 | 고개 옆으로 | 보조 |
| 어깨 기울기 | 양어깨 연결선 각도 변화 | 몸 한쪽으로 | 보조 |

- **얼굴 면적만 커졌다고 이탈로 보지 않는다.** 의자째 다가오거나 카메라가 움직여도 커진다. 어깨 변위와 함께 봐서 "어깨는 그대로인데 얼굴만 커짐/내려옴"일 때 전방 이탈로 추정한다 (개발 상세 §2-B)
- 보조 지표 단독으로는 경고하지 않는다 (가정)

### 단계 (판정 기준 근거 + 기능 명세서 T02·A03·A04)

| 단계 | 조건 | 동작 | 상태 |
|---|---|---|---|
| 바른 자세 | 주 지표가 기준 ±민감도 안 | 상태 "바른 자세" | — |
| 주의 | 주 지표 이탈이 **지속 시작** | 상태 "주의", 이탈 시간 시작 | 실험: 임계값 시작값 — 화면 접근 +10%, 머리–어깨 간격 −10% (민감도 보통). **10%는 출처를 확인하지 못한 설계값**(detection-basis 7장) |
| 경고 | 주의가 **30초** 이어짐 | 거북이가 되었습니다 (배너·알림·소리) | 가정 30초 — problem.yaml R1(Cureus 30초 지연)·R2(ErgoAssist 30초)·R3(블로그 30초 시작)이 지지. "15°"는 출처 확인 실패로 쓰지 않음 |
| 재경고 | 경고 뒤에도 이탈 지속 | **60초**마다 다시 (A04). 여러 지표 동시 이탈도 경고는 1건 (A05) | 가정 |
| 복귀 | 기준 범위로 돌아와 **5초** 유지 | 경고 해제, 이탈 구간 닫힘 (A03) | 가정 (근거 없음, 깜빡임 방지 설계값) |
| 감지 불가·자리 비움 | 필수 지점 없음/신뢰도 낮음 | 판정·경고 중단, 이탈 구간 닫음, 유효 시간 멈춤. 정상으로 치지 않음 (T05·T06) | 확정 |

- 민감도 낮음/보통/높음 = 임계값 ×1.5 / ×1.0 / ×0.7 — 가정
- 팀이 처음 말한 "5분"은 경고 시간 설정의 후보값으로 남긴다. 실험(8장)에서 30초·5분 중 오경고/놓침이 나은 쪽을 고른다 — 실험

### 집계 (리포트)

기능 명세서 "지표 집계 기준" 그대로: 전체 세션 시간 / 유효 감지 시간(일시 정지·자리 비움·인식 불가 제외) / 이탈 발생 횟수(지속 조건 충족 구간 수) / 이탈 누적 시간(최초 이탈~복귀 확인) / 이탈 비율(누적÷유효×100, 유효 0이면 계산 안 함) / 경고 횟수(최초+재경고). 감지 중단 시 진행 중 구간을 닫고 재개 후 새 구간.

## 8. 성공 기준

| 구분 | 기준 |
|---|---|
| 동작 | 팀원이 S1→S2→S3을 그대로 해서 경고 1회를 받고 리포트에 1회로 남는다 |
| 정확도 (실험) | 팀원 3명, 각자 기준 등록 뒤 ① 바르게 앉기 3분 ② 의도적 거북이 2분 ③ 물 마시기·필기 등 짧은 움직임 10회. ①③에서 거짓 경고 0회, ②에서 경고 발생. 사람·세션을 나눠 두 번 |
| 신뢰 | 영상·이미지·좌표가 네트워크로 나가지 않는다(네트워크 탭 확인). 세션 중 CPU가 팬이 돌 정도로 높지 않다(5fps 처리, 가정) |
| 제출 | `docker compose up --build`로 뜨고, S1~S6이 E2E로 통과하고, 공개 HTTPS URL에서 같은 동작 |
