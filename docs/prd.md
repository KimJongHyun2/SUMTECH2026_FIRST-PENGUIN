# 패스트거북이 — MVP 구현 설계

패스트거북이는 공부·코딩에 몰입한 대학생에게 지속적인 자세 변화를 알려, 스스로 자세를 확인하고 조정하도록 돕는 서비스이다. 노트북 웹캠의 개인 기준 비교와 경고·복귀 기록·리포트를 연결해 거북목 예방을 위한 일상 자세 관리를 지원한다.

## 1. 범위와 문서 역할

[problem.yaml](problem.yaml)이 문제·경험·근거·선택한 해법·기능 완료 조건을, [scenarios.yaml](scenarios.yaml)이 사용자 흐름을 담당한다. 이 문서는 세부 구현 규칙을 담당한다. 실제 실행 결과와 미완료 사항은 [진행 기록](../progress.md)에 둔다.

기능 범위가 바뀌면 팀의 결정에 따라 `problem.yaml`의 `solution_paths`·`features`부터 수정하고 이 문서·시나리오·테스트를 맞춘다.

- 기본 경로는 개인 기준 등록 → 탐지 → 지속 이탈 경고 → 자기 조정 → 리포트·기록 확인이다.
- 선택형 딥 모드는 휴대폰 연결 승인 → 양쪽 기준 등록 → 통합 탐지 → 종료의 경로이다.
- 로그인 없이 같은 PC 사이트·브라우저 프로필에 저장한다. 로그인·클라우드 동기화·랭킹은 보류 범위이다.
- 딥 모드·유효 30분 자동 리포트·기록 비교를 포함한다. 기본 경로를 먼저 연결하고 딥 모드를 이어 구현한다.

### 처리와 저장의 담당 범위

| 담당 | 책임과 경계 |
|---|---|
| PC 브라우저 | 정면 영상 추론·개인 기준 등록·세션 판정·경고·리포트 집계와 IndexedDB 저장·조회·비교·삭제를 담당한다. |
| 휴대폰 브라우저 | 딥 모드에서 승인된 연결에 최소 특징·품질·시각을 전달하고 촬영 종료 요청에 응답한다. 개인 기록 이력을 보관하지 않는다. |
| 서버·중계 | 앱 제공·`/__health`와 딥 모드 QR 토큰·연결 요청·PC 승인·측면 입력 전달·유실·종료 확인을 담당한다(6절 프로토콜). 연결 상태는 메모리에만 두고 끝나면 지운다. PC의 기록 저장·조회·비교·삭제를 서버 저장 기능으로 바꾸지 않는다. |

현재 기능은 서비스용 LLM API를 호출하지 않는다. 실행·환경변수·배포는 [README](../README.md)를, 구현 완료 여부는 진행 기록을 따른다.

## 2. 화면과 판정 입력

| 화면 | 주요 행동과 결과 |
|---|---|
| 첫 화면 `/` | 서비스 이름·목적·로컬 저장 안내, 자세 등록하고 시작·딥 모드 사용하기·내 기록을 제공한다. |
| 등록 `/setup` | 카메라 켜기 → 배치 안내 → 기준 자세 등록 → 탐지 시작이다. |
| 감지 `/watch` | 상태·유효 시간·경고·판정 보류를 표시하고 일시 정지·재개·종료·설정·재등록·리포트 보기를 제공한다. |
| 딥 연결 `/connect`·휴대폰 `/phone` | 연결 요청 → PC 연결 승인 → 측면 배치 → 양쪽 기준 등록 → 딥 모드 탐지 시작이다. |
| 리포트 `/report` | 유효 시간·확정 이탈 시간·비율·경고·복귀·중단·저장 결과를 표시한다. 진행 중 닫기는 같은 세션으로 돌아간다. |
| 기록 `/history` | 저장된 세션 선택·리포트 조회·조건부 비교·삭제 확인을 제공한다. |

첫 화면은 ‘로그인 없이 이 PC 브라우저에 기록을 저장해요’를 안내한다. 카메라 권한 거부·장치 없음은 ‘카메라를 쓸 수 없어요’와 재시도 안내를 표시하고 등록·시작을 막는다. 없는 주소는 404와 첫 화면 안내를 제공한다.

‘머리가 기준보다 앞으로 나왔어요’는 해당 유형을 판별할 수 있을 때 쓰는 상태 문구이다. 공통 경고는 ‘기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.’이다. 입력이 무효이면 자세를 추정하지 않고 판정 보류를 표시한다.

기본 판정은 MediaPipe Pose·Face의 머리–어깨 관계·목 길이·고개 각도 특징을 개인 기준과 비교한다. 안정 등록은 비교할 입력을 모으는 과정이며, 기준 자세는 의학적 정상 인증이 아니다. 제품의 예방 목적과 질환의 진단·치료·장기 예방 효과의 입증은 구분한다.

R7~R9는 특징 설계의 기술 참고이며 출처·주장은 problem.yaml을 따른다. 얼굴 크기만으로 목 전진을, 어깨 기울기만으로 둥근어깨를 확정하지 않는다. C7을 측정하지 않은 대체 지표는 임상 CVA로 표시하지 않는다.

[판정 코드](../posture-web/src/core/detector.js)의 경계값은 파일럿이다. 사람·촬영 세션을 나눠 오경고·놓침·유효 시간·보류 사유를 확인하고 민감도·측면 촬영 범위·동기화 오차를 확정한다.

## 3. 시간과 상태 전이

제품 기본값은 아래와 같다. [policy.js](../posture-web/src/core/policy.js)와 함께 관리하며 사용자가 바꿀 수 있는 항목은 5절을 따른다.

| 정책 키 | 기본값 | 완료 조건 |
|---|---:|---|
| `baselineStableSeconds` | 5초 | 필수 입력이 연속 안정·유효하면 기준을 저장한다. 중단·불안정이면 처음부터 모은다. |
| `deviationSeconds` | 10초 | 기준 이탈이 연속 유효 10초이면 확정 이탈·최초 경고를 만든다. |
| `recoverySeconds` | 3초 | 확정 이탈 후 기준 범위가 연속 유효 3초이면 경고를 해제하고 정상 복귀 1회를 남긴다. |
| `rewarningSeconds` | 60초 | 같은 확정 이탈의 최초 경고 뒤 연속 유효 60초마다 재경고한다. |
| `reportValidSeconds` | 1800초 | 누적 유효 30분마다 자동 리포트를 만들고 세션을 계속한다. |
| `qrExpirySeconds` | 120초 | 발급 후 경과 120초 미만만 QR 요청·승인할 수 있다. |

F1·F2·F4의 구현·검수 기준은 입력 무효 시 즉시 연속성 초기화이다. 아래 값은 코드 대조용이며 정책 변경은 아니다. 구현 차이와 후속 조치는 진행 기록에서 관리한다.

| 정책 키 | 코드값 | 계약과의 차이 |
|---|---:|---|
| `recognitionGraceSeconds` | 0초 | 없다. 첫 무효 프레임에서 즉시 초기화한다. 짧은 가림 2초 유예는 미채택 파일럿이며 기본값으로 쓰지 않는다. |

세션 상태·입력 유효성·연결·저장 결과는 구분한다. 입력 중단은 세션 기록 삭제나 정상 복귀가 아니다.

| 조건 | 처리 |
|---|---|
| 진행·유효 입력 | 연속 타이머와 세션 유효 시간을 누적한다. |
| 자리 비움·인식 불가·영상 갱신 중단 | 후보를 폐기하고 확정 이탈은 중단 사유로 닫는다. 경고·유효 시간 누적을 멈추고 이탈·복귀·재경고 타이머를 초기화한다. 보류 구간·사유를 별도로 남긴다. |
| 입력 복원 | 기준·배치가 유효하고 세션이 진행 중일 때 새 연속 구간을 시작한다. 사용자 정지·복구 대기는 입력만 돌아왔다고 재개하지 않는다. |
| 사용자 일시 정지 | 촬영·추론·경고·유효 시간 누적을 중단한다. 명시적 재개와 장치·기준·배치 확인 후 같은 세션을 이어간다. |
| 기준 재등록·유효 설정 변경 | 기존 이탈을 변경 사유로 닫고 새 기준·설정 구간을 남긴다. 재등록 뒤 ‘탐지 재개’를 요구한다. |
| 종료 | 촬영·판정을 중단하고 미복귀 이벤트를 종료 사유로 닫는다. 카메라 종료와 저장 완료·실패를 따로 표시한다. |

자리 비움은 촬영 중 판정 보류이고 일시 정지는 촬영 자체의 중단이다. 이탈 6초 → 자리 비움 5초 → 새 이탈 4초에서는 경고가 없다. 새 이탈이 연속 10초가 될 때만 경고한다. 복귀 2초 → 인식 불가 → 복귀 1초도 정상 복귀가 아니다. 누락된 경고를 재개 뒤 몰아서 표시하지 않는다.

10초 전에 기준 범위로 돌아온 후보는 폐기한다. 확정 이탈 중 기준 범위로 돌아와도 3초를 채우기 전에 다시 벗어나면 같은 이탈 ID를 유지하고 복귀 타이머만 초기화한다. 기본 설정에서 연속 이탈 70초는 확정 이탈 1회·최초 경고 1회·재경고 1회이다.

## 4. 리포트와 저장

| 항목 | 정의 |
|---|---|
| V | 진행 중 필수 입력이 유효했던 구간의 합집합 시간이다. 준비·등록·자리 비움·인식 불가·정지·복구 대기·재등록 준비는 제외한다. |
| D | 확정 이탈 시작부터 복귀 확인 또는 중단까지를 유효 구간과 교집합한 합집합 시간이다. 확정 전 시작 구간과 복귀 확인 3초를 포함한다. 미확정 후보는 제외한다. |
| R | `D / V × 100(%)`이다. 각 리포트는 해당 구간 D/V, 전체 세션은 합산 D/합산 V로 계산한다. |
| 분석 없음 | V=0이면 비율은 null이고 ‘분석 가능한 기록이 없습니다’를 표시한다. 0%로 채우지 않는다. |

R은 지속 조건을 충족한 개인 기준 이탈의 시간 비율이다. 복귀 확인 시간도 포함한다는 의미를 리포트에 안내한다. 이탈 10초 → 복귀 3초의 명목 D는 13초이며 V에는 UI 조작 중 유효 시간도 포함한다. 항상 0≤D≤V이고, 원장·계산은 반올림 전 값을 사용한다.

### 구간 경계와 이벤트

- 유효 1800초마다 자동 리포트를 만든다. 종료 시 마지막 경계 뒤 남은 유효 구간만 종료 리포트로 만든다. 정확한 경계 종료에는 빈 종료 리포트를 추가하지 않는다.
- 유형 중첩·재경고·리포트 경계로 같은 이탈 ID를 늘리지 않는다. 신규 횟수는 시작 구간에, 경고는 실제 표시 구간에 귀속한다.
- 자동 구간은 시작을 포함하고 끝을 제외한다. 종료 구간은 종료 시점의 경고도 포함한다. 정확한 자동 경계에서 종료해 종료 구간이 없으면 경계 시점의 경고는 마지막 자동 리포트에 반영한다. 종료된 세션의 리포트별 경고 합계는 경고 원장과 같아야 하며, 누락·중복 방지에 필요한 마지막 집계 갱신을 허용한다.
- 경계에 미확정 후보가 있으면 리포트를 잠정 표시한다. 나중에 확정되면 시작 시각부터 시간을 나눠 같은 리포트 ID의 개정값과 세션 비율을 갱신한다. 후보가 끝나면 잠정 표시를 해제한다.
- onset=1795초, confirmed=1805초이면 첫 구간 D에 5초를 소급 반영하고 경고는 다음 구간에 남긴다. 이미 확인한 리포트의 개정 여부와 갱신 시점을 표시한다. 세션·구간·개정 식별자로 중복 저장을 방지한다.
- V=0 종료는 빈 분석 안내로 처리한다. 현재 엔진의 empty 종류 기록은 자동·종료 리포트와 구분한다.

가상 산술 C01~C06은 [검사 입력](../tools/fixtures/report-calculation.json)과 [엔진 테스트](../posture-web/src/core/engine.test.js)에 연결한다. 사람의 측정 데이터나 E2E 실행 증거가 아니다.

### 저장·비교·삭제

| 항목 | 규칙 |
|---|---|
| 저장 범위 | 기록·리포트·기준·설정은 같은 PC 사이트·브라우저 프로필에 저장한다. 다른 기기와 동기화하지 않으며 같은 브라우저를 쓰는 사람은 조회·삭제할 수 있다. |
| 기준·설정 | 기준 ID·특징·장치·촬영 조건·모델 버전과 설정 버전을 남긴다. 기존 기록을 새 기준으로 덮어쓰지 않는다. |
| 저장 단위 | 세션 ID별로 상태·유효/보류 구간·모드/기준/설정 구간·이탈/경고/복귀 원장·리포트를 함께 저장한다. 저장 완료는 실제 로컬 저장 성공 뒤 표시한다. |
| 새로고침 | 마지막 성공 저장본의 측정 범위까지만 복원하고 `lastSavedAt`에서 중단 종료로 처리한다. 이후 재접속까지의 시간은 V·D에서 제외하고 카메라·탐지는 꺼진 상태로 둔다. |
| 저장 실패 | ‘저장 실패’를 표시한다. 촬영 종료를 저장 성공으로 표시하지 않는다. |
| 비교 | 모드·지표·기준·설정·배치가 같은 기록만 정량 비교한다. 조건 차이는 ‘조건이 달라 비교할 수 없어요’, 자료 부족은 ‘비교할 기록이 부족해요’를 표시한다. |
| 삭제 | 종료된 세션 원장·리포트·파생 집계를 함께 제거한다. 현재 기준과 다른 세션의 참조 기준을 보존한다. 전체 삭제 확인에서 기준·설정 포함 여부를 구분한다. |

원본 영상·연속 원시 좌표는 보관하지 않는다. 영상은 각 기기에서 처리하고 딥 모드의 최소 특징·품질·시각만 승인된 보안 연결로 PC에 전달한다. 휴대폰·중계에는 개인 기록 이력을 남기지 않는다. 안내 문구는 실제 구현·검증한 처리 범위에 맞춘다.

저장 요청과 완료를 구분하고 미저장 구간은 복원 대상에서 제외한다. 브라우저 데이터 정리로 기록이 사라질 수 있음을 안내한다. 주기 저장 간격·유실 허용 범위·보관 기간은 미정이다.

## 5. 설정과 기준 변경

민감도·경고 시간·재경고 간격·소리를 설정한다(F5). 시간은 숫자 변환과 밀리초 환산 후에도 유한하고 안전한 양의 정수여야 한다. 0·소수·음수·빈 값·처리할 수 없는 큰 수는 ‘양의 정수를 입력해 주세요’로 거부하고 저장값·버전·측정 구간을 유지한다. 제품의 시간 설정 상한은 별도로 정한다.

유효 값이 실제로 바뀔 때만 새 버전·적용 시각을 남기고 기존 이탈을 닫는다. 같은 값 재적용은 오류 해제·화면 닫기만 수행한다. 변경 전 기록에 새 값을 소급 적용하지 않는다. 등록 5초·복귀 3초·자동 리포트 30분은 설정 화면에서 바꾸지 않는다. 입력 상한·민감도 경계는 미정이다.

재등록은 판정 보류와 새 기준 ID 생성이다(F1). 연속 안정 5초가 끝나도 ‘탐지 재개’ 전에는 자동 시작하지 않는다. 현재 구현과의 차이는 진행 기록에 둔다.

## 6. 딥 모드 연결과 복구

F8~F10은 다음 계약을 따른다.

1. QR 생성만으로 촬영하지 않는다. 휴대폰 연결 요청 뒤 PC 승인으로 연결한다.
2. 요청 수신·승인 시점 모두 만료를 검사한다. 120초 도달·사용·재발급으로 무효인 요청은 거부하고 새 휴대폰으로 자동 교체하지 않는다. QR 만료만으로 승인된 기존 연결을 끊지는 않는다.
3. 정면·측면 필수 입력이 함께 연속 안정 5초여야 등록한다. 유효하고 동기화된 두 입력만 결합하며 한쪽 무효이면 전체 판정·V 누적을 즉시 보류한다.
4. 연결 끊김 확인 시 연결 권한을 무효화하고 복구 대기로 전환한다. 유효 정면 기준·입력과 사용자의 ‘기본 모드로 계속’ 선택 뒤 같은 세션에 새 기본 구간을 만든다. 정면 무효이면 전환을 비활성화한다.
5. 전환 뒤 새 이탈은 새 10초를 요구한다. 장애·전환을 정상 복귀로 세지 않는다. 모드별 D·V·R을 나누고 전체 합산 비율을 모드 간 개선 효과로 쓰지 않는다.
6. 휴대폰 종료 요청과 실제 종료 확인을 구분한다. 무응답이면 ‘종료 요청·확인 안 됨’으로 남긴다.

측면 판정은 기준 대비 측면 각도(수평선과 어깨→귀 선)가 15° 이상 줄면 이탈로 보고, 양쪽 기준 등록 중 측면 각도가 8°를 넘게 흔들리면 다시 센다. 두 값은 [deep.js](../posture-web/src/core/deep.js)의 파일럿 값이다. 측면 입력의 시각은 중계 서버 시각으로 맞추고 PC 정면 입력 시각과 1초 이내일 때만 결합한다.

연결 감시·장애 판정·휴대폰 자체 중단 시간은 실기기로 확정한다. 코드의 heartbeat 2초·disconnect 6초·phoneStop 10초·측면 입력 최대 나이 1초는 파일럿 값이고 확정 정책이 아니다. QR 120초는 확정 기본값이다. 값은 [deep-protocol.js](../posture-web/shared/deep-protocol.js) 한 곳에 두고 서버와 브라우저가 함께 쓴다.

### 연결 프로토콜

PC와 휴대폰은 같은 사이트에서 연 페이지로 `/relay?role=pc` 또는 `/relay?role=phone` WebSocket에 접속한다. 다른 사이트의 페이지·다른 역할은 403으로 거부한다. 메시지는 `type`이 있는 JSON이며 2KB 이하, 초당 20개 이하이다. 초과하면 오류 후 연결을 닫는다. 서버는 접속 때 `hello`(serverTime·각 시간값)를, `ping`에 `pong`(serverTime)을 보낸다. 양쪽은 heartbeat마다 ping을 보낸다.

| 단계 | 보내는 쪽 → 메시지 | 서버 처리·결과 |
|---|---|---|
| QR 발급 | PC `qr.issue` | 144비트 무작위 토큰(24자)을 PC 연결에 묶어 `qr.issued`(token·issuedAt·expiresAt)로 준다. 이전 토큰과 대기 요청은 `reissued`로 무효화한다. 이미 연결된 PC는 발급할 수 없다. QR 주소는 `/phone?token=<token>`이다. |
| 연결 요청 | 휴대폰 `connect.request`(token) | 발급 후 120초 미만·미사용·PC 접속 중일 때만 대기로 받아 휴대폰에 `connect.pending`, PC에 `connect.requested`(requestId)를 보낸다. 대기 중인 토큰을 다른 휴대폰이 요청하면 `used`로 거부한다. |
| 승인·거절 | PC `connect.approve`·`connect.reject`(requestId) | 승인 시점에 만료를 다시 검사한다. 통과하면 토큰을 사용 처리하고 양쪽에 같은 `link.approved`(linkId)를 보낸다. 거절·만료된 토큰은 다시 쓸 수 없다. |
| 측면 입력 | 휴대폰 `side` | 승인된 연결에서만 받는다. seq(증가하는 정수)·t·valid·angleDeg(0~180, 무효면 null)·earVis·shoulderVis(0~1)를 검증하고 그 PC에만 `side`(+receivedAt)로 전달한다. 원본 영상·좌표는 받지 않는다. |
| 오래된 입력 | 서버 | 측정 시각이 2초보다 오래되면 전달하지 않고 PC에 `side.stale`, 휴대폰에 `stale_input` 오류를 보낸다. 1초보다 미래 시각이나 거꾸로 온 seq는 버린다. |
| 입력 갱신 중단 | 서버 | 측면 입력이 2초 넘게 없으면 PC에 `link.input-idle`을 한 번 보내고, 다시 오면 `link.input-resumed`를 보낸다. 연결은 유지한다. |
| 연결 유실 | 서버 | 6초 넘게 아무 메시지가 없거나 소켓이 닫히면 승인을 무효화한다. PC에는 `link.lost`(phone_timeout·phone_closed), 휴대폰에는 `link.revoked`(pc_timeout·pc_closed)를 보낸다. 다시 연결하려면 새 QR과 승인이 필요하다. |
| 촬영 종료 | PC `stop.request` → 휴대폰 `stop.done`(stopId) | 휴대폰에 `stop.request`를 전달하고 PC에 `stop.requested`(deadline)를 보낸다. 촬영 종료 뒤 같은 stopId로 답하면 PC에 `stop.confirmed`를 보낸다. 10초 안에 답이 없으면 `stop.unconfirmed`를 보내고 연결을 무효화한다. 확인 없이 완료로 처리하지 않는다. |

오류는 `error` 또는 `connect.rejected`(code·message)로 보낸다. 코드는 `bad_message`·`rate_limited`·`invalid_token`·`expired`·`used`·`reissued`·`pc_offline`·`already_linked`·`duplicate`·`rejected`·`no_request`·`not_approved`·`not_linked`·`stale_input`·`bad_side`이다. 요청 뒤 휴대폰이 새로고침하면 PC에 `connect.canceled`를 보내고 그 토큰은 다시 쓸 수 없다. PC가 새로고침하면 토큰·대기 요청·연결이 모두 무효가 된다.

시간 비교는 서버 시각을 기준으로 한다. 각 기기는 `hello`·`pong`의 serverTime으로 자기 시계와의 차이를 보정한다. 휴대폰은 측정 시각 t를 서버 시각으로 보낸다. PC는 정면 입력 시각(서버 시각 환산)과 측면 t의 차이가 1초 이하인 입력만 결합하고, 그보다 오래됐거나 `link.input-idle` 상태이면 측면 입력을 무효로 보고 판정을 보류한다. 기본 모드 전환은 `link.lost` 뒤 사용자의 선택으로 PC가 처리하며 서버는 관여하지 않는다.

## 7. 평가 재현 설계

공식 제출·실행 요건은 [README](../README.md#루프톤-제출-요건)를 따른다. 각 시나리오에 같은 ID의 spec과 test 하나를 두고, 첫 화면부터 실제 UI 조작으로 최종 값을 확인한다. 앞 흐름의 기록이나 팀의 Playwright 설정에만 있는 준비에 기대지 않으며, 각 흐름은 로컬에서 1분 안에 끝나야 한다.

녹화 입력·카메라 입력 교체·측면 모의 입력·첫 리포트 3초 가속은 팀의 시험 설계이다. 주최 측 허용 여부와 평가 빌드 실행 가능 여부는 확인 대상이다. 일반 사용자 기능과 시험 도구를 구분하고, 최종 기준·세션·승인 성공·리포트를 직접 주입하지 않는다. skip·route 계열·addInitScript 등 공식 금지 우회는 사용하지 않는다.

| 검증 | 확인할 결과 |
|---|---|
| 결정적 입력 단위 시험 | 등록 4/5초, 이탈 9/10초, 복귀 2/3초, 재경고 70/130초, 운영 리포트 1799/1800초, QR 120초와 종료 경고의 누락·중복을 확인한다. |
| 녹화 입력 E2E | 실제 추론·판정·집계·저장과 화면 결과를 확인한다. 영상 라벨·400ms 처리·최근 3개 샘플 평균·추론 지연을 고려해 시간 오차를 실측한다. 명목 D=13초를 영상 결과에 강제로 맞추지 않는다. |
| 실기기·운영 | 실제 카메라 권한·다른 앱 사용 중 경고·QR·휴대폰 연결·촬영 종료와 운영 주기를 확인한다. 모의 입력·3초 가속 결과와 구분한다. |

입력 파일·평가 빌드·테스트 도구의 상세 계약은 [E2E 입력 자료](../e2e/fixtures/README.md), 구현·실행·주최 측 확인 상태는 [진행 기록](../progress.md)에 모은다. 일반 빌드·평가 빌드·실기기·주최 측 실행의 통과 여부를 각각 기록한다.

다른 탭·IDE·인강 화면에서 경고 이벤트 생성 → 실제 전달 → 사용자 인지를 나눠 확인한다. 기존 화면 경고·소리의 전달 범위를 먼저 실측하고, 전달 방식의 추가·변경과 권한 거부 시 동작은 팀이 결정한다.

## 9. 구현 우선순위와 미정 사항

기본 경로(F1~F7·F12)의 등록·경고·복귀·종료·리포트·기록을 먼저 연결하고 딥 모드(F8~F10)를 이어 구현한다. 리포트 개정·설정 버전·비교 조건은 현재 집계 계약이며, 단순화를 위한 범위 변경은 기능 명세부터 반영한다.

| 순서 | 확정·검증할 사항 | 담당 |
|---|---|---|
| 우선 | 작업 중 경고 전달·인지, 감지 품질·민감도 경계, 제출 입력의 허용·재현 경로이다. | 팀·프론트엔드·QA |
| 딥 모드 연동 | 연결 메시지·승인·무효화·종료 확인은 6절을 따른다. 동기화 오차·장애 판정·휴대폰 자체 중단 시간은 실기기로 확정하고 공개 HTTPS의 WebSocket 실행 환경을 정한다. | 프론트엔드·백엔드 |
| 운영 세부값 | 저장 주기·유실 허용 범위·보관 기간·자동 만료·시간 설정 상한·표시 자릿수이다. | 팀·관련 구현 담당 |

실측값·파일럿·팀의 확정값을 구분한다. 결정 근거와 현재 미구현·실패·다음 행동은 진행 기록에서 관리한다.
