# PRD — 패스트거북이

2026-10-30 통합 설계본. 사용자 제공 보완자료와 이 채팅의 직접 경험을 반영했다. [problem.yaml](problem.yaml)이 문제·기능 계약, [scenarios.yaml](scenarios.yaml)이 사용자 흐름, [planning-policy.yaml](planning-policy.yaml)이 공통 기본값이다. 구현·배포·실제 검증 완료를 뜻하지 않는다.

## 1. 문제와 사용자

자세를 관리하려는 대학생은 노트북 과제·공부에 몰입할 때 자세 변화를 제때 알아차리기 어렵고, 고쳐 앉아도 다시 작업에 집중하면 같은 자세로 돌아오는 어려움을 겪는다(E2의 자기보고). 이러한 사용자에게 지속 변화 알림이 도움이 되는지와 작업을 방해하는지를 함께 검증한다.

초기 고객 조건은 자세를 관리하려는 의지가 있지만 노트북 작업에 몰입하면 확인을 놓치는 대학생이다. 현재 직접 자기보고가 있는 대상은 P1이다. 관리 도구 사용 경험과 추가 서비스 사용 의향은 아직 확인하지 않았으며, 기존 방법으로 충분한 사용자에게 추가 필요성을 가정하지 않는다.

E1은 학교 프로젝트에서 사용자가 친구의 자세를 보고 알려준 관찰이다. 최신 정정에 따라 과거의 관찰 주체·날짜·직접 인용을 철회한다. E2는 이 채팅에서 사용자가 직접 제공한 본인의 최근 일주일 경험이다. 두 기록을 같은 사건이나 독립된 두 사용자 표본으로 합치지 않는다.

E2의 최근 일주일 반복 빈도는 "자주"라는 정성적 회상이며 횟수·지속 시간·작업 중단·효율 영향은 미측정이다. 목·어깨 불편과 특정 자세의 인과는 확인하지 않았다. 관찰 시 작업 종류·기기 배치·자세 변화·인지/조정 시점·작업 중단·알림 방해를 기록하고, 무알림/시간 기반/변화 기반 조건을 비교한다. R1~R4의 집단 연구 결과를 개인의 측정값으로 바꾸지 않는다.

잠정 근본 문제는 작업 중 자세 확인과 작업 수행에 주의를 함께 써야 한다는 점이다. E2는 자세를 고쳐도 다시 집중하면 돌아오는 경험을 뒷받침한다. 인지 부족·화면 높이·글씨 크기·자세 유지의 불편 중 주원인은 미확인이다. 지속 알림이 충분한 해법이라는 결론은 아직 내리지 않는다.

## 2. 목적·대안·선택 이유

거북목 예방을 위한 자세 관리 습관을 돕는 것이 목적이다. 개인 등록 자세를 정상으로 인증하거나 질환 진단·치료·장기 예방 효과를 보장하지 않는다. 사용자가 실제로 자세를 확인·조정하는지와 공부를 방해하는지를 함께 평가한다.

- A1: 생각나거나 주변 사람이 알려줄 때 자세를 고쳐 앉는다(E2에서 확인). E2에서는 다시 작업에 집중하면 같은 자세로 돌아왔다. 원인은 미확인이다. 주변 사람이 없는 동안에도 지속 변화를 확인할 계기를 제공하려 한다. 반복 알림이 실제 조정에 도움이 되는지와 부담을 함께 검증한다.
- A2: 정해진 시간에 자세 확인·휴식을 알리는 타이머. 팀원의 실제 사용 여부는 미확인이다. 실제 자세 변화와 알림 시점이 맞지 않을 수 있다는 가설이다. 사용 만족도는 아직 모른다. 유효한 변화가 지속될 때 알리는 방식이 불필요한 경고를 줄이는지 시간 기반 조건과 비교한다. 우월성을 미리 확정하지 않는다.
- A3: 받침대·외부 입력장치 등으로 작업 환경을 조정한다. 실제 사용 경험은 미확인이다. 환경 조정 후에도 확인의 어려움이 남는지는 미확인이다. 이것만으로 충분하면 추가 서비스 필요성이 낮다. 환경 개선을 대체하지 않고, 개선 뒤에도 변화를 놓치는 사용자에게 확인 계기를 보완하는 가설이다.
- A4: 기준 등록·웹캠 분석·자세 알림을 제공하는 유사 접근(R5). 팀원의 사용 경험은 미확인이다. 기존 서비스의 정확도·사용 부담·중단 이유를 직접 비교하지 않았다. 기존 서비스에 결함이 있다고 단정하지 않는다. 기능 자체의 새로움 대신 학습 중 오경고·방해·반복 사용 가능성, 유형별 기록과 주기 리포트의 유용성을 비교 검증한다. 측면 추가의 정확도 향상도 별도 실험 대상이다.

## 3. 범위와 상태

- 기본: 안내 → 개인 기준 → 지속 변화 경고 → 기록 → 주기·종료 리포트 → 사용자 조정.
- 선택형 딥 모드: QR 승인 → 측면 배치·기준 → 정면·측면 통합 → 장애 복구. 이번 설계에 포함되지만 실제 지원 환경·동기화·공식 재현은 미검증이다.
- 로그인 없는 PC 브라우저 기록과 랭킹 후속 정책을 반영한다. F11은 번호를 재사용하지 않고 후속 경로로 남긴다.
- 조건부 비교·보관·시간값은 보완자료의 파일럿 설계안이다. 별도의 사용자 승인 이력이나 성능 검증으로 기록하지 않는다.
- 기본 플랫폼은 desktop이다. 휴대폰 보조 화면의 다중 기기 재현은 platform 값만으로 제공되지 않는다.

## 6. 공통 시간과 경고

| 항목 | 파일럿 값 |
|---|---|
| 안정 등록 | 5초 |
| 지속 이탈 경고 | 10초 |
| 복귀 확인 | 3초 |
| 같은 이탈 재경고 | 최초 경고 이후 60초 간격 |
| 자동 리포트 | 유효 입력 누적 1800초(30분) |
| QR | 120초·1회용 |
| 연결 신호/장애/폰 자체 중단 | 2초/6초/10초 |
| 로컬 보관 상한 | 종료 또는 중단 세션 마지막 저장 유효 시각부터 30일; 접속·조회 시 정리 |

값의 기준은 planning-policy.yaml이다. 사용자 경고 시간 1~300초, 재경고 간격 10~600초는 이번 통합의 입력 검증 설계안이다. 소수·범위 밖 입력은 저장하지 않는다. 민감도 3단계의 실제 판정 경계·동기화 허용 오차·촬영 범위는 실측으로 정한다.

공통 경고는 **기준 자세에서 벗어난 상태가 지속되고 있습니다. 자세를 확인해 주세요.** 이다. 유형 판별이 실제로 검증된 뒤에만 구체적인 확인 문구를 사용한다. 정면 어깨 기울기를 둥근어깨로 확정하거나 특정 교정 동작을 강요하지 않는다. 유형은 불명확하지만 신뢰 가능한 변화가 있으면 공통 문구, 입력 품질 자체가 낮으면 판정 보류다.

## 7. 상태·판정·데이터

세션(준비/진행/사용자 정지/복구 대기/종료), 인식(유효/자리 비움/인식 불가), 모드(기본/딥), 연결(대기/연결/끊김/해제), 저장(저장 중/완료/실패)을 분리한다.

유효 입력에서만 연속 시간을 센다. 후보는 onset, 지속 조건 충족은 confirmed, 복귀 조건 충족은 종료 시각으로 기록한다. 복귀 확인 3초는 확정 이탈 끝까지 포함한다. 지속 조건 전에 돌아온 후보는 확정 이탈·경고로 집계하지 않는다. 가림·정지·기준/설정/모드 변경·종료는 중단 사유이며 정상 복귀와 구분한다.

기준·설정은 불변 버전으로 저장한다. 설정 적용 시 진행 이탈을 닫고 새 구간을 시작한다. 딥 모드는 시각·품질이 맞는 두 입력만 결합하며 불일치 시 전체 판정을 보류한다. 같은 에피소드의 유형 변경이나 재경고가 새 이탈 ID를 만들지 않는다.

원본 영상은 각 기기에서 처리하고 저장·전송하지 않는 구조가 목표다. 휴대폰 최소 특징·품질·측정 시각은 인증된 보안 연결로 PC에 전달한다. 따라서 딥 모드에서 모든 특징이 기기를 떠나지 않는다고 쓰지 않는다. 중계는 영상·특징·리포트 이력을 영구 저장하지 않는 안이다. 실제 네트워크·로그 검사가 필요하다.

기록·리포트·기준·설정은 같은 PC 브라우저에 저장하는 안이다. 공유 PC 타인 접근 보호와 기기간 동기화는 제공하지 않는다. 브라우저 삭제·정리에 따른 조기 소실과 저장 실패를 안내한다. 진행 중 주기 저장하며 새로고침 후 마지막 저장 구간만 복원하고 카메라는 자동 시작하지 않는다.

## 8. 집계·삭제 계약

[report-contract.md](report-contract.md)의 유효 구간·합집합·경계 개정 규칙을 따른다. 신규 횟수는 onset 구간, 실제 경고 횟수는 경고 발생 구간에 각각 귀속한다. 유효 시간 0은 비율 계산 불가다. 정확한 1800초 경계에서 종료하면 자동 리포트 하나만 남긴다.

같은 모드·지표·기준·설정·배치 유효성일 때만 비교한다. 조건이 다르면 비교 불가를 표시하며 재등록을 피하도록 유도하지 않는다. 삭제는 원장·리포트·파생 집계에 함께 적용하고 다른 세션이 참조하는 기준은 보존한다. 전체 삭제에 기준·설정을 포함할지 확인 화면에서 명시한다.

## 9. 성공 기준과 남은 검증

- 문제: 실제 대안 사용·반복 빈도·불편·사용 의향을 확인한다. 경험이 없는 숫자와 발화는 만들지 않는다.
- 감지: 사람·세션을 분리해 독립 참조와 비교하고 이벤트 정밀도·놓침·시간당 오경고를 기록한다. 단순 움직임과 지속 변화를 구분한다.
- 가치: 무알림/시간 기반/변화 기반을 같은 작업 조건에서 순서를 바꿔 비교한다. 자세 조정·알림 무시·작업 방해·재사용 의향을 함께 본다. 합격 수치는 실험 전 정하며 현재 성과로 적지 않는다.
- 기능: F1~F10·F12 완료 조건과 S1~S8을 실제 입력으로 확인한다. 종료 리포트 성공을 30분 자동 생성 성공으로 대신하지 않는다.
- 실행: 카메라 자동 입력·다중 기기·30분 시험은 운영진 확인 대기다. 지원 브라우저의 탭 전환·잠금·기기 종료를 실제 시험한다.
- 제출: 기본 브랜치 문서 push와 앱 실행·CI·배포·대시보드 반영은 서로 다른 상태로 보고한다. 병행 개발된 초기 코드가 posture-web/에 합쳐졌으며 이 통합 설계 전체의 구현 완료를 뜻하지 않는다. 확인한 차이는 implementation-status.md에 기록한다.

구체적인 재현 제약과 닫힘 조건은 [validation-plan.md](validation-plan.md)에 기록한다.
