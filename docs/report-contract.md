# 리포트·기준·삭제 계약

2026-10-30 사용자 지정 정책을 반영한 기획 계약이다. 시간값·용어의 기준은 [planning-policy.yaml](planning-policy.yaml)이다. 구현·제품 효과 검증 결과가 아니다. 복귀 확인 3초는 이탈 종료 확인 시각까지 포함한다. 동일 에피소드의 유형 중첩은 한 이벤트로 관리하며 유형별 시간을 합산해 전체 이탈 시간으로 쓰지 않는다.

## 1. 리포트 집계 계약

### 시간과 이벤트

| 항목 | 규칙 |
|---|---|
| 유효 구간 | 실제 입력이 유효했던 반열린 구간 [시작, 끝)의 합집합이다. |
| 전체 이탈 시간 | 유형별 이탈을 유효 구간과 교집합한 뒤 합집합한다. |
| 유형별 합계 | 유형이 겹치면 전체 이탈 합집합보다 클 수 있다. |
| 후보·확정 | onset_at은 처음 이탈한 시각, confirmed_at은 지속 조건 충족 시각이다. |
| 복귀 | 기준 범위의 연속 유효 입력 3초가 확인된 경우에만 normal_return으로 기록한다. 자리 비움·인식 불가·정지는 복귀가 아니다. |
| 자리 비움 | 판정 보류로 전환해 후보를 폐기하고 확정 이탈은 자리 비움 사유로 닫는다. 이탈·복귀·재경고 연속 타이머를 모두 0으로 만든다. |
| 보류 기록 | 확정 이탈 유무와 별개로 세션의 보류 구간·사유를 남긴다. 후보 폐기를 확정 이탈 횟수로 세지 않는다. |
| 입력 복원 | 기준·배치가 유효하면 새 연속 구간을 시작한다. 이전 누적 유효 시간은 유지하되 중단 전후 이탈을 같은 이벤트로 잇지 않는다. |
| 리포트 구간 | 경과 30분이 아니라 유효 입력 누적 30분마다 경계를 만든다. |
| 이탈 횟수 | 확정 이벤트가 시작된 구간에 한 번만 귀속한다. 후속 구간은 이어진 이벤트로 표시한다. |

### 경계에서 아직 확정되지 않은 후보의 처리

유효 시각 1795초에 이탈이 시작되고 1805초에 10초 지속을 충족하면, 1800초 시점에는 후보가 확정되지 않았다. 현재 기획에서는 다음 규칙을 적용한다.

1. 1800초에 동일 구간 리포트 v1을 만들고 지속 조건을 충족하기 전의 이탈 후보가 있으면 ‘일부 자세 구간 확인 중’으로 표시한다.
2. 이후 유효 입력에서 후보가 확정되면 동일 이벤트의 시작 시각은 1795초로 유지한다. 이전 구간에 5초, 다음 구간에 5초를 배분한다.
3. 신규 이탈 횟수는 이전 구간에 한 번만 귀속하고 리포트 ID를 유지한 채 v2로 개정한다. 최초 경고는 실제 발생 시각인 1805초 구간에 남는다.
4. 후보가 기준 미달로 끝나면 확정 이탈로 집계하지 않고 잠정 표시를 해제한다. 신호가 끊기면 중단으로 닫고 나중에 이어 붙이지 않는다.
5. 사용자가 이미 확인한 리포트는 ‘일부 구간 갱신’과 갱신 시점을 표시한다. 이전 값을 확정값으로 내보내지 않는다.

리포트 생성과 저장은 (session_id, window_id, revision)의 고유 식별자로 중복을 방지한다. 문서상 집계 규칙이며 실제 앱에서의 생성·저장·개정은 검증 전이다.

## 2. 기준·삭제·카메라 상태 계약

| 항목 | 기획 계약 |
|---|---|
| 기준 스냅샷 | 특징·촬영 조건·모델 버전을 포함한 불변 기준과 ID를 저장한다. 자동으로 과거 기준을 덮어쓰지 않는다. |
| 설정 스냅샷 | 유효 시작 시점이 있는 설정 버전을 남긴다. 설정 변경 직전·직후 구간을 분리한다. |
| 비교 적합성 | 같은 ID만으로 충분하지 않다. 카메라·배치 유효성까지 확인한다. 이동 여부를 알 수 없으면 정량 개선을 보장하지 않는다. |
| 공유 기준 삭제 | 세션 삭제로 다른 세션이 참조하는 기준을 무조건 지우지 않는다. 참조가 없고 현재 등록 기준도 아닐 때 정리한다. |
| 개인 기록 삭제 | 세션 원장·리포트·파생 집계를 같은 범위로 제거한다. 진행 중 자동 저장과 경쟁하지 않게 세션 종료를 선행한다. |
| 연결 장애 | 판정 보류와 연결 권한 무효화가 필요하다. 폰 카메라 종료 확인과 다르며 장애 판정 대기 시간은 실제 기기 시험 후 확정한다. |
| 휴대폰 자체 중단 | 연결 유실 시 촬영 중단을 시도하는 설계이다. 자체 중단 시간은 실제 기기 시험으로 확정하며 절전·잠금·스케줄 지연에서 실제 동작을 검증해야 한다. |
| 휴대폰 표시 | ‘연결 끊김·종료 요청·종료 확인’을 구분한다. 확인되지 않은 폰 종료를 완료로 표시하지 않는다. |


가상 산술 원본은 references/2026-10-30/report-calculation.source.json이다. tools/check-planning.mjs는 입력 구간에서 기대값을 독립 재계산한다. 실제 앱의 이벤트 생성·자동 리포트·저장을 시험한 것은 아니다.

## 3. 연속 시간과 저장 범위

- 이탈 6초 → 자리 비움 5초 → 이탈 4초에서는 최초 경고가 0회이다. 6초와 4초를 합치지 않는다. 돌아온 뒤 이탈이 연속 10초가 되면 새 후보에서 최초 경고 1회가 발생한다.
- 경고 중 자리 비움은 경고 표시를 중단하고 해당 확정 이탈을 중단 사유로 닫는다. 정상 복귀 수는 증가하지 않는다. 돌아온 뒤 새로 10초 이탈해야 새 최초 경고가 발생한다.
- 복귀 확인 2초 → 인식 불가 → 복귀 1초도 정상 복귀 1회가 아니다. 인식 중단으로 이전 확정 이탈을 닫았으므로 새 구간의 기준 범위 입력을 과거 이벤트의 복귀로 처리하지 않는다.
- 재경고는 최초 경고 이후 같은 확정 이탈의 연속 유효 60초마다 발생한다. 중단이 생기면 이전 경고 시계는 폐기하며 재개 시 누락 경고를 몰아서 만들지 않는다.
- 자리 비움에서는 카메라를 자동 종료하는 것으로 정의하지 않는다. 사용자 일시 정지는 촬영·추론을 중단하고, 자리 비움은 촬영 중 입력 상태에 따라 판정을 보류하는 차이가 있다.
- 기록·리포트·기준·설정은 로그인 없이 같은 PC의 같은 사이트·브라우저 프로필에 저장한다. IndexedDB 또는 localStorage는 구현 수단이며 같은 저장 범위·삭제·실패 계약을 따른다. 클라우드·계정·다른 브라우저의 기록을 복원 수단으로 전제하지 않는다.
- 보관 기간·만료 정리 시점은 구현 전 확정한다. 과거 보관 기간 제안은 archive/planning-history/에 보존하며 현재 자동 삭제·영구 보관을 약속하지 않는다. 브라우저 정리로 기록이 소실될 수 있음을 안내한다.

## 4. 성공 지표 계약 — 자세 이탈 비율

주 성공 지표는 **R = D / V × 100(%)**이다. V는 전체 세션 유효 시간, D는 확정 이탈의 유효 시간 합집합이다. 지속 조건을 충족하기 전의 이탈 후보는 D에서 제외하지만 해당 입력이 유효했다면 V에는 포함한다. 확정되면 이탈 시작 시각부터 집계하고 복귀 확인 3초까지 포함한다. 이는 지속 조건을 충족한 이탈의 비율이며 모든 자세 이상 시간이나 의학적 위험도가 아니다.

| 계산·비교 조건 | 계약 |
|---|---|
| D와 V | 항상 0≤D≤V이다. 준비·등록·자리 비움·인식 불가·정지·복구 대기·재등록 준비는 둘 다에서 제외한다. |
| 구간 합산 | 여러 자동·종료 리포트는 합산 D / 합산 V × 100으로 계산한다. 비율을 단순 평균하지 않는다. |
| 반올림 | 원장과 계산은 반올림 전 값을 사용하고 화면 표시만 반올림한다. 표시 자릿수는 구현 시 확정한다. |
| 경계 개정 | 늦은 확정으로 D가 바뀌면 해당 구간 R과 전체 세션 R을 같은 원장 기준으로 갱신한다. |
| 혼합 모드 | 딥→기본 전환은 모드별 D·V·R을 분리한다. 세션 전체 R은 기술 통계이며 모드 간 개선 효과로 비교하지 않는다. |
| 비교 조건 | 같은 사용자·작업 조건·모드·지표·기준·설정·배치에서만 R 차이를 %p로 기록한다. 제품이 자동 확인할 수 없는 작업 조건은 별도 실험에서 통제한다. |
| 데이터 부족 | V=0은 계산 불가이다. 유효 시간이 부족하거나 조건·보류 비중이 달라 해석할 수 없으면 성공 판단을 유보한다. |
| 효과 판단 | 경고가 많거나 R만 낮다는 이유로 인지 향상·건강 개선을 확정하지 않는다. 인지 보고·감지 품질·작업 방해를 별도 검증한다. |

아래는 명세 검증용 가상 산술이며 실제 사용자 성과가 아니다.

| 예시 | 입력 | 기대값 |
|---|---|---|
| S2·S5 경고와 복귀 | 연속 이탈 10초 뒤 기준 범위 3초 복귀, 나머지는 기준 범위 입력이다. | D=13초이다. 실제 세션 V가 20초이면 R=65%이며 V를 고정 13초라고 가정하지 않는다. |
| S4 보류와 후보 | 이탈 6초 → 자리 비움 5초 → 새 이탈 10초 → 복귀 3초이다. | 해당 유지 구간만 보면 V=19초·D=13초·R=13/19×100≈68.421%이다. 첫 6초 후보는 V에만 포함한다. UI 조작 중 추가 유효 시간은 실제 V에 더한다. |
| 합산 가중치 | 구간 A는 D=10초·V=100초, B는 D=90초·V=300초이다. | 세션 R=100/400×100=25%이다. 구간 비율 10%·30%의 단순 평균 20%를 사용하지 않는다. |
| 조건 비교 | 같은 조건에서 비교 R=40%, 알림 R=30%라는 가상 값이다. | ΔR=-10%p이다. 실제 달성이나 목표 감소폭 10%p를 뜻하지 않는다. |
