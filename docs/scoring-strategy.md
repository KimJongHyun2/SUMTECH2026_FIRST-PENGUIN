# 기획 평가 대응 메모

현재 기준은 2026-10-30 사용자 전달 **14.6점**이며 최우선 목표는 **20점대 이상**이다. 과거 13.5점 기록은 이전 상태로만 남긴다. 기존 기록상 기획은 30점 만점이며 problem.yaml·scenarios.yaml 중심 평가이다. 이번 스타터킷에는 세부 배점표가 없고 실제 감점 이유·채점 대상 버전·재채점 결과는 확인하지 못했다.

## 이번 문서에서 정리한 사항

| 평가 관점 | 반영 내용 | 확인 위치 |
|---|---|---|
| 문제와 근거의 연결 | E1 관찰·E2 자기보고·R1~R9 문헌·가설을 구분하고 근본 원인·손실의 미확인 범위를 표시한다. | problem.yaml의 canvas·experiences·insight이다. |
| 대안과 선택 이유 | 실제 사용이 확인된 방법과 비교 후보를 구분하고 같은 자세 확인 목표로 why_ours를 연결한다. | canvas.alternatives이다. |
| 정책 일관성 | 등록 5초·최초 경고 10초·복귀 3초·재경고 60초·자동 리포트 유효 30분을 통일한다. | planning-policy.yaml이다. |
| 상태·데이터 흐름 | 자리 비움은 판정 보류·연속 타이머 초기화, 기록은 로그인 없는 같은 PC 브라우저 로컬 저장으로 정리한다. | F2~F4·F12, PRD의 상태·저장 계약이다. |
| 관찰 가능한 완료 조건 | 기능마다 input·output·done을 쓰고 경고/복귀 횟수·리포트 수·저장/삭제 결과를 명시한다. | problem.yaml의 features이다. |
| 독립 사용자 흐름 | 각 흐름에서 기준·기록·연결을 준비하고 앞 흐름 결과에 의존하지 않는다. | scenarios.yaml의 S1~S8이다. |
| 주최측 양식 | 문제정의 키, 8개 흐름, 단계 1~12개, 제목 1~120자, 기대 결과 1~500자를 검사한다. | 스타터 예시 대조와 progress.md의 검사 기록이다. |
| 검증의 정직성 | 30분 자동 리포트와 1분 실행 요건, 카메라·다중 기기 재현 미확인을 드러낸다. | validation-plan.md이다. |

문서의 정합성과 형식 개선은 완료 조건이며 점수 상승 보장은 아니다. “다섯 빈칸 때문에 13.5점”, “네 칸이 점수를 결정”, “PRD는 점수에서 제외” 같은 과거 단정은 현재 근거로 사용하지 않는다. 자가 검사 16/16은 빈칸·구조 확인이며 품질 점수가 아니다.

실제 평가에 반영하려면 최종 문서가 등록 저장소의 기본 브랜치에 반영되어야 한다. 로컬 수정·문서 검사·기본 브랜치 반영·대시보드 재채점은 별도 상태이다. 재채점 전에는 20점대 달성으로 기록하지 않는다. 추가로 필요한 실제 대안 사용 경험·반복 빈도·손실·사용 의향은 새 인터뷰·관찰 없이 만들어 넣지 않는다.
