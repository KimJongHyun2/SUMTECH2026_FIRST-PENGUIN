# 기획 평가 대응 기준

기획 점수는 사용자 전달 기준 **14.6/30**, 목표는 **20점대 상위권**이다. 문서 구조 검사와 실제 기획 점수는 별도로 확인한다.

| 연결 | 문서 근거 | 평가·검증 기준 |
|---|---|---|
| 대상·장면 → 문제 | E1 새벽 캡스톤 회의실, E2 기숙사 밤샘 과제, E3 도서관 3시간 인강이다. | 행동·발화·감정을 원문에 연결한다. |
| 문제 → 원인 | 팀이 제시한 five_whys 5단계이다. | 작업 몰입 중 자세 미인지를 핵심 문제로 설명한다. |
| 원인 → 선택 이유 | IT융합학과 4학년 당사자 팀의 why_ours이다. | 팀의 생활 맥락과 탐지→경고→리포트의 연결을 설명한다. |
| 문제 → 규모 | R1의 조사 환경, R10의 건강 맥락, R11의 과거 문제 규모이다. | 출처·연도·대상과 현재 규모를 구분한다. |
| 해법 → 성과 | 자세 이탈 비율과 인지 지연이다. | 같은 조건에서 감지 품질·작업 방해와 함께 평가한다. |
| 효과 → 리스크 | PRD 10절의 R3·R4와 R2의 작업 부담이다. | 경고 증가나 보류 시간 증가를 성과로 세지 않는다. |
| 기능 → 실행 | 기존 F1~F10·F12와 S1~S8이다. | 입력·결과·완료 조건과 선택 경로 완주를 연결한다. |

P0는 형식·독립성·재현 위험, P1은 논리·지표·근거·일관성에 대한 내부 우선순위이다. 공식 세부 배점표로 사용하지 않는다. 문서 자가 검사 16/16은 블록 구조 충족 결과이며 점수 보장이 아니다.

S3의 테스트 3초 가속, S5·S6의 측면 데이터·장애 주입, 운영 환경 비활성화를 유지한다. 실제 효과·기기·E2E·실행 시간·주최측 테스트 예외 수용과 대시보드 재평가는 각각 확인한다. 검증 기준은 [PRD](prd.md#10-리스크-및-검증-계획)와 [검증 계획](validation-plan.md)을 따른다.
