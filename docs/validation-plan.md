# 검증 계획과 미해결 조건

현재는 기획 문서 통합 단계다. 병행 개발된 초기 코드는 posture-web/에 있지만 이번 작업에서 앱·카메라·기기·E2E·CI·배포는 실행하지 않았다. 문서 검사로 아래 외부 제약이 해결됐다고 표시하지 않는다.

| 흐름 | 필요한 입력·시험 | 현재 상태 |
|---|---|---|
| S1 | 카메라 권한·안정 영상·새로고침 | 공식 입력 경로 확인 대기 |
| S2 | 안정→10초 이탈→3초 복귀, 60초 전 종료 | 영상·판정값 검증 대기 |
| S3 | 유효 1800초 실시간과 후속 구간 | 1분 목표 공식 실행과 충돌; 운영진 확인 대기 |
| S4 | 실제 카메라 정지·재개·종료 | 기기 시험 대기 |
| S5 | PC·휴대폰·HTTPS·동기화·실제 통합 | 다중 기기 재현 확인 대기 |
| S6 | 독립 연결 후 실제 통신 중단 | 동일; 종료 요청/확인 구분 시험 대기 |
| S7 | 동일 흐름의 실제 생성·조회·삭제 | 로컬 저장 구현 대기 |
| S8 | 설정 적용·재등록·새 구간 | 버전·비교 조건 구현 대기 |

모든 흐름은 새 브라우저 기록에서 독립적으로 준비한다. 한 줄의 등록 동작 중 안정 대기는 시스템 처리 완료 조건이며, 실제 spec은 버튼·권한·관찰 단계를 누락 없이 풀어쓴다. 현재 흐름에 대응하는 공식 E2E를 실행하지 않았으므로 문서는 실행 완료 증거가 아니다.

실패 시험: 권한 거부, 장치 없음, 안정 등록 중 가림, 자리 비움, 10초 전 복귀, 60초 재경고, 정상 복귀와 중단 구분, 설정 범위 오류, 저장 실패·새로고침, QR 만료·재사용·중복 폰, 연결 종료 미확인, 기록 만료·공유 기준 삭제, 비교 조건 불일치.

카메라 fixtures를 실제 추론으로 처리하는 경로는 운영진 허용 확인 전 채택 완료라고 쓰지 않는다. 상태를 강제 생성하거나 시간을 속여 성공을 만들지 않는다. 30분 주기와 종료 부분 리포트는 별도 시험한다. 주기 축소가 허용되더라도 설정·실제 경과를 공개하고 기본 1800초의 실시간 시험을 별도로 남긴다.

주최 측 확인 항목: 카메라 권한/입력, 두 context/기기와 HTTPS 주소, 자동 주기의 짧은 재현 방법, 별도 평가표. 외부 문의를 전송하지 않았다.

스타터 실행 요건: 기본 브랜치 파일, Docker 빌드 10분·기동 2분, app 포트 3000, CPU 2·메모리 4GB, /__health와 실제 releaseId, 흐름마다 spec/test 하나, 독립 입력, 금지된 mock/skip 없이 실제 실행. 구체 규정은 제공 스타터를 따른다. desktop은 두 기기 제공을 뜻하지 않는다.

정밀도·재현율·시간당 오경고·작업 방해·재사용 의향을 기록한다. 목표 허용치는 실험 전에 팀이 정하며, 측정 전에는 통과나 효과 입증을 주장하지 않는다.
