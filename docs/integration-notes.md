## 0단계: 현재 파일과 과거 자료 분리

- problem.draft.yaml·scenarios.draft.yaml이라는 실제 파일은 없으므로 삭제했다고 기록하지 않는다.
- 초기 실험 HTML 4개·전용 스크립트·분석·기술검증 문서·예전 README를 archive/posture-experiments/로 이동했다.
- 메인 화면이 사용하는 공통 모듈은 유지했고 아카이브에는 동일 바이트의 실험 당시 스냅샷만 복사했다.
- 과거 기획 보완자료·초안·PRD 검토·구현 대조·통합 기록은 archive/planning-history/로 이동했다. 원문 내용은 보존했다.
- 현재 문서 검사에서 사용하는 가상 산술 JSON은 docs/references/에 유지했다.
- 이동한 실험 파일을 가리키던 메인 Vite 진입점·전용 개발 중계와 화면의 실험 링크만 정리했다. 감지·경고·저장 알고리즘은 변경하지 않았다.
- 실제 실험 data/·results/·사진/영상 데이터 폴더는 발견하지 못했다. 존재하지 않는 파일을 새로 만들지 않았다.

보관 범위와 과거 기록은 [archive/README.md](../archive/README.md)를 따른다. 후속 단계의 분석·수정·검증 결과는 이 문서와 progress.md에 이어 기록한다.

## 1단계: 새 스타터킷 분석

요청 API의 POST 응답에서 받은 ZIP을 별도 임시 폴더에 풀고 START_HERE.md·문제정의/시나리오 예시·관련 단계 안내를 다시 읽었다. ZIP SHA-256은 304478e454c1fc7d0d68a01b90892af63715e4fcf0bbf3dc4cf08fb7f4c7c61e이다. 앞 작업에서 받은 ZIP과 동일한 내용이며 이번에도 새로 요청·다운로드했다.

주최측 양식은 문제정의의 지정 키와 시나리오 3~8개, 단계 1~12개, 제목 1~120자, expected 1~500자이다. account는 로그인 없는 흐름에서 생략한다. 공식 P0/P1 배점표는 없으며 기존 위험 문서의 P0/P1은 내부 우선순위이다. 예시의 P1은 페르소나 ID이다.

## 2단계: 현재 정책의 범위 단일화

- 서비스명은 패스트거북이, 인식 실패의 상태 표기는 인식 불가로 통일한다. 과거 서비스 UI의 명칭은 코드 구현 차이로 분리하고 문서에서 현재 이름으로 정리한다.
- 공통 시간은 안정 유효 등록 5초·최초 연속 유효 이탈 10초·연속 유효 복귀 3초·재경고 60초·누적 유효 감지 30분이다.
- 자리 비움·인식 불가는 판정 보류·경고/유효 시간 누적 중단·이탈/복귀/재경고 연속 타이머 초기화이다. 이전 누적 유효 시간은 보존하며 중단을 정상 복귀로 세지 않는다.
- 로그인 없이 같은 PC 사이트·브라우저 프로필에 로컬 저장한다. IndexedDB/localStorage는 구현 수단이며 클라우드 동기화·타 브라우저 복원·공유 PC 접근 보호를 약속하지 않는다.
- 보관 기간·QR 만료·연결 시간·설정 입력 상한은 기존 제안이므로 현재 확정 명세에서 제외하고 과거 정책 스냅샷에 보존한다. 관련 기능·실패 상태를 삭제한 것은 아니다.
- 30점 만점/현재 14.6점/목표 20점대 이상과 실제 재채점 미확인을 구분한다.

## 3단계: 최종 제출 문서 재작성

- problem.yaml은 스타터의 최상위·중첩 키로 전체 재작성했다. 기존 경험 사실·외부 출처 9개·기능 ID 11개를 보존했다.
- scenarios.yaml은 account 없는 독립 흐름 S1~S8로 전체 재작성했다. 각 흐름이 기준·QR·연결·세션·리포트를 자체 생성하고 최종 상태·횟수·삭제 결과를 확인한다.
- PRD는 사용자/문제/경로/다섯 시간값/중단/저장을 첫 표에 모으고 정책·상태 전이·화면·기능 연결·집계를 일치시켰다.
- S6의 과거 장애 판정 대기 숫자는 미채택 제안으로 분리했다. 연결 끊김 감지 후 복구 대기·기본 전환·경고/복귀 0회·미확인 폰 종료 상태를 명확히 했다.
- S8은 무효 0초 거부·기본 10초 적용·새 기준 ID·명시적 재개를 확인하며 오류 문구도 양의 정수 검증과 일치시켰다.
- 30분 자동 리포트와 흐름당 로컬 1분 요건 충돌, 실제 카메라·다중 기기 재현은 해결되지 않았으며 문서 통과나 점수 상승으로 기록하지 않는다.
