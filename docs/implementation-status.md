# 설계와 병행 구현의 대조

2026-10-30 기획 통합 도중 원격 main에 합쳐진 `fceb3e6`까지의 posture-web 코드를 읽어 확인한 범위이다. 실행 결과가 아니다. 이 코드를 보존해 기획 커밋을 rebase했다. 현재 docs/는 목표 계약, posture-web/은 별도 병행 초기 구현이며 둘의 완료 상태를 혼동하지 않는다.

| 항목 | 최신 설계 | 확인한 초기 코드 | 후속 작업 |
|---|---|---|---|
| 이름·안내 | 패스트거북이, 개인 기준 변화 확인 | README·app.js는 바른목과 거북목 문구 사용 | 제품명·문구 매핑 |
| 경고·복귀 | 파일럿 10초·3초 | posture.js의 createAlertTracker 기본 30초·5초, 숙임 90초 | 설정 계약을 반영하고 실제 시험 |
| 저장·리포트 | IndexedDB 구현안, 유효 1800초 구간·이벤트 원장 | report.js는 localStorage 하루/시간대 집계 | 데이터 모델·구간 집계 구현/마이그레이션 검토 |
| 측면 | 승인 연결·통합 경고·장애 복구 | README에 side/front 실험 도구·개발 서버 WebSocket 중계 설명 | 실험 도구 연결과 제품 딥 모드 완료를 구분 |
| 이미지 | 제품은 원본 저장·전송하지 않는 구조 목표 | 실험 도구 side.html에는 사진 저장 기능 설명 | 실험 자료 수집과 제품 개인정보 안내를 분리 |
| 테스트 | S1~S8 실제 사용자 흐름 | package.json에 vitest·Vite, README에 단위/분석 테스트 안내 | 기존 테스트를 공식 흐름 E2E로 간주하지 않음 |

이 차이는 이번 문서 변경에서 코드까지 수정·검증한 것으로 표시하지 않는다. 새 기획을 기준으로 구현 담당자가 후속 반영할 항목이다. 기존 데이터·실험 결과의 타당성은 이번 정적 확인만으로 판단하지 않았다.
