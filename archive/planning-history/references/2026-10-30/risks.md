# PRD 후속 보완용 취약점 목록

작성일은 2026.10.30이다. 스타터킷을 읽은 결과 배점표는 확인되지 않았다. 아래 P0/P1은 주최 측 점수가 아니라 작업상 위험 우선순위이다. 외부 문의·대시보드 등록·push·실행은 수행하지 않았다.

## P0: 실행·재현이 막히는 구멍

| 위험 | PRD에 추가할 결정·대응 | 닫힘 조건 |
|---|---|---|
| 자동 실행에서 카메라 입력이 없음 | 권한·가상 입력·장치 지원을 운영진에게 확인한다. 동의받은 fixtures를 실제 추론에 넣는 방안도 허용 확인 대상이다. | 승인된 입력으로 실제 기준 등록·경고를 재현한다. |
| QR과 측면 휴대폰을 동시에 재현할 수 없음 | 두 기기·context·접속 URL·HTTPS·중계 조건을 확인한다. both는 동시 기기 제공이 아니다. | 허용된 방법으로 실제 연결·특징 전달·해제를 증명한다. |
| 30분 자동 리포트와 짧은 E2E의 충돌 | 종료 부분 리포트와 자동 주기를 별도 시험한다. 시험용 짧은 주기를 쓸 경우 운영진 허용과 명시된 설정·실제 처리라는 조건을 먼저 갖춘다. | 주기 자동 생성은 실제 시간 경과로 확인한다. 시간 조작·가짜 결과를 성공으로 쓰지 않는다. |
| 로컬 기록의 독립 시나리오 실패 | 기록 조회·삭제 E2E가 같은 흐름에서 실제 짧은 세션을 생성하게 한다. | 새 브라우저·빈 앱에서 앞 흐름 없이 성립한다. |
| Compose·상태 경로 없음 | app·포트·환경변수·빈 DB·모델 준비·/__health·실제 releaseId를 설계한다. | 빌드 10분·기동 2분 조건과 지정 자원에서 실행한다. |
| spec 없이 CI가 성공 | 예시 --pass-with-no-tests와 실제 흐름 수행을 구분한다. | 제출한 모든 ID의 실제 테스트·결과가 있다. |
| 배포만 하고 기본 브랜치 미반영 | 등록 repo·bot 읽기·실제 push·버전을 확인한다. | 주최 측이 최종 파일과 구현을 읽을 수 있다. |

## P1: 제품·근거·데이터의 구멍

| 위험 | 보완할 내용 | 닫힘 조건 |
|---|---|---|
| 개인 기준이 처음부터 부적절함 | 공식 환경·자세 안내, 자가 확인, 측정 조건 확인을 분리한다. | 인식 성공을 정상 인증으로 표시하지 않고 기준 등록 실패 조건을 시험한다. |
| 정면 지표를 임상 CVA로 오해 | 측정 지점·대체 지표·경고 문구를 매핑한다. | C7 미측정 시 CVA·진단·임상 각도라고 표시하지 않는다. |
| 어깨 기울기만 보고 펴기 지시 | 검증된 유형에만 구체 문구를 쓰고 불확실하면 확인 안내를 쓴다. | 혼동 동작 자료에서 유형과 문구를 검토한다. |
| 예방 목적을 예방 효과 보장으로 바꿈 | 목적·행동 지표·장기 효과 검증을 구분한다. | 단기 E2E·리포트 변화를 장기 예방 입증이라고 쓰지 않는다. |
| 인식 불가가 정상으로 집계됨 | 유효 시간·중단 사유·복귀·모드 버전을 분리한다. | 장애·정지·모드 변경 시 시간이 틀리지 않는지 검증한다. |
| 리포트 중복·숫자 왜곡 | 시간 합집합, 경계를 넘는 이벤트 ID, 신규·이어진 이탈을 구분한다. | 구간 합계·전체 합계·경고 원장이 일치한다. |
| 공유 PC의 로컬 기록 노출 | 기기·브라우저 범위와 삭제·보관 안내를 제공한다. | 타인 접근 방지·영구 보관을 제공한다고 오인시키지 않는다. |
| 폰이 끊겨도 카메라가 남음 | 명령·ack·로컬 타임아웃·foreground 조건을 설계한다. | 끊김·잠금·앱 전환의 실제 카메라 종료를 확인한다. |
| 백그라운드에서 감지가 멎음 | 지원 범위를 실측하고 미지원 상태는 판정 중단·알림으로 처리한다. | 다른 탭·앱 사용 시 영상 갱신·경고 전달을 실제 시험한다. |
| 원본 영상 미전송 약속과 구현 불일치 | 기기별 추론·특징 전송·서버 로그·모델 CDN·원본 저장을 점검한다. | 네트워크·로그·저장소 검토에서 실제 정책과 일치한다. |
| 실제 팀원 경험 없음 | experiences에는 시점·장면·행동·영향·발화를 기록한다. | 실제 경험을 확보하고 sources와 분리한다. |
| 랭킹이 범위를 소모함 | 후속 범위 제안과 사용자 요구 보존을 명시한다. | 팀이 승인한 우선순위와 정당한 산식이 있다. |

## 다음 PRD 작업 순서

1. 운영진 카메라·다중 기기 재현 답변과 실제 평가표 유무를 확인한다.
2. User Flow의 로그인 없는 MVP·로컬 보관·주기·랭킹 후속 정책을 팀이 검토한다.
3. 실제 경험과 대안별 why_ours를 채운다.
4. 기능별 입력·결과·완료 조건과 User Flow·화면명을 연결한다.
5. 지원 환경·데이터 흐름·모델 배포·중계·오류 처리의 구현 계약을 작성한다.
6. 최종 3~8개 시나리오와 각각의 독립·실제 재현 경로를 정한다.
7. 앱 구현 뒤 빌드·기기 시험·실제 E2E·배포·대시보드를 검증한다.

이 목록은 다음 PRD 보완 작업의 입력이다. 현재 실제 위험이 해결됐다는 완료 보고서가 아니다. 계정·배포·영상 수집 등 외부 작업을 임의로 수행하지 않는다.
