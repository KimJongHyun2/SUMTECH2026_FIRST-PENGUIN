# User Flow 최종 설계안

작성일은 2026.10.30이다. 사용자가 요청한 정책과 시간값까지 구체화한 초안 v1.2이다. 사용자는 로그인 없는 PC 브라우저 기록과 랭킹 후속 범위를 채택했다. ‘최종’은 문서 논리 검토를 반영했다는 뜻이며 나머지 정책 승인·구현·기기 시험·대회 자동 테스트 완료를 의미하지 않는다.

## 1. 목적과 핵심 흐름

목적은 노트북 작업 중 거북목 예방을 위한 자세 관리 습관을 돕는 것이다. 예방은 제품 목표이며 이미 발생한 질환의 진단·치료와 구분한다. 장기적인 예방 효과가 입증됐다는 주장은 하지 않는다.

**바른 작업 자세 안내·기준 등록 → 일상 작업 → 지속 이탈 감지 → 유형별 경고 → 경고·이탈·복귀 기록 → 주기 리포트 자동 생성 → 결과 확인·환경·습관 개선 → 작업 지속**의 순서이다.

딥 모드는 ‘딥 모드 사용하기 → QR 연결 → 휴대폰 측면 거치 → 배치 확인·기준 등록 → 정면·측면 분석’의 선택 경로이다. 측면 정보가 추가되며 정확도 향상은 별도 비교 검증 대상이다.

## 2. 이번 문서에서 제안하는 운영 정책

| 항목 | 구체적인 초안 |
|---|---|
| 로그인 | 사용자 채택 정책이다. MVP는 로그인 없이 이용한다. 계정·클라우드 동기화는 후속 범위로 둔다. |
| 기록 소유·접근 | PC의 같은 사이트·브라우저 프로필에 저장한 기록만 조회한다. 공유 PC의 다른 이용자로부터 보호하는 계정 인증은 제공하지 않는다는 점을 안내한다. |
| 저장 | 이벤트·구간·리포트·설정·기준 버전을 PC IndexedDB에 저장하는 안이다. 원본 영상과 연속 원시 관절 좌표는 저장하지 않는다. |
| 보관 | 세션 종료 후 30일을 보관 상한으로 제안한다. 접속·조회 시 만료 기록을 정리한다. 브라우저가 닫혀 있을 때 정확한 만료 시각 삭제를 보장하지 않는다. 사이트 데이터 삭제·브라우저 정리에 따른 조기 소실을 안내한다. |
| 삭제 | 개별 세션과 전체 기록 삭제를 제공한다. 전체 기록 삭제는 기준·설정도 지우는지 확인 화면에서 구분한다. 진행 세션은 종료한 뒤 삭제한다. 삭제 성공 후 해당 기록 기반 기간 집계를 다시 계산한다. |
| 원본 영상 | 각 기기에서 실시간 처리하고 저장·외부 전송하지 않는 구현을 목표로 한다. 이 구조가 구현·확인되기 전 외부 공개 문구로 보장하지 않는다. |
| 딥 모드 데이터 | 휴대폰에서 산출한 최소 특징·상태·측정 시각만 인증된 연결로 전달한다. 전송 중 보안 연결을 사용하고 중계 서버에는 영상·특징·리포트 이력을 보관하지 않는 안이다. 연결 정보의 수명도 구현에서 관리한다. |
| 첫 화면 | ‘자세 등록하고 시작’, ‘딥 모드 사용하기’, ‘내 기록’을 제공하고 QR을 자동 생성한다. QR 생성은 카메라 시작과 별개이다. |
| 기본 사용 화면 | PC 웹을 주 화면, 휴대폰 웹을 측면 촬영 보조 화면으로 설계한다. 대회 platform 값은 두 기기 테스트 방식을 확인한 후 선택한다. |
| 일시 정지 | 양쪽 촬영·추론·경고를 중단한다. 연결 확인 신호만 유지할 수 있다. 재개 시 카메라·배치를 확인한다. |
| 딥 모드 장애 | 전체 판정을 일시 중단하고 ‘재연결’, ‘기본 모드로 계속’, ‘세션 종료’를 제공한다. 정면 입력·기준이 유효할 때만 기본 모드로 계속할 수 있다. |
| 실행 중 모드 변경 | 같은 세션을 유지하며 판정은 일시 중단한다. 연결·배치·기준 등록 준비 시간은 유효 감지 시간에서 제외한다. |
| 설정 변경 | ‘적용’ 시점부터 변경한다. 진행 중 이탈은 ‘설정 변경’으로 닫고 이후 새 설정 구간으로 판정한다. |
| 랭킹 | 사용자 채택에 따라 후속 범위로 둔다. 요구사항을 삭제한 것이 아니며 산식·공개·신뢰도·부정 사용 정책을 정한 뒤 구현한다. MVP에는 더미 순위를 넣지 않는다. |
| 기간별 비교 | MVP에는 같은 기기의 최근 기록과 비교를 포함하는 안이다. 동일 모드·지표·설정 조건만 비교하며 데이터가 부족하면 비교 불가로 표시한다. |

로그인 없는 PC 브라우저 기록과 랭킹 후속 범위는 사용자 채택 사항이다. 그 외 항목은 사용자의 ‘미정 항목까지 초안을 짜 달라’는 요청에 따른 제안이며 이미 팀이 결정한 사실로 기록하지 않는다. 리포트 경계의 잠정·개정, 기준 참조·삭제 규칙은 PRD_보완팩_노션용.md의 추가 계약을 함께 검토한다.

## 3. 시간·설정 기본값 초안

다음 값은 UI·동작 실험을 시작하기 위한 제품 설정값이다. 논문에서 확정된 의학적 기준이나 검증된 성능값이 아니다.

| 항목 | 제안값 | 적용 규칙 |
|---|---|---|
| 기준 등록 | 연속 안정된 유효 입력 5초 | 흔들림·인식 불가 시 수집 구간을 초기화하고 다시 등록한다. |
| 이탈 경고 | 연속 유효 이탈 10초 | 인식 중단 시 연속성을 끊는다. |
| 복귀 확인 | 연속 유효 복귀 3초 | 이탈 진입보다 완화된 복귀 경계를 사용하는 안이다. 실제 경계는 검증이 필요하다. |
| 재경고 | 같은 이탈에서 60초 간격 | 한 이탈을 여러 이탈로 세지 않는다. 동시에 여러 문구를 쏟아내지 않는다. |
| 자동 리포트 | 유효 감지 30분마다 | 정지·장애·가림 시간은 제외한다. 리포트 생성이 세션을 끝내지 않는다. |
| 종료 리포트 | 종료 시 즉시 | 30분 미만이어도 부분 리포트를 생성한다. |
| QR 유효 시간 | 발급 후 120초·1회용 | 만료·사용 QR은 거부한다. 새 QR 발급으로 이전 요청을 폐기한다. 숨겨진 페이지에서 무한 발급하지 않는다. |
| 연결 확인 | 2초 간격, 6초간 미수신 시 장애 | 처리 지연·브라우저 제약에 따라 조정할 파일럿 값이다. |
| 휴대폰 자체 중단 | PC 제어 신호 10초 미수신 | PC의 중단 명령을 받지 못해도 로컬 타임아웃으로 추론·촬영을 중단하도록 한다. 백그라운드·잠금 시 동작은 실제 시험이 필요하다. |
| 로컬 보관 상한 | 종료 후 30일 | 앱 실행·조회 시 만료 정리를 수행한다. |

민감도는 낮음·보통·높음으로 제안하되, 실제 각도·비율 경계값은 검증용 데이터로 정한다. 근거가 없는 값을 정상 자세의 기준으로 만들어 넣지 않는다.

중계의 연결 대기 정보는 QR의 120초 만료에 맞춰 제거한다. 연결 중 특징 메시지는 전달용 메모리에서만 처리하고 전달·실패 후 폐기하며 영구 로그로 남기지 않는다. 6초 연결 장애 판정 시 연결 권한을 무효화하고 재연결은 새 승인으로 처리한다. 세션의 개인 기록은 PC에만 남기는 안이다. 이 수명 관리는 아직 구현된 사실이 아니다.

## 4. 상태와 집계 원칙

| 상태 축 | 값 |
|---|---|
| 세션 | 준비 / 진행 / 사용자 정지 / 복구 대기 / 종료 |
| 인식 | 유효 / 자리 비움 / 인식 불가 |
| 모드 | 기본 / 딥 |
| 연결 | 대기 / 연결 / 끊김 / 해제 |
| 기록 저장 | 저장 중 / 저장 완료 / 저장 실패 |

정지·연결 끊김·인식 불가는 정상 복귀가 아니다. 이탈 종료 사유는 정상 복귀·인식 중단·사용자 정지·기준 변경·설정 변경·모드 변경·세션 종료로 구분한다. 기록에는 세션·이벤트 ID, 시간, 모드, 기준·설정 버전, 경고 유형·문구, 복귀·중단 사유를 남긴다.

## S1. 안내에 따라 기준 자세를 등록하고 기본 모드를 시작한다

| 순서 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | PC 웹에 접속한다. | 예방 목적·처리 방식·로컬 기록 범위를 안내하고 QR을 생성한다. |
| 2 | ‘자세 등록하고 시작’을 누른다. | 카메라 선택·미리보기 화면을 연다. |
| 3 | 카메라 권한을 허용하고 장치를 선택한다. | 실제 영상과 얼굴·어깨 인식 상태를 표시한다. |
| 4 | 머리 중립·어깨 이완·화면 배치·등과 발 지지 안내를 확인한다. | 보이지 않는 신체 부위는 자가 확인 항목으로 안내한다. |
| 5 | 촬영 위치를 맞춘 뒤 ‘기준 자세 등록’을 누른다. | 유효 입력 5초로 기준 특징을 등록한다. |
| 6 | 등록 결과를 확인하고 ‘탐지 시작’을 누른다. | 기준과 장치를 확인한 뒤 세션·유효 시간 누적을 시작한다. |

**완료 조건:** 실제 기준이 등록되고 진행 상태가 표시된다. 권한 거부·불안정 인식에서는 시작하지 않는다. 초기 인식 통과는 의학적 정상 인증이 아니다.

## S2. 일상 작업 중 자세별 경고를 받고 조정한다

| 순서 | 사용자 행동·상황 | 시스템 반응 |
|---|---|---|
| 1 | 공부·과제·작업을 한다. | 기준 대비 변화를 추적한다. |
| 2 | 유효한 이탈 상태가 10초 이어진다. | 유형에 맞는 경고를 표시하고 설정에 따라 소리를 재생한다. |
| 3 | 경고를 확인하고 편안한 자세로 조정한다. | 같은 이벤트에서 측정을 계속한다. |
| 4 | 복귀 상태가 3초 이어진다. | 경고를 해제하고 정상 복귀로 기록한다. |
| 5 | 작업을 계속한다. | 이탈 유형·시각·지속 시간·실제 경고 문구·반복 횟수·복귀 결과를 누적한다. |

| 감지 가능한 상태 | 경고 문구 초안 | 제한 |
|---|---|---|
| 얼굴 접근·머리와 어깨의 관계 변화 | ‘머리가 화면 쪽에 가까워졌어요. 편안한 위치로 돌아가 주세요.’ | 얼굴 크기만으로 머리만 전진했다고 확정하지 않는다. |
| 검증된 측면 머리 전방 변화 | ‘고개를 무리하지 않게 뒤로 조정해 주세요.’ | 해당 유형을 구분할 수 있을 때만 사용한다. |
| 어깨 높이·기울기 변화 | ‘어깨의 힘을 빼고 위치를 확인해 주세요.’ | 정면 어깨선만 보고 둥근어깨나 펴기 필요성을 단정하지 않는다. |
| 검증된 측면 어깨·상체 변화 | ‘어깨를 무리하지 않게 펴고 편안히 앉아 주세요.’ | 해당 움직임을 실제 측정할 수 있을 때만 사용한다. |
| 유형을 신뢰하기 어려운 변화 | ‘자세가 기준에서 달라졌어요. 자세와 화면 위치를 확인해 주세요.’ | 신뢰도가 부족하면 판정을 보류한다. |

**완료 조건:** 경고가 실제 감지 이벤트와 연결되고 복귀·중단을 구분한다. 표현의 구체성이 측정 능력을 넘어가지 않는다.

## S3. 자동 리포트를 확인하고 다음 작업을 개선한다

| 순서 | 사용자 행동·상황 | 시스템 반응 |
|---|---|---|
| 1 | 유효 감지 30분 동안 작업한다. | 해당 구간의 리포트를 자동 집계한다. |
| 2 | ‘리포트가 준비됐어요’ 알림을 확인한다. | 작업을 강제로 중단하지 않고 ‘리포트 보기’를 제공한다. |
| 3 | ‘리포트 보기’를 누른다. | 아래의 시간·유형·경고·복귀 결과를 표시한다. |
| 4 | 반복되는 변화를 확인하고 자세·화면·입력장치 배치를 조정한다. | 화면·카메라가 달라졌다면 재등록을 안내한다. |
| 5 | 작업을 이어간다. | 같은 세션의 다음 유효 30분 구간을 기록한다. |
| 6 | 이후 리포트를 확인한다. | 같은 조건의 이전 구간이 있을 때 변화량을 비교한다. |

| 리포트 항목 | 집계 정의 |
|---|---|
| 전체·유효 시간 | 경과 시간과 실제 판정 시간을 구분한다. |
| 이탈 시간·비율 | 여러 유형이 겹쳐도 시간은 합집합으로 한 번만 센다. 분모는 유효 시간이다. |
| 신규 이탈·이어진 이탈 | 해당 구간에서 새로 시작한 이벤트 수와 이전 구간에서 이어진 이벤트를 구분한다. |
| 경고 횟수·내역 | 실제 표시한 최초·재경고와 문구·발생 시각이다. |
| 유형별 요약 | 반복 유형·지속 시간·중단 사유이다. 유형별 중첩 합계가 전체 이탈 시간과 다를 수 있음을 표시한다. |
| 경고 후 복귀 | 유효한 입력으로 정상 복귀가 확인된 이벤트만 집계한다. 진행·중단 이벤트를 실패로 단정하지 않는다. |
| 이전 구간 비교 | 동일 모드·지표·기준·민감도 조건에서 이탈 비율 등을 비교한다. 조건 차이·자료 부족이면 비교 불가를 표시한다. |

리포트 경계를 넘는 이탈은 이벤트 ID를 유지하고 시간만 구간에 나누어 배분한다. 새 이탈·새 경고를 자동 생성하지 않는다. ‘거북목이 개선됐다’ 대신 ‘측정된 기준 이탈 비율이 달라졌다’고 표현한다. 자동 리포트는 세션 중간 결과이며 종료 시 남은 부분 구간도 따로 집계한다.

유효 감지 시간이 0이면 이탈 비율을 계산하지 않고 ‘분석 가능한 기록이 없습니다’를 표시한다. 복귀율을 제공할 경우에도 분모가 되는 완료 이벤트가 없으면 계산하지 않는다. 마지막 자동 리포트 이후 유효 시간이 있을 때만 종료 부분 리포트를 생성한다. 정확한 경계에서 종료했다고 같은 구간이나 빈 리포트를 중복 생성하지 않는다.

## S4. 일시 정지·재개·종료한다

| 순서 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | ‘일시 정지’를 누른다. | 촬영·추론·경고를 멈추고 현재 이탈을 사용자 정지 사유로 종료한다. |
| 2 | ‘재개’를 누른다. | 카메라를 연결하고 배치·기준 유효성을 확인한다. |
| 3 | 필요하면 ‘기준 다시 등록’을 수행한다. | 유효한 준비 후 판정을 재개한다. 정지·준비 시간은 제외한다. |
| 4 | ‘세션 종료’를 누른다. | 양쪽 탐지·촬영을 먼저 종료한다. |
| 5 | 결과 처리 상태를 확인한다. | 남은 부분 리포트를 생성하고 저장 결과를 표시한다. |
| 6 | ‘리포트 보기’를 누른다. | 저장·집계 상태와 실제 결과를 보여준다. |

기록은 진행 중 주기적으로 저장하는 설계로 하고 미저장 메모리와 영구 저장을 구분한다. 저장 실패 시 화면에서 실패·재시도를 표시한다. 메모리의 미저장 결과는 페이지 종료 시 소실될 수 있다고 안내한다. 새로고침 후 카메라를 자동 재시작하지 않고 저장된 구간만 ‘중단된 세션’으로 복원한다. 마지막 유효 시각 이후를 감지 시간으로 추정하지 않는다.

## S5. QR로 휴대폰 측면을 연결해 딥 모드를 이용한다

| 순서 | 기기 | 사용자 행동 | 시스템 반응 |
|---|---|---|---|
| 1 | PC | ‘딥 모드 사용하기’를 누른다. | 유효한 QR을 표시한다. 진행 중이라면 판정을 일시 중단한다. |
| 2 | 휴대폰 | QR을 스캔하고 연결 대상을 확인한다. | 연결 페이지를 연다. 이때 카메라는 자동으로 켜지지 않는다. |
| 3 | 휴대폰 | ‘연결 요청’을 누른다. | PC에 확인 정보를 표시한다. |
| 4 | PC | ‘연결 승인’을 누른다. | 같은 세션에 연결하고 QR을 만료시킨다. |
| 5 | 양쪽 | 각 카메라를 허용·선택한다. | 정면·측면 미리보기와 상태를 표시한다. |
| 6 | 휴대폰 | 옆에 고정하고 측면 가이드에 맞춘다. | 측면 방향·신체 가시성·안정성을 확인한다. |
| 7 | PC | ‘기준 자세 등록’을 누른다. | 정면·측면의 유효 입력으로 각 기준을 등록한다. |
| 8 | PC | ‘딥 모드 탐지 시작’을 누른다. | 동기화·입력 품질을 확인해 두 입력을 사용한다. |

한 입력이 오래되거나 시각 동기화 오차를 허용 범위 안으로 줄일 수 없으면 결합하지 않는다. 양쪽 입력에서 발생한 같은 이탈은 한 이벤트로 기록한다. C7을 정확히 찾지 못하는 대체 지표를 CVA로 표시하지 않는다. 화면 잠금·앱 전환 중 촬영이 유지된다고 보장하지 않는다.

## S6. 딥 모드 장애·모드 변경에서 복구한다

| 순서 | 상황·선택 | 시스템 반응 |
|---|---|---|
| 1 | 연결·동기화·측면 인식 문제가 발생한다. | 전체 판정을 보류하고 장애 종류를 표시한다. |
| 2 | ‘재연결’을 선택한다. | 연결·배치·기준을 다시 확인하고 사용자 확인 후 재개한다. |
| 3 | 또는 ‘기본 모드로 계속’을 선택한다. | 정면 기준이 유효할 때만 전환하고 휴대폰 카메라를 종료한다. |
| 4 | 또는 ‘세션 종료’를 선택한다. | 카메라 종료 후 남은 결과를 집계한다. |
| 5 | 아무것도 선택하지 않는다. | 복구 대기를 유지하고 유효 시간을 누적하지 않는다. |

중복 휴대폰 요청은 기존 연결을 자동 교체하지 않는다. 사용자가 교체를 승인하면 기존 연결의 권한과 QR을 폐기하고 촬영 종료를 요청한다. 폰이 명령을 못 받는 상황도 자체 타임아웃으로 중단하도록 설계한다. 휴대폰 이동을 모두 자동 검출할 수 있다고 약속하지 않는다.

## S7. 같은 기기의 기록을 조회·비교·삭제한다

| 순서 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | ‘내 기록’을 누른다. | 같은 브라우저 프로필의 보관 범위와 만료 정리 결과를 표시한다. |
| 2 | 기간·세션을 선택한다. | 실제 저장한 기록만 표시한다. |
| 3 | ‘이전 기록과 비교’를 누른다. | 동일 조건의 자료가 있을 때만 비교한다. |
| 4 | ‘기록 삭제’를 누른다. | 대상·기간·기준 및 설정 포함 여부를 확인한다. |
| 5 | ‘삭제 확인’을 누른다. | 성공 후 목록과 해당 기록 기반 집계를 갱신한다. 실패하면 완료 표시를 하지 않는다. |

다른 기기·브라우저의 기록은 연결하지 않는다. 사이트 데이터 삭제 시 기록이 사라질 수 있다. 로그인이 없으므로 같은 브라우저를 쓰는 다른 사람에게 기록을 숨기는 기능은 아니다. 서버 랭킹은 MVP 범위에 없으므로 삭제 시 서버 순위 갱신을 약속하지 않는다.

비정상 종료 세션은 마지막 저장된 유효 시각을 보관 만료 기준으로 사용한다. 정량 비교는 같은 기준을 재사용한 세션 또는 같은 세션의 동일 조건 구간에만 제공한다. 재등록으로 기준이 달라진 세션은 조건 차이를 표시하고 요약 조회만 제공한다. 기준 유효성이 의심되면 비교를 위해 재등록을 생략하지 않는다.

## S8. 경고 설정·기준을 변경한다

| 순서 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | ‘설정’을 연다. | 현재 민감도·간격·소리를 표시한다. |
| 2 | 값을 변경하고 ‘적용’을 누른다. | 유효한 값만 적용하고 변경 시각·설정 버전을 남긴다. |
| 3 | ‘기준 다시 등록’을 선택한다. | 판정을 중단하고 등록 화면으로 이동한다. |
| 4 | 등록을 완료하고 ‘탐지 재개’를 누른다. | 새 기준 버전으로 새 측정 구간을 시작한다. |

재등록 실패 시 재개하지 않는다. 취소하면 기존 기준이 여전히 유효한 경우에만 돌아간다. 설정·기준 변경을 거북목 예방 효과의 개선으로 해석하지 않는다.

## 6. 대회 검증과 분리할 항목

| 항목 | 현재 판단 |
|---|---|
| S1~S8의 사용자 목표 | 사용자 흐름 정리이며 그대로 8개 제출한다는 뜻은 아니다. 화면 동작과 재현 방법을 확정해 3~8개로 작성한다. |
| 자동 30분 리포트 | 실제 시간 시험이 필요하다. 로컬 1분 목표 E2E와 직접 충돌한다. |
| 종료 부분 리포트 | 같은 흐름 안에서 짧은 실제 세션을 만들어 검증할 수 있으나 자동 주기 검증을 대체하지 않는다. |
| 기록 조회·삭제 | 같은 테스트 흐름 안에서 실제 기록을 만들어야 한다. 앞 흐름·다른 context의 IndexedDB를 가정하지 않는다. |
| 카메라·QR | 주최 측 입력·권한·다중 기기·HTTPS 지원을 확인해야 한다. |
| 임계값·지원 브라우저·실제 동작 | 설계 초안이며 아직 성능·기기 테스트를 하지 않았다. |

팀이 승인할 것은 구체적인 운영·보관·MVP 정책이다. 실험으로 결정할 것은 측정 임계값·촬영 허용 범위·시간 설정의 사용성이다. 운영진에게 확인할 것은 자동 카메라 입력과 다중 기기 재현 방식이다. 이 세 가지를 에이전트 논리 검토로 완료 처리하지 않는다.
