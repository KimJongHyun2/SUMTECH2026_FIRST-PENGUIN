# PRD 보완팩 — 요구사항·수용 조건·검증 증거

작성일은 2026.10.30이다. 팀장이 PRD를 작성할 때 연결할 자료이며 최종 PRD를 대신 승인한 문서가 아니다. 사용자는 이번 대화에서 ‘로그인 없이 PC 브라우저에 기록 보관, 랭킹은 후속 구현’ 정책을 채택했다. 나머지 시간·보관 기간·세부 구현 정책은 제안 상태이다.

## 1. 문서의 우선 참조 순서

| 순서 | 자료 | 취급 |
|---|---|---|
| 1 | 사용자의 최신 정정·결정 | 거북목 예방 목적, 유형별 경고 누적, 주기 리포트·개선, 선택형 측면 딥 모드이다. |
| 2 | UserFlow_최종설계안_노션용.md 및 이 보완팩 | 현재 운영 제안·계산 규칙이다. 사용자 승인 전 정책은 제안 상태를 유지한다. |
| 3 | 스타터킷 원문 | 제출 경로·실행·E2E 요구이다. 별도 실시간 공지·평가표는 확인하지 않았다. |
| 4 | 문제 정의 사용자 원문·문헌 보고서 | 사용자 가설·실제 경험·외부 자료를 분리한다. |
| 5 | 이전 PRD·노션 통합본·ZIP | 이전 초안이다. 예방 목적·주기 리포트·운영 정책에는 최신 자료를 우선한다. |

이번 업데이트로 문서 차원에서 닫은 빈틈은 요구사항 추적, 집계 경계 규칙, 기준 버전·삭제 규칙, 독립 검증 계획이다. 실제 서비스의 위험이 해결됐다는 의미는 아니다.

## 2. 제품 범위와 정책 상태

| 항목 | 사용자 지정 또는 근거 | 현재 상태 |
|---|---|---|
| 거북목 예방을 위한 자세 관리 | 사용자의 명시적 목적이다. | 제품 방향 확정이다. 장기 효과 입증과 다르다. |
| 자세 안내·개인 기준·지속 경고 | 사용자의 핵심 흐름이다. | 구현 전이다. |
| 유형별 경고·누적 기록 | 사용자가 고개·어깨 안내를 예로 들었다. | 검증 가능한 유형에 한해 구체화한다. |
| 주기 리포트와 결과 기반 조정 | 사용자의 명시적 요청이다. | 주기는 제안이며 자동 생성 실험 전이다. |
| QR 연결·측면 배치 딥 모드 | 사용자의 명시적 요청이다. | 지원 환경·재현 방식 검증 전이다. |
| 로그인 없는 PC 로컬 저장 | 사용자가 ‘초안 채택’으로 답변했다. | MVP 정책 채택이다. IndexedDB 등 구현 수단은 구현 제안이다. |
| 30일 보관·30분 리포트·10초 경고 등 | 파일럿 기본값 제안이다. | 승인·사용성·성능 시험 전이다. |
| 랭킹 후속 | 사용자가 ‘초안 채택’으로 답변했다. | 후속 범위로 채택했다. |
| 동일 조건 기간 비교 | MVP 범위 제안이다. | 별도 채택 여부 확인이 필요하다. |

## 5. 리포트 집계 계약 — 추가로 닫은 문서상 구멍

### 시간과 이벤트

| 항목 | 규칙 |
|---|---|
| 유효 구간 | 실제 입력이 유효했던 반열린 구간 [시작, 끝)의 합집합이다. |
| 전체 이탈 시간 | 유형별 이탈을 유효 구간과 교집합한 뒤 합집합한다. |
| 유형별 합계 | 유형이 겹치면 전체 이탈 합집합보다 클 수 있다. |
| 후보·확정 | onset_at은 처음 이탈한 시각, confirmed_at은 지속 조건 충족 시각이다. |
| 복귀 | 유효한 복귀 조건이 확인된 경우에만 normal_return으로 기록한다. |
| 리포트 구간 | 경과 30분이 아니라 유효 입력 누적 30분마다 경계를 만든다. |
| 이탈 횟수 | 확정 이벤트가 시작된 구간에 한 번만 귀속한다. 후속 구간은 이어진 이벤트로 표시한다. |

### 경계에서 아직 확정되지 않은 후보의 처리 제안

유효 시각 1795초에 이탈이 시작되고 1805초에 10초 지속을 충족하면, 1800초 시점에는 후보가 확정되지 않았다. 다음 정책을 제안한다.

1. 1800초에 동일 구간 리포트 v1을 만들고 미확정 후보가 있으면 ‘일부 자세 구간 확인 중’으로 표시한다.
2. 이후 유효 입력에서 후보가 확정되면 동일 이벤트의 시작 시각은 1795초로 유지한다. 이전 구간에 5초, 다음 구간에 5초를 배분한다.
3. 신규 이탈 횟수는 이전 구간에 한 번만 귀속하고 리포트 ID를 유지한 채 v2로 개정한다. 최초 경고는 실제 발생 시각인 1805초 구간에 남는다.
4. 후보가 기준 미달로 끝나면 확정 이탈로 집계하지 않고 잠정 표시를 해제한다. 신호가 끊기면 중단으로 닫고 나중에 이어 붙이지 않는다.
5. 사용자가 이미 확인한 리포트는 ‘일부 구간 갱신’과 갱신 시점을 표시한다. 이전 값을 확정값으로 내보내지 않는다.

리포트 생성과 저장은 (session_id, window_id, revision)의 고유 식별자로 중복을 방지한다. 이 정책은 구현 전 설계 제안이며 사용자·팀 검토 대상이다.

### 계산 예시

아래 숫자는 요구사항을 설명하기 위해 만든 가상 입력이다. 사람의 실제 기록·제품 성능·예방 효과가 아니다.

| 예시 | 입력 | 기대값 |
|---|---|---|
| C01 중첩 유형 | 유효 [0,40), [50,90); 머리 [10,30), 어깨 [20,40) | 유효 80초, 전체 이탈 30초, 37.5%이다. 유형 합계 40초와 구분한다. |
| C02 가림 교집합 | 유효 [0,40), [50,90); 계산용 이탈 구간 [25,65) | 유효한 부분은 [25,40), [50,65)의 30초이다. 가림 10초를 넣지 않으며 실제 이벤트 연속성도 끊어야 한다. |
| C03 경계 횡단 | 유효 [0,1810); 확정 이벤트 [1790,1810), confirmed_at=1800 | 첫 구간 10초, 다음 구간 10초이며 신규 횟수는 첫 구간에만 1이다. |
| C04 늦은 확정 | 유효 [0,1810); onset=1795, confirmed=1805, 끝=1810 | 첫 리포트 개정값 5초·신규 1, 다음 구간 10초·신규 0이다. 경고는 실제 발생한 다음 구간에 집계한다. |
| C05 분석 없음 | 유효 구간 없음 | 비율은 0%가 아니라 계산 불가이다. |
| C06 정확한 경계 종료 | 유효 시간 1800초 | 자동 구간 1개이고 빈 종료 리포트는 없다. |

## 6. 기준·삭제·카메라 상태의 구현 계약

| 항목 | 계약 제안 |
|---|---|
| 기준 스냅샷 | 특징·촬영 조건·모델 버전을 포함한 불변 기준과 ID를 저장한다. 자동으로 과거 기준을 덮어쓰지 않는다. |
| 설정 스냅샷 | 유효 시작 시점이 있는 설정 버전을 남긴다. 설정 변경 직전·직후 구간을 분리한다. |
| 비교 적합성 | 같은 ID만으로 충분하지 않다. 카메라·배치 유효성까지 확인한다. 이동 여부를 알 수 없으면 정량 개선을 보장하지 않는다. |
| 공유 기준 삭제 | 세션 삭제로 다른 세션이 참조하는 기준을 무조건 지우지 않는다. 참조가 없고 현재 등록 기준도 아닐 때 정리한다. |
| 개인 기록 삭제 | 세션 원장·리포트·파생 집계를 같은 범위로 제거한다. 진행 중 자동 저장과 경쟁하지 않게 세션 종료를 선행한다. |
| 6초 장애 | 연결 권한 무효화와 PC 판정 중단이다. 폰 카메라 종료 확인과 다르다. |
| 10초 자체 중단 | 휴대폰 로컬 제어가 촬영 중단을 시도한다. 절전·잠금·스케줄 지연에서 실제 동작을 측정한다. |
| 휴대폰 표시 | ‘연결 끊김·종료 요청·종료 확인’을 구분한다. 확인되지 않은 폰 종료를 완료로 표시하지 않는다. |

## 7. 제출 시나리오 후보와 재현 경로

아래는 User Flow를 시험 목표로 묶은 검토표이다. 최종 steps·platform·spec이 확정된 제출 파일은 아니다. 제안 UI 명칭과 정책 승인이 먼저 필요하다.

| 후보 | 사용자 목표 | 필요한 실제 입력 | 확인할 expected | 독립성과 제한 |
|---|---|---|---|---|
| T01 | 기본 등록 후 경고·종료 리포트 확인 | 안정 자세→이탈→복귀 영상 | 기준 등록·경고·복귀·리포트가 같은 기록으로 연결된다. | 허용된 카메라 입력이 필요하다. |
| T02 | 정지·재개·설정 변경 | 유효 영상과 실제 시간 | 정지 제외 시간과 설정 변경 구간이 남는다. | T01 결과를 사용하지 않고 자체 등록한다. |
| T03 | 실제 세션 기록 조회·삭제 | 같은 흐름에서 생성한 짧은 실제 기록 | 조회 후 삭제하면 해당 기록과 집계가 사라진다. | 새 context의 IndexedDB를 자동 시드한다고 가정하지 않는다. |
| T04 | QR 측면 연결·배치·통합 경고 | 두 입력·연결·HTTPS | 승인한 폰의 측면 값이 실제 통합 판정에 쓰인다. | 운영진 지원·동기화 재현 방식 확인이 필요하다. |
| T05 | 측면 장애 후 기본 모드 계속 | 실제 연결 중단·정면 유효 영상 | 복구 대기 후 기본 구간으로 재개되고 중단을 복귀로 세지 않는다. | T04 선행 결과 없이 자체 연결한다. |
| T06 | 자동 구간 리포트 확인 | 실제 유효 시간 경과 | 주기 생성·계속 탐지·경계 개정·중복 방지가 동작한다. | 30분 실시간 시험과 공식 짧은 실행의 관계를 운영진에게 확인한다. |

3~8개 수를 맞추려고 핵심 경로를 숨기거나 불가능한 물리적 동작을 가짜 UI 조작으로 바꾸지 않는다. 시험용 영상 입력 UI를 만들 경우 제품 범위 추가와 주최 측 허용을 확인한다. 종료 리포트 시험은 자동 주기 시험의 대체가 아니다.

## 11. 지금 넘길 수 있는 것과 아직 넘길 수 없는 것

요구사항·흐름·수용 조건·집계 계약·검증 계획은 팀장이 PRD에 반영할 수 있다. 로그인 없는 로컬 기록과 랭킹 후속 정책은 채택됐으며 실제 경험도 일부 확보했다. 경험 세부사항, 나머지 정책 승인, 운영진 답변, 측정 임계값, 구현·E2E 증거는 아직 없다. 이 문서가 완성됐다는 이유로 출시·제출·평가 통과로 기록하지 않는다.

산술 확인 결과는 리포트_집계_계산검증.json에 저장했다. C01~C06의 기대값과 구간 계산 결과가 일치했다. 이는 명세 예시의 산술 확인이며 탐지 알고리즘·이벤트 생성·저장·30분 자동 생성·문서의 개정 정책을 구현해 시험한 결과가 아니다.

## 12. 실제 경험 수령 기록

| 항목 | 확인된 내용 |
|---|---|
| 사용자 전달 원문 | ‘학교에서 프로젝트를 하다가 목이랑 허리가 너무 뻐근해서 옆에 있는친구가 너무 굽어있는걸 보고 자세를 교정함’이다. |
| 장소·상황 | 학교에서 프로젝트를 진행하던 중이다. |
| 불편 | 첫 설명에 목·허리 뻐근함이 포함됐다. 그 당사자는 아직 확인하지 않았다. |
| 행동 | 사용자가 친구의 굽은 자세를 보고 친구에게 알려줬다. |
| 관찰 주체 | 사용자가 관찰자이고 친구가 안내를 받은 대상이다. 후속 답변으로 확인했다. |
| 아직 없는 정보 | 경험 날짜·작업 시간·사용 기기·불편 당사자·친구의 자가 인식·실제 조정·작업 중단·조정 후 변화·당시 발화이다. |
| 제품 연결 | 외부 관찰자가 작업자의 자세 변화를 보고 알려준 실제 장면이다. 서비스는 이런 확인 계기를 제공하려는 방향이다. |
| 해석 한계 | 이 사례 하나로 몰입이 원인이라고 확정하거나, 웹캠 경고·예방 효과가 검증됐다고 쓰지 않는다. |

원문은 사용자가 이번 대화에서 전달한 경험 설명이다. 당시 실제로 한 말로 제공한 것이 아니므로 직접 발화 quote로 옮기지 않는다.

후속 확인 답변은 ‘제가 친구의 굽은 자세를 보고 친구에게 알려줬습니다’이다. 친구가 스스로 몰랐다거나 안내로 자세가 개선됐다는 결론을 덧붙이지 않는다.

## 13. 이번 검토 결과

정책·집계 감사와 스타터킷·제출 감사 에이전트가 이 보완팩을 재검토했다. 치명적인 문서 논리 모순이나 대회 검증 완료를 허위로 표시한 부분을 발견하지 않았다고 보고했다. RQ09·RQ12의 정책 채택 상태를 사용자 답변에 맞춰 수정했다. 이 결론은 사람 대상 연구·코드·기기·E2E의 품질 보증이 아니다.

문서 검사로 RQ01~12·AC01~27·T01~06의 고유 순서, 표 행 형식, 집계 예시 C01~06의 계산값, problem.draft.yaml의 문법·insight 키·E1과 quote 미창작을 확인했다. YAML 들여쓰기 오류 한 건을 수정한 뒤 재검사를 통과했다. 최종 출시·제출 검증은 미완료이다.
